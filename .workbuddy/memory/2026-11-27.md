## 力士序列帧动画：5 个 AnimationClip + 运行时组件完善

需求：力士已有序列帧，制成动画。

### 核查结论（重要：项目正在被并行重构）
- `StrongmanSpriteAnimation.cs` 与三处接线（`PlayerMotor` / `AbilityCaster` / `CharacterInstance.BuildVisual`）**已存在**；真正缺的是 `Assets/Animations/Strongman/*.anim` 剪辑资产。
- 战斗层脚本（`CombatBody` / `AbilityCaster` / `CharacterInstance` / `PlayerMotor`）在本次会话期间被并行工作流实时改写（`AbilityCaster` 从 753 增至 1000+ 行，新增 `Assets/Scripts/Combat/` 10 个脚本）。**刻意不改这些文件**，只新增动画资产 + 改动画组件，避免写冲突。
- `PlayerMotor` 重构为 `CombatBody` 驱动后 `PlayJump()` **无任何调用者** → 跳跃序列帧虽存在但游戏里不播。

### 做法
- 新增 5 个 `.anim`（Idle / Run / Punch / Dash / Jump）+ `.meta` + 目录 `.meta`，与剑士 `Swordsman_*.anim` 同构（单条 `m_Sprite` PPtr 曲线、`path` 空、`m_Events: []`）；GUID 从 33 个 `.png.meta` 实读，新资产 GUID 用 uuid5 确定性生成并扫全工程防撞。
- 帧率对齐组件：Run 10 / Punch·Dash 14 / Jump 18 fps；Jump 8/18 = 0.444 s 贴合 `CombatBody.jumpDurationSeconds = 0.45`。
- 组件重写（**全部 public API 与既有序列化字段名不变**，零接线改动）：脚底锚定（实测 109/88/153/82 px）、`FireImpact` 三处兜底（修掉打断时丢伤害）、`Time.deltaTime` 跑动计时、订阅 `CombatBody.IsAirborne` 上升沿补上跳跃接线、`ResumeLocomotion`、只读状态属性、逐套缺帧警告、每套显示倍率留 Inspector 微调。
- **未生成** prefab / Animator Controller / 场景物体 / UI 控件（沿用工程约定 + 用户偏好）。

### 实测（venv Pillow 13.0.0）
- 脚底公式 `offset = y_bottom - h/2`（PPU=100，取 `alpha > 32` 包围盒最底行），用剑士既有 54/100/107 反验通过。
- 四套画布 219×250 / 256×240 / 362×362 / 192×200；脚底最大差 71 px ≈ 0.51 世界单位（scale 0.72）；人物实际高度中位数 190/153/249/181，Punch 固有偏大约 30%。

### 关键坑（可复用）
- **Unity YAML 模板不能用 `str.format()`**——文件里大量字面 `{fileID: 0}` 花括号会触发 `KeyError`，改用 `__TOKEN__` 占位符替换。
- 新建 `.anim` / `.meta` 的 GUID 必须 32 位十六进制；生成前先扫全工程现有 guid 防撞（11-25/11-26 已两次踩过 33 位坑）。
- **离线编译判断代码对错要用 `.check/check.csproj`**（`Compile Include="..\Assets\**\*.cs"` 收录当前全部脚本），不能用 `Assembly-CSharp.csproj`——后者在新增脚本后、Unity 刷新前是陈旧的，会误报一整片 `CS0234/CS0246`。
- `Glob` 默认上限 100 条，列资源目录要用精确 pattern 复核帧数；首轮 `Assets/**/*.png` 被截断，少算了 `Punch_05~11` 与 `Jump_00~07`。
- 并行会话中文件 mtime 会实时变化，`Grep` 与 `Read` 的结果可能来自不同版本；以 `Read` + `wc -l` + `ls --full-time` 交叉确认。
