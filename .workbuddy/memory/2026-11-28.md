## 精灵游侠：白底素材转序列帧 + 13 个剪辑 + 动作系统接入

### 素材前提（重要）
- 桌面「精灵游侠素材」原图是 **RGB 白底无 alpha**（其余三套角色都是透明背景），直接导入游戏里就是白框。文件名是 GBK↔UTF-8 乱码字面量，需先按 gbk→utf-8 还原再归集。
- 真正的高分辨率跑/跳/闪素材是 4 张 4128×1024 的 AI 参考条（JPG），GIF 只是 320×400 缩略图。
- 切条带时人物披风互相重叠、**没有纯白分隔列**，列投影找空白会失败；改用「预期等分位置 ±200px 内找墨量谷值」定切割点，再用 GIF 逐帧形状相似度匹配确认配对。

### 转换口径（`.tools/elf_ranger/build_frames.py`）
1. 软阈值抠底：`a = clamp((235 - min(R,G,B)) / 20)`，保留弓弦等浅色细节。
2. 去白污染：`C = (P - (1-a)·255) / a`，否则暗色地图上全是白边。
3. 近白淡绿光晕（治疗/光环）再乘色 `(0.52,0.86,0.60)`，不然是一坨白。
4. 边缘外扩 6 圈（bleed），避免双线性采样把透明区的白 RGB 混进边缘。
5. 统一画布 800×800、脚底 y=799、中心 x=400、人物高 583px。

## 地图层：25×12 坐标统一 + 单图切镜落位

来源：用户提供 `地图.docx` 进度表，5.1 的「需要检查」项是「25×12 格坐标与角色坐标统一；当前是圆形擂台/6 锚点布局」。

### 根因（三条独立的错位）
1. 上一版只缩放 `BG_背景` / `Ground_地面25格` 两个子物体，**地图根节点没进设计坐标系**；MapKit 机制把特效放在 `localPosition=(格+0.5, 1)`、雷从 `y=12` 落下，于是全停在半空/25 列外。
2. `CameraFollow` 自由跟随，`MapScreenFitter` 只在 `OnEnable` 算一次 → 相机一动背景就跑出屏幕。
3. `MatchSpawner` 用 `arenaSpacing=14` 把三场摆成 x≈-14/0/+14，而屏幕只展示一张居中地图 → 玩家场次落在地图外。

### 做法
- 新增 `Assets/Scripts/Maps/MapStage.cs`：`MapStage`（背景世界矩形 + `GridSpace` 25×12 + 地面顶面 + 可玩圆）+ `MapStageBuilder`（唯一几何实现，把**根节点**缩放 `s` 并移到背景左下角）。
- `MapScene.Enter()` 自动 `Refit()`（不再依赖 Editor 菜单）；`BattleMapPresenter` 加 `MapShown` 事件与 `TryGetStage`。
- `MatchSpawner` 订阅 `MapShown` 重摆：玩家那场摆在中轴左右各 3 格、脚底贴地面上沿；其余两场停到地图右边界外（半径 0.5）。格宽同步给 `GameInput.Grid` / 三个 `unitsPerCell`。
- `CameraFollow.Clamp To Stage` 把相机限制在场地矩形内（16:9 下 Y 钉死、X 只能 ±1.53）。

### 数值（16:9，ortho 5）
`根缩放 0.833` / 背景 20.833×10 / 视口 17.778×10 / 格宽 0.8333 / 地面上沿 -4.167 / 可玩圆 圆心 (0,0.417) 半径 4.583 / 双方 x = ±2.5。

### 坑
- `parent.InverseTransformPoint(world)` 的结果是 **parent 局部坐标**，要赋给 `localPosition`（不是 `position`）。
- Editor 工具用 `Undo.RecordObject` 必须把**地图根节点**也记上，否则 Ctrl+Z 只还原了子物体。
- `MapScene` 新字段 `groundCollider` 是 `Collider2D`，Editor 里用 `SerializedObject` 赋 `BoxCollider2D` 可以，但 `SetRef` 的参数类型要写 `UnityEngine.Object`（否则 `Object` 与 `object` 歧义）。
- `.check` 两种配置（含/不含 `UNITY_EDITOR`）均 0 错误。

## 角色移动口径变更：只能在地面左右移动，W 触发跳跃（推翻 Docs/21 的四向结论）

来源：策划原话「现在场景中的角色可以到处走。但是游戏需要把角色改为只能在地面左右移动。让 W 也映射到跳跃，S 无功能。」
上一轮把圆形约束改成矩形，恢复了 W/S 四向；这次是**玩法口径本身改了**：横版只需要地面一行。

### 做法
- `MotionSolver.MoveGround(position, delta, radius, walls, minX, maxX, groundY)`：纯函数，只解算 X，Y 恒等于 `groundY`，墙体阻挡与左右边界内缩沿用同一套。原 `Move`（圆）/`MoveRect`（四向）一行未动。
- `CombatBody`：新增 `lockToGround`（默认开）+ `groundLineY`；`SolveMotion` 分流顺序 地面锁定 → 矩形 → 圆形；`Update` 在地面锁定时**每帧都解算**，这样 Teleport/拉回/落位后的偏离会被立刻压回地面线；`ConfigureArenaRect` 增加带 `groundY` 的重载。
- `PlayerMotor`：移动轴只取 `axis.x`；新增 `moveUpAlsoJumps`，把 `InputActionId.MoveUp`（W）的**按下沿**并入跳跃判定。
- `MatchSpawner`：三处落位都传地面线，当前地图取 `stage.GroundSurfaceY + groundClearance`。
- `CombatBody.Awake` 先把出生高度当地面线，避免生成第一帧被拉到 y=0。

### 为什么 W 不写进 Jump 键位槽
`InputBindingTable.CollectIssues` 把「一键绑两动作」判 Error，`GameInput.LoadBindings` 会因此清档回退默认键位；W 同时也是 `MoveUp` 主键。所以键位表不动，由 `PlayerMotor` 解释 W 的按下沿为跳跃。S 仍绑 `MoveDown`（解除会触发「未绑定」Error），但不再产生任何动作。

### 连带影响（有意）
闪避/冲刺只能左右；击退/击飞/拉回的竖向分量被丢弃（击飞高度仍走 `JumpOffset` 视觉抛物线）；AI 同样锁地面；技能位移竖向被压平。

### 验证
- `.check/check.csproj --no-restore` → 0 错误（30 个既有警告）。
- belltest → 587 通过 / 0 失败；战斗核心 53（45 + 新增 `TestGroundLock` 8 条）。
- 文档：新增 `Docs/22_横版地面锁定与跳跃键位.md`；`Docs/21` 顶部加作废说明并标注第二节已被取代；`Docs/20` 同步矩形→地面锁定的口径变更。

## 竹林（Z1）落雷频闪放慢

来源：策划原话「竹林那个区域频闪太快，再慢一点」。**不是代码 bug，是节奏参数问题**，共三处叠加：

1. `intervalSeconds 0.8~1.2` → `2.6~4.2`（平均 ~3.4s 一道雷）；
2. `extraChance 0.5` → `0.22`、`extraCheckEvery 1` → `1.4`（连击概率与二次雷延迟同时放大）；
3. `flashSeconds 0.3` → `0.6`。

代码侧关键：`BambooNightMechanic.FlashAndHide()` 原来把「亮 0.05s → 暗 0.04s → 亮 0.05s」**硬编码**，50/40ms 白黑硬对切才是频闪的主因，且 `flashSeconds` 只影响后面淡出段。现改为四阶段按 `flashSeconds` 比例分配（0.20/0.17/0.20/0.43），中间回落停在 `Lerp(亮, 黑, 0.55)` 不压到近全黑。黑幕打亮透明度提成常量 `CoverAlphaLit = 0.13f`，`Update()` 驱动雨丝亮度同源。`MakeLine` 的 `Destroy(go, 0.22f)` 改为 `flashSeconds × 0.78`，否则第二次亮时闪电线已消失。

坑：只调 `intervalSeconds` 而不动 `FlashAndHide`，单次闪光仍是「50ms 白→40ms 黑」硬切，观感还刺。**三个参数要一起调**。

验证：`.check` 0 错误；belltest 587 通过 / 0 失败。`Docs/06` 补「竹林落雷闪烁节奏」小节与参数表更新。改 JSON 即生效（`MapKitConfig.Load()` 每次 Awake 从 Resources 读），不需要重拖 Inspector。

### 二次回调：黑屏太久（同日 21:51）

`intervalSeconds` 从 `2.6~4.2` 收回 `1.6~2.4`。关键口径：**黑屏时长 ≈ `intervalSeconds` − `flashSeconds`**（`ThunderLoop` 拍完雷就开始计时，`FlashAndHide` 并行播 0.6s），所以 2.6~4.2 意味着暗等 2.0~3.6 秒，太长；现在 1.0~1.8 秒。`flashSeconds 0.6`、`extraChance 0.22`、`darknessAlpha 0.99` 均未动——`darknessAlpha` 属「全黑靠闪电照明」的玩法取舍，要调需策划确认。



## 普攻「发射东西往斜上方飘」修复（角色动画）

现象：任意角色按左键普攻，场上飞出一个白点/箭并朝斜上方飘走。

根因两条：
1. `AbilityCaster.ResolveBasicAttack` 开头有 `Shape==Line/Fan && ProjectileSpeed>0 → SpawnProjectiles(BasicAttack)`。玩家 `playerPersona` 在场景里是 3（游侠），而**形象跟最后一张特质卡走**（`CharacterInstance.VisualPersona`），所以换任何造型普攻都在射游侠的箭。
2. `GetAimDirection()` 用鼠标投到 z=0 平面的落点减角色位置；横版地面锁定后角色在地面线（低于平面 3~4 单位），方向天然带竖直分量 → 弹道/近战矩形都朝斜上方。§22 加 `lockToGround` 时没压平这里。

改动（都在 `Assets/Scripts/Flow/AbilityCaster.cs`）：
- 删掉普攻的弹道分支，改成「动画命中帧 + 沿朝向瞬时判定」；
- `SpawnProjectiles` 入口对 `BasicAttack` 直接 return（防御性兜底）；
- 散弹伤害合并 `PelletDamage × PelletCount`（否则 4×2 被削成 2）；
- `FindBasicAttackTarget` 放行 `AbilityShape.Line`，远程人设按直线判定而不是「最近的人」；
- `GetAimDirection` 在 `body.IsGroundLocked` 时把方向压成 `(±1,0)`，`SetFacing` 统一在此处。

技能槽弹道（狂战投矛 / 破甲重箭 / 高压喷射 / 时钟飞刃）保留，方向同样被压平。

遗留（已写进 `Docs/08` 第八节）：形象人设与普攻人设可以不一致，现在没有箭矢视觉后会出现「剑士造型挥剑打到 8 格外」。收口方案二选一：① 普攻卡跟 `VisualPersona` 换；② 形象锁 `playerPersona`。等策划定。

验证：`.check/check.csproj --no-restore` 0 错误（30 警告，均为既有 CS0618/CS0169）。


## 平A 朝向：鼠标只通知释放，不参与左右朝向（策划口径）

策划原话：「点按鼠标只负责通知攻击。攻击和原来的朝向是相同的，不应该因为鼠标位置而改变左右的朝向。现在如果角色朝右，鼠标在角色左边，点按鼠标角色会向左攻击，正常应该是和角色原来朝向一样向右」。

我先按「攻击要转向鼠标」理解，加过两处兜底（视口外鼠标坐标守卫 + UI 遮挡时回落指针投影）——口径相反，**已全部回退**，`Assets/Scripts/Inputs/GameInput.cs` 恢复原状。

最终改动（`Assets/Scripts/Flow/AbilityCaster.cs`）：
- 新增 `private Vec2 GetFacingDirection()`：取 `body.FacingVector`，`body.IsGroundLocked` 时压成 `(±1,0)`；
- `BasicAttack()` 里 `Vec2 aimedDirection = GetAimDirection();` → `GetFacingDirection();`，且**不调 `SetFacing`**，鼠标在哪一侧都不改左右；
- `GetAimDirection()` 原样保留，继续给技能用（按鼠标选点 + 施放时同步翻转）。

验证（play mode + `StartMatch()`，注入选点制造「鼠标在反侧」）：
- 朝右 + 鼠标在左 → `fired=True facing=(1,0) sign=1 flipX=False`（改之前会翻成朝左）；
- 朝左 + 鼠标在右 → `fired=True facing=(-1,0) sign=-1 flipX=True`。
- `.check` 0 错误 / 30 既有警告。文档：`Docs/16` 第 23 行结论 + 第二节收口说明。

环境注记（可复用）：
- 沙箱内**无法**移动或点击 OS 光标（`SetCursorPos` 返回 False、`Cursor.Position` 无效），真机点击只能靠注入选点等价验证。
- 编辑器失焦时 `Application.runInBackground=false` 会让 play mode **停帧**（`Time.frameCount` 卡住）；跑运行时验证前先置 true。
- play mode 中改脚本会触发域重载，之后 `GameFlow.Instance` 变 null、状态机停摆 —— 必须退出重进 play mode 再测。
- 在运行中的编辑器跑 C# 用 `unity command eval --file <path.cs>`；`--code` 里的字符串必须用双引号（单引号会被当字符字面量）。

遗留：横版精灵只有左右翻转，朝上/朝下没有表现（见 `Docs/19` §150），这是素材限制不是 bug。
