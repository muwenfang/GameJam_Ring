## 二、五层架构

| 层 | 内容 | 依赖 | 为什么这样切 |
|---|---|---|---|
| **数据层** | `CharacterBaseStats` / `CharacterRoster` / `InputSettings` / `BellSettings`（ScriptableObject） | UnityEngine | 策划改数值不动代码，Inspector 直接可调 |
| **规则核心** | `BellRuntime` + 三个 `IBellEffect` + `BellTrackingLedger` + `BellComponentPool` + 输入映射表 | **纯 C#，零 UnityEngine** | 可以脱离 Unity 跑单元测试，规则改动有回归保护 |
| **外壳层** | `BellSystem`、`GameInput`（MonoBehaviour） | UnityEngine | 只负责计时、轮询、事件转发，不含规则 |
| **能力层** | `AbilityCatalog`（30 条数值）+ `AbilityLoadout`（五槽）+ `AbilityRuntime`（冷却/叠层/派生数值） | 纯 C#（`CharacterStatAdapter` 负责接 UnityEngine） | 技能数值与状态机能离线测；同一角色可混装不同人设的能力 |
| **流程层** | `MatchFlow`（纯 C#）+ `GameFlow`（壳） | 前者零依赖、后者 UnityEngine | 状态机可离线测；生角色/切面板这些副作用集中在壳里 |
| **界面层** | `GameUiController` + `UiBuilder` | UnityEngine.UI | 只订阅 `GameFlow.StateChanged`，不认钟声与数值 |

规则核心与能力层不含 UnityEngine 这件事是刻意保证的：`.check/belltest` 工程把它们（Bells 排除 `BellSettings.cs`/`BellSystem.cs`，
Abilities 排除 `CharacterStatAdapter.cs`）直接编译进控制台程序跑断言。**只要有人往核心里加了 `using UnityEngine`，离线测试立刻编译失败**，等于上了锁。

### 2) 编译校验（不需要 Unity）

```powershell
& 'C:\Program Files\dotnet\dotnet.exe' build 'D:\unity\GameJam_Ring\.check\check.csproj' -v q --nologo
```

`.check/` 是点目录，Unity 不会导入，可以放心留着。

> **本机 SDK 环境注意**：当前 `dotnet 10.0.400-preview` 在还原 / 读取 `project.assets.json` 时会报 `NETSDK1060 / Value cannot be null (Parameter 'path1')`（Git Bash 下多为 `APPDATA` 等 Windows 环境变量为空所致）。编译可加 `--no-restore -p:GenerateDependencyFile=false -t:Rebuild` 绕过；离线测试改用 `dotnet exec --runtimeconfig … belltest.dll` 直跑断言，完整绕过方式与验证记录见 `Docs/10_完整游戏流程与接线.md` 第十节。

### 3) 在 Unity 里接进场景

1. 新建空 GameObject → 加 `BellSystem`（菜单 钟声/钟声系统 BellSystem），把 `Assets/Data/Bells/BellSettings.asset` 拖进 `Settings`。
2. 同一个或另一个 GameObject → 加 `GameInput`，把 `Assets/Data/Inputs/InputSettings.asset` 拖进 `Settings`。
3. 战斗结算里调用 `BellSystem.Instance.NotifyDeath(id)`；击杀后叫 `TryStealOneCard(winner, victim)` 或 `NotifyTracking(tracker, target)`。
4. 监听 `BellSystem.Instance.BellRung` 拿结果：`BellResult.Swaps`（谁和谁换位置）、`BellResult.Clone`（B12 要生成的复制体）、`BellResult.Assignments`（一次钟声后每个人手上有什么牌）。

### 4) Editor 菜单

- **钟声 / 校验 / 校验全部数据**：角色六份数值 + 输入映射 + 钟声规则，一次性列出偏差（例如游侠 12.5% 与公式 15% 的文档特例）。
- **钟声 / 校验 / 校验技能总表**：30 条能力自检（数量、缺失、重复），并把角色资产里的旧平A 数值与技能总表做交叉提示。
- **钟声 / 校验 / 按公式回填…**：把「减伤 = 防御/500」「移速 = 速度×0.03」写回资产；带「含文档特例」的版本会保留游侠的 12.5%。
- **钟声 / 输入映射 / 改键面板**：点一行 → 按想要的键 → 保存回 InputSettings.asset。

## 四、本轮没做的部分

- **技能命中判定**：30 条能力的数值、冷却、叠层、增益与状态机已经实现（`AbilityRuntime`），但矩形/扇形检测、弹道飞行、地形生成、冲刺分段档位这些**空间判定**还没做，`AbilityCaster` 里用的是「射程内最近目标」的简化平A（11-25 起已限定只命中本场 1v1 对手，不跨场）。
- **地图与六区域**：六张战斗地图的随机（`BattleMapId` / `BattleMaps`）、按图切场景（`BattleMapPresenter` / `MapScene`）与开局显示 `battleCanvas` 已接通；11-25 起 `MapKit` 六区美术资源、机制脚本与配置已入库，并新增六图身份映射表与机制状态桥接（见 `Docs/06_MapKit地图资源与接线.md`）。**场景层级仍需手工搭建、机制效果未接入战斗数值**，六个槽位留空即可运行。`BellRules.RegionCount` 只是被校验和提示用到；位置钟声仍只产出「谁和谁换」的配对数据（`BellResult.Swaps`），**不直接移动任何 GameObject**，但 11-25 起已由 `GameFlow.RebuildArenas` 真正消费，用于重建三场 1v1 并交给 `MatchSpawner.ApplyPlan` 落位（区域锚点 `regionAnchors[6]` 可选拖入，留空走计算布局）。详见 `Docs/10_完整游戏流程与接线.md` 第四节。
- **UI 美术 / 演出**：界面是运行时用 uGUI 搭的纯色占位（字体走系统中文字体），钟声仍没有音效与屏幕表现。
- **人机 AI**：人机会被钟声换牌、会被演示脚本推进，但不会主动走位或放技能。

## 六、游戏流程与界面（早期基线）

以下为 11-23 基线结论；**最新完整流程见第八节与 `Docs/10_完整游戏流程与接线.md`**。界面细节见 `Docs/03_游戏流程与界面.md`。

- **状态机**：主菜单 → 准备中 → 收集人设 → 淘汰赛 → 胜利 / 失败 → 主菜单。规则在纯 C# 的 `MatchFlow`，Unity 侧只有 `GameFlow` 做副作用。
- **失败口径**：只有淘汰赛阶段玩家阵亡才判负；收集阶段阵亡按 B8 满血复活（`CharacterInstance.Revive()`）。
- **胜利口径**：`GameFlow.requireCompleteSetForVictory` 默认 **开**（B14 严格口径）——必须「集齐完整特质与技能、合成完整人设 **且** 只剩最后一人」才判胜；活到最后却未集齐会明确结算为失败，避免无对手又无法凑牌的死局。关掉该 Inspector 开关才退回旧口径「只剩自己即胜」。详见 `Docs/10` 第六节。
- **场景接入**：`SampleScene` 里目前是平铺的根物体——`GameFlow`、`BellSystem`、`InputSystem`（挂 `GameInput`）、`MainMenu`（手工搭的主菜单 Canvas）、`GameUIController`；`MatchSpawner` 还没进场景，编辑器里由 `GameUiController.autoCreateSpawnerWhenMissing` 临时补，打包前记得正式加进去。`MatchDirector` 只用于演示推进，接真实战斗后关掉。
- **界面切换**：单场景 + 面板切换（不换 Scene）。主菜单是场景里的 Canvas，HUD 与结算由 `GameUiController` 运行时搭；设置面板会抬高 Canvas 层级压住 HUD，游戏里 Esc 开关。细节与物体名字表见 `Docs/03_游戏流程与界面.md` 第四节。
- **战斗 HUD**：左右双方血条 + 血条下的虚线「状态栏」（展示已获得的特质），中间是钟声倒计时与「回合 X / Y」。
  可在场景里手工搭/生成（菜单「钟声 / 界面 / 生成战斗 HUD（场景）」），`BattleHud` 上所有位置、配色、文案都是 Inspector 字段；
  场景里没有它会运行时兜底搭一套。详见 `Docs/03_游戏流程与界面.md` 第四节。
- **演示键**：B 敲钟、K 处决自己（看失败界面）、L 处决一个人机（看胜负推进）。

## 七、人设技能与界面（技能系统基线）

细节见 `Docs/04_技能系统.md`，这里只放结论。

- **五槽模型**：特质 / 普攻 / 本我 / 自我 / 超我各是一个独立槽位，`AbilityLoadout` 按槽存卡。
  一键换牌时 `SyncFromBellCards` 把钟声发的特质卡与技能卡同步进槽位，**普攻槽不受钟声影响**。
- **可以混装**：一个人身上能同时挂着别人的人设特质和别人的人设技能——「特质:剑客 ｜ 本我:钟表师 ｜ 超我:力士」这种组合是合法的。
- **数值唯一真源**：30 条能力的数字全在 `AbilityCatalog`（代码常量），资产里那份旧平A 数值只用于校验提示。
- **与人物属性衔接**：`AbilityRuntime.ComputeDerived()` 从 `CharacterBaseStats` 出发，依次叠普攻覆盖 → 特质被动 → 限时修正 → 联动，
  产出的 `DerivedAbilityStats` 被移动、平A、受击减伤、HUD 共用；所以「过载损耗」会让移速随血量掉、「绝对防御」会真的让你走得慢。
- **玩家操作**：WASD 移动、左键平A、1/2/3 施放本我/自我/超我；HUD 会列出五个槽位与技能冷却。
- **集齐口径不变**：B13/B14 仍然只认「特质 + 三个技能等级」，普攻不算；要五槽才算齐时给 `IsCompleteSet` 传 `includeBasicAttack: true`。

## 八、完整游戏流程（11-25 晚间新增）

细节见 `Docs/10_完整游戏流程与接线.md`，这里只放结论与接线要点。

- **六区域 / 三场 1v1**：六个区域复用 `BattleMapId.Map01..Map06`（MapKit Z1..Z6）；`BattleMaps.PickDistinct(3, rnd)` 抽 3 个互不重复场地，6 人洗牌两两配对成 3 场。新增纯 C# 规则层 `Maps/ArenaPlan.cs`（`ArenaDuel` / `ArenaPlan` / `ArenaPlanGenerator`，零 UnityEngine，已纳入离线回归）。`GameFlow.CurrentPlan` 是「角色 ↔ 区域 ↔ 对手」的唯一权威，只在开局 / 位置钟声 / B8 死亡重分配三处由 `RebuildArenas` 重建。
- **开局随机**：特质 / 技能仍由 `BellRuntime.DealInitialCards()` 洗牌发牌；位置与对手由 `ArenaPlanGenerator` 生成，`MatchSpawner.ApplyPlan()` 落到世界坐标（每场双方站区域中心左右），并把玩家所在擂台中心交给 `PlayerMotor.SetArenaCenter`，圆形边界不再被拉回原点。
- **钟声口径**：出现死亡（任何阶段）必定触发 `BellKind.Position`；30 秒定时随机钟声只在 `BellPhase.Normal`（无人集齐）生效，且死亡会打断并重置计时；淘汰制已不满足 B4 前提，**不再定时敲钟，只由死亡驱动**。`BellResult.Swaps` 现在被真正消费用于重匹配，钟声核心仍不碰位置实体。
- **B8 普通阶段死亡**：不淘汰，位置钟声 → 重抽场地并重匹配 → 被杀者 `Revive()` 满血、清冷却增益 → 仍是 3 场 1v1，在场人数不变。**B9 淘汰制死亡**：`StoreEliminatedCards` 卡牌入组件池、`IsInPlay = false`，不再复活，逐人淘汰至剩 1 人。
- **B14 胜负**：`requireCompleteSetForVictory` 默认 true；只剩玩家且 `HasCompleteSet` 才 Victory，活到最后未集齐则 Defeat。`MatchDirector` 演示推进改为优先给玩家补缺牌，以便能看到胜利界面。
- **重开清场**：公开幂等的 `GameFlow.InitializeGame()`（可直接绑按钮 OnClick）清角色 / 名册 / 追踪 / 组件池 / 钟声计时 / 场地计划 / `timeScale` / 相机与 HUD 绑定；`Start()`、`StartMatch()`、`ReturnToMenu()` 与结算面板「返回」「再来一局」均调用。纯 C# 侧 `MatchFlow.InitializeGame()` 同步清本局数据但不改状态。
- **相机与 HUD**：新增 `Flow/CameraFollow.cs`（挂 Main Camera，`LateUpdate` 用 `SmoothDamp` 跟 XY、保持 Z，位置重排时 `Snap()`）；HUD 在 `Loading / Collect / Elimination` 全程显示，`BattleHud.preferPairedOpponent` 让右侧优先显示本场 1v1 对手；平A 也只命中本场对手。
- **UI 仍由用户手工搭建**：本轮未新增任何自动创建 UI 控件或自动挂载组件到 Canvas 的代码；`CameraFollow` 是相机逻辑组件。需在 Inspector 手工拖的：`GameFlow.Battle Count`、`MatchSpawner.Region Anchors[0..5]`（可选，留空走计算布局）、`Main Camera` 上的 `CameraFollow`、`BattleHud.Prefer Paired Opponent`、`GameUiController.Keep Hud On Result`、`BattleMapPresenter.Scenes[0..5]`。完整清单见 `Docs/10` 第九节。
- **验证**：`.check/check.csproj` 全量编译 **0 错误**（2 条既有 MapKit 未用字段警告）；离线断言 **487 条通过 / 0 失败**（新增 `TestArenaPlan`、`TestFlowInitializeGame`）。
- **仍未做**：B12 复制体实体生成与结算、三场同屏 / 切镜策略、AI 主动战斗、技能真实空间命中判定、地图机制数值接入、夺取 / 追踪 / 组件池的玩家选择面板。
