# 钟声（Ring）— 代码总览

本轮按《数据和结构.txt》《钟声_全文.txt》补齐了三块：**人物基础数值**、**输入系统**、**钟声系统架构**。
技能效果与地图（六地域 / 区域分配）按约定**暂未实现**，只留好挂接点。

## 二、三层架构

| 层 | 内容 | 依赖 | 为什么这样切 |
|---|---|---|---|
| **数据层** | `CharacterBaseStats` / `CharacterRoster` / `InputSettings` / `BellSettings`（ScriptableObject） | UnityEngine | 策划改数值不动代码，Inspector 直接可调 |
| **规则核心** | `BellRuntime` + 三个 `IBellEffect` + `BellTrackingLedger` + `BellComponentPool` + 输入映射表 | **纯 C#，零 UnityEngine** | 可以脱离 Unity 跑单元测试，规则改动有回归保护 |
| **外壳层** | `BellSystem`、`GameInput`（MonoBehaviour） | UnityEngine | 只负责计时、轮询、事件转发，不含规则 |
| **流程层** | `MatchFlow`（纯 C#）+ `GameFlow`（壳） | 前者零依赖、后者 UnityEngine | 状态机可离线测；生角色/切面板这些副作用集中在壳里 |
| **界面层** | `GameUiController` + `UiBuilder` | UnityEngine.UI | 只订阅 `GameFlow.StateChanged`，不认钟声与数值 |

规则核心不含 UnityEngine 这件事是刻意保证的：`.check/belltest` 工程把 `Assets/Scripts/Bells/*.cs`（排除 `BellSettings.cs`、`BellSystem.cs`）直接编译进控制台程序跑断言。**只要有人往核心里加了 `using UnityEngine`，离线测试立刻编译失败**，等于上了锁。

## 三、快速上手

### 1) 跑规则回归测试（不需要 Unity）

```powershell
& 'C:\Program Files\dotnet\dotnet.exe' run --project 'D:\unity\GameJam_Ring\.check\belltest\belltest.csproj'
```

覆盖：发牌守恒、特质/技能钟声洗牌守恒、B13 豁免、位置配对、B12 复制体、B7 追踪时长、B3/B8/B11 死亡与牌池、B6 夺取、B14 胜利、输入默认键位与改键存档。

### 2) 编译校验（不需要 Unity）

```powershell
& 'C:\Program Files\dotnet\dotnet.exe' build 'D:\unity\GameJam_Ring\.check\check.csproj' -v q --nologo
```

`.check/` 是点目录，Unity 不会导入，可以放心留着。

### 3) 在 Unity 里接进场景

1. 新建空 GameObject → 加 `BellSystem`（菜单 钟声/钟声系统 BellSystem），把 `Assets/Data/Bells/BellSettings.asset` 拖进 `Settings`。
2. 同一个或另一个 GameObject → 加 `GameInput`，把 `Assets/Data/Inputs/InputSettings.asset` 拖进 `Settings`。
3. 战斗结算里调用 `BellSystem.Instance.NotifyDeath(id)`；击杀后叫 `TryStealOneCard(winner, victim)` 或 `NotifyTracking(tracker, target)`。
4. 监听 `BellSystem.Instance.BellRung` 拿结果：`BellResult.Swaps`（谁和谁换位置）、`BellResult.Clone`（B12 要生成的复制体）、`BellResult.Assignments`（一次钟声后每个人手上有什么牌）。

### 4) Editor 菜单

- **钟声 / 校验 / 校验全部数据**：角色六份数值 + 输入映射 + 钟声规则，一次性列出偏差（例如游侠 12.5% 与公式 15% 的文档特例）。
- **钟声 / 校验 / 按公式回填…**：把「减伤 = 防御/500」「移速 = 速度×0.03」写回资产；带「含文档特例」的版本会保留游侠的 12.5%。
- **钟声 / 输入映射 / 改键面板**：点一行 → 按想要的键 → 保存回 InputSettings.asset。

## 四、本轮没做的部分

- **技能效果**：只有「技能卡 = 人设 + 等级」的身份建模，没有伤害/冷却/位移等实际技能逻辑。
- **地图与六区域**：`BellRules.RegionCount` 只是被校验和提示用到；位置钟声输出的是「谁和谁换」的配对数据，**不直接移动任何 GameObject**，交给后续的场地逻辑消费。
- **战斗**：没有血量结算、碰撞、平A 命中判定；`BasicAttackProfile` 只承载数值。
- **UI 美术 / 演出**：界面是运行时用 uGUI 搭的纯色占位（字体走系统中文字体），钟声仍没有音效与屏幕表现。

## 五、已知取舍

| 问题 | 处理 |
|---|---|
| 键位表「鼠标左键/：平A/闪避」缺一个字（原文指向 §9-Q4） | 默认 平A = 鼠标左键、闪避 = 鼠标右键；两份文档资产里都写了 designNotes，随时可在改键面板改 |
| 游侠减伤 12.5% 与 防御/500 = 15% 冲突（文档自己标了 ⚠️） | 保留文档值 12.5%，校验器只提示不覆盖；回填菜单需显式选「含文档特例」 |
| 闪避距离/时长/冷却文档没给 | 3 格 / 0.25s / 3s 占位，写在各角色 designNotes |
| B7「不能成为追踪对象」有两种读法 | `BellTrackingExclusion.SelectionOnly`（默认：不能成为新的追踪目标）/ `SelectionAndPosition`（连位置交换也跳过），可在 BellSettings 里切 |
| 工程没装 Input System 包 | 全部走旧版 `UnityEngine.Input`；`GameInput` 里的轮询是唯一需要替换的地方 |

## 六、游戏流程与界面（本轮新增）

细节见 `Docs/03_游戏流程与界面.md`，这里只放结论。

- **状态机**：主菜单 → 准备中 → 收集人设 → 淘汰赛 → 胜利 / 失败 → 主菜单。规则在纯 C# 的 `MatchFlow`，Unity 侧只有 `GameFlow` 做副作用。
- **失败口径**：只有淘汰赛阶段玩家阵亡才判负；收集阶段阵亡按 B8 满血复活（`CharacterInstance.Revive()`）。
- **胜利口径**：场上只剩玩家即胜利（按需求）；想严格按 B14，把 `GameFlow` 的 `RequireCompleteSetForVictory` 勾上，就必须集齐完整人设。
- **场景接入**：一个 `RingRoot` 上挂 `BellSystem` + `GameFlow` + `MatchSpawner` + `GameUiController`，另一个物体挂 `GameInput`；`MatchDirector` 只用于演示推进，接真实战斗后关掉。
- **演示键**：B 敲钟、K 处决自己（看失败界面）、L 处决一个人机（看胜负推进）。
