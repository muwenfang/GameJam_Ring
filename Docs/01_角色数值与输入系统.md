# 角色数值 与 输入系统

## 一、角色数值

### 1. 资产在哪

| 资产 | 路径 |
|---|---|
| 单个角色 | `Assets/Data/Characters/Character_<代号>.asset`（Swordsman / SteamMechanic / Spartan / Ranger / Clockmaker / Strongman） |
| 总表 | `Assets/Data/Characters/CharacterRoster.asset`（按顺序引用上面六份） |

新增角色时：右键 Create → 钟声/角色基础数值，再拖进总表的 `characters` 列表。`PersonaId` 是主键，总表里同一个人设出现两次会被校验器报错。

### 2. 字段

`CharacterBaseStats`（ScriptableObject）：

| 字段 | 含义 | 来源 |
|---|---|---|
| `persona` | 人设 ID（0–5） | 文档 |
| `displayName` / `positioning` | 显示名、定位描述 | 文档 |
| `traitName` / `traitDescription` | 特质名与说明 | 文档 |
| `maxHealth` | 生命上限 | 文档 |
| `defense` | 防御值 | 文档 |
| `damageReduction` | 减伤百分比（0–1 的小数，如 0.14 = 14%） | 文档，可用公式回填 |
| `speed` | 速度（整数刻度） | 文档 |
| `moveSpeedCellsPerSecond` | 实际移速（格/秒） | 文档，= speed × 0.03 |
| `jumpHeightCells` | 跳跃高度（格） | 文档：六人都是 2 |
| `attackIntervalSeconds` | 平A 冷却 | 文档 |
| `basicAttack` | 平A 档案（见下） | 文档 |
| `dodgeDistanceCells` / `dodgeDurationSeconds` / `dodgeCooldownSeconds` / `dodgeGrantsInvulnerability` | 闪避参数 | **文档未给，占位值 3 / 0.25 / 3 / 是** |
| `designNotes` | 备注（记录文档歧义、占位值） | 本工程补充 |

`BasicAttackProfile`（平A）：`attackName`、`damage`（单发/单次伤害）、`windupSeconds`（前摇）、`rangeCells`（射程）、`widthCells`（宽度，近战用）、`projectileSpeed`（投射物速度，0 = 近战）、`projectileCount`（弹丸数）、`spreadDegrees`（散射角）、`returns`（是否回旋）。派生属性：`IsProjectile`（速度 > 0）、`IsFan`（弹丸数 > 1）、`GetPelletAngleDegrees(i)`。

### 3. 六人总表（与文档一致）

| 角色 | 生命 | 防御 | 减伤 | 速度 | 移速 | 平A 间隔 | 平A |
|---|---|---|---|---|---|---|---|
| 剑客 | 100 | 70 | 14% | 130 | 3.9 格/s | 0.7s | 横斩 4 伤害 / 前摇 0.15s / 2 格 / 宽 2 |
| 蒸汽机械师 | 110 | 82 | 16.4% | 108 | 3.24 格/s | 0.8s | 蒸汽铳 每枚 2 / 0.2s / 5 格 / 速 6 / 4 枚 / 28° |
| 斯巴达 | 116 | 120 | 24% | 72 | 2.16 格/s | 0.9s | 长矛 5 / 0.2s / 2 格 / 宽 1 |
| 精灵游侠 | 75 | 75 | **12.5%** ⚠️ | 110 | 3.3 格/s | 0.6s | 短弓 3 / 0.15s / 8 格 / 速 10 |
| 钟表师 | 96 | 96 | 19.2% | 108 | 3.24 格/s | 0.8s | 飞刃 4 / 0.2s / 5 格 / 速 8 / 回旋 |
| 力士 | 120 | 90 | 18% | 90 | 2.7 格/s | 0.9s | 出拳 3 / 0.2s / 1 格 / 宽 2 |

跳跃高度：六人统一 2 格。手动计算：剑客 70/500 = 0.14 ✓、机械师 82/500 = 0.164 ✓、斯巴达 120/500 = 0.24 ✓、钟表师 96/500 = 0.192 ✓、力士 90/500 = 0.18 ✓；游侠 75/500 应为 0.15，文档自己用 ⚠️ 标了 12.5%，**本工程保留文档值**。

### 4. 公式与 Q1 决策（本轮资产化）

`CharacterBalance` 仍集中两条换算入口，但**公式除数、策略与特例已搬到资产**，
代码里只保留种子默认值并委托给 `BalanceDecisionRuntime.Active`：

```csharp
ReductionFromDefense(defense)   // 纯公式：defense / ActiveDecision.DefenseToReductionDivisor
ReductionFor(persona, defense)  // 按当前策略解析：含 Q1 覆盖
CellsPerSecondFromSpeed(speed)  // speed * ActiveDecision.SpeedToCellsPerSecond
```

- 除数 `500`、系数 `0.03`、容差 `0.0005` 现在是 `AbilityTuning.asset → Balance` 里的可写字段；
- `HasDocumentedException(persona)` 不再硬编码 `persona == Ranger`，改查资产里的覆盖表；
- Q1 的完整决策记录（问题 / 选项 / 决议 / 决议人 / 日期 / 后续动作 / 确认状态）见下方第 6 节。

### 5. 校验与一键回填（Editor 菜单）

- **钟声 / 校验 / 校验全部数据**：逐项跑 `CharacterBaseStats.CollectIssues`，与 `CharacterReferenceTable`（文档总表快照）比对；
  同时校验 `AbilityTuning.asset` 的 30 条技能数值、effectRefs 映射与 Q1 决策。
- **钟声 / 校验 / 按公式回填角色派生数值**：默认跳过「资产里登记了覆盖值」的人设（保留游侠 12.5%）。
  **例外**：若把资产 `Policy` 切到 `FormulaOnly`，本菜单也会把游侠改成 15% —— 由策略决定，不改代码。
- **钟声 / 校验 / 按公式回填（含文档特例）**：连覆盖值一起按公式覆盖。
- **钟声 / 数值层 / 应用 Q1 决策到六个角色资产**：按资产里的 `BalanceDecision` 一次性重算六份
  `Character_*.asset` 的 `damageReduction`，是「改策略 → 落资产」的推荐入口。
- **钟声 / 数值层 / 校验数值资产（含 effectRefs 与 Q1）**、**列出资产与代码种子差异**：见 `Docs/04` 第九节。

### 6. Q1 决策记录（本轮完善）

**问题（Q1）**：防御 70/82/90/96/120 均满足「减伤 = 防御 ÷ 500」（即百分数 = 防御 ÷ 5）；
唯独精灵游侠防御 75 在总表里写 **12.5%**，按公式应为 **15%**（相当于 ÷600）。
架构分析 §9-Q1 建议「统一为 ÷5 并确认游侠值」。

| 项 | 内容 |
|---|---|
| 选项 A | 统一按公式 15%（需改写文档总表） |
| 选项 B | 保留文档 12.5%，登记为显式特例 ← **当前决议** |
| 选项 C | 改公式除数使六行全部自洽（**已排除**：不存在能同时满足 6 行的单一除数） |
| 决议依据 | 文档总表用 ⚠️ 显式标注该值，视为策划定稿；工程不得擅自改写设计数值 |
| 当前状态 | **待策划最终确认**（工程侧已按 B 实现，不是「已闭环」） |
| 决议人 / 日期 | 工程侧取舍（待策划确认） / 2026-11-26 |

**落地形态**（不再是一句 `return persona == Ranger`）：

```
AbilityTuning.asset → Balance
  ├─ DefenseToReductionDivisor = 500     （可改）
  ├─ SpeedToCellsPerSecond     = 0.03    （可改）
  ├─ Policy = DocumentExceptions         （FormulaOnly / DocumentExceptions / OverrideOnly）
  ├─ Overrides[0] = { Persona=Ranger, DamageReduction=0.125,
  │                   Reason, Source, DecidedBy, DecidedOn, FollowUp }
  └─ Q1Status / Q1Question / Q1Options / Q1Decision / Q1FollowUp
```

**策划改主意时怎么做**（全程不改 C#）：

| 目标 | 操作 |
|---|---|
| 改成 15%（选项 A） | 资产里把 `Policy` 切到 `FormulaOnly`（或删掉 Ranger 覆盖）→ 菜单「应用 Q1 决策到六个角色资产」→ 同步更新 `Docs/01` 总表与 `CharacterReferenceTable` 快照 |
| 维持 12.5% | 把 `DecidedBy` 改成策划、`Q1Status` 改成「已确认」、补决议日期即可 |
| 想验证选项 C | 把 `DefenseToReductionDivisor` 改成 600 并切 `FormulaOnly`，游侠 75 防御即 12.5%（离线回归已覆盖此断言） |

**校验行为变化**：`CharacterBaseStats.CheckAgainstFormula` 现在比较的是「当前策略的解析值」，
因此刻意保留的 12.5% 不会再被误报成一条含糊的 Warning；Q1 的偏差由
`BalanceDecision.CollectIssues` 带依据地报 Info，并要求覆盖表必须写 `Reason` / `Source`（否则报 Warning）。
`CharacterReferenceTable` 与 `CharacterStatBlock.FromDocument` 里原先各写死一份的 `0.125f`
已统一改为从 `BalanceDecision.DocumentDefault.ResolveReduction(...)` 读取，消除第二份真源。

## 二、输入系统

### 1. 文件职责

| 文件 | 职责 | 依赖 |
|---|---|---|
| `InputKey.cs` | 键枚举（数字即存档格式，**只能追加不能重排**）+ 显示名 | 纯 C# |
| `InputKeyCatalog.cs` | 与 `KeyCode` 的互转、按键合法性校验 | UnityEngine |
| `InputActionId.cs` | 11 个动作 + 默认键 + 动作分类（移动/技能） | 纯 C# |
| `InputBinding.cs` | `InputBindingTable`：每个动作主键 + 备用键，改键冲突检测 | 纯 C# |
| `InputBindingSerializer.cs` | 映射表 ⇄ 文本，存取用 | 纯 C# |
| `InputSettings.cs` | ScriptableObject：默认键位、是否允许运行时改键、是否落盘 | UnityEngine |
| `GridSpace.cs` | `GridCoord` 格坐标 + 世界↔格换算（D12）：25×12 边界、钳制、格中心 | 纯 C# |
| `InputIntent.cs` | `InputIntent` 统一输入意图 + `AimMode`（D3 / 架构 §4.1） | 纯 C# |
| `InputIntentUnity.cs` | `Vector2` / `Vector2Int` 转换扩展 | UnityEngine |
| `GameInput.cs` | MonoBehaviour：每帧轮询 → `WasPressed` / `IsHeld` / `WasReleased` / `MoveAxis`，并产出 `Intent`（含鼠标选点 → 世界 → 格） | UnityEngine |

纯 C# 那半边（含存档序列化）在 `.check/belltest` 里被真实跑过断言，改序列化格式不会把存档写坏而无人察觉。

### 2. 默认键位（文档键位表）

| 动作 | 主键 | 备用键 |
|---|---|---|
| 向上 / 向下 / 向左 / 向右 | W / S / A / D | ↑ / ↓ / ← / → |
| 平A | 鼠标左键 | — |
| 闪避 | 鼠标右键 | — |
| 跳跃 | 空格 | — |
| 技能 1（本我） | 1 | — |
| 技能 2（自我） | 2 | — |
| 技能 3（超我） | 3 | — |
| 暂停 / 菜单 | Esc | — |

⚠️ 文档原文是「鼠标左键/：平A/闪避」——斜杠后面丢了一个键名（正文指向 §9-Q4）。本工程取 平A = 鼠标左键、闪避 = 鼠标右键，两边资产都写了备注，随时可在改键面板改掉。

### 3. 改键

**玩家（游戏内）**：设置面板 →「键位调整」（`TopCanvas/SettingPanel/Input`）→ 点某行的「主键/备用」→ 直接按想要的键（鼠标键也行）→ 立刻生效并写 PlayerPrefs。冲突会告诉你被谁占用，`Esc` 取消捕捉、再 `Esc` 关面板，「恢复默认」回到文档默认键位。面板是 `Assets/Scripts/UI/KeyBindingPanel.cs`，运行时用 `UiBuilder` 搭出来，场景里不需要手搭。

**策划（编辑器，改默认键位）**：钟声 / 输入映射 / 改键面板 → 点某行的「主键/备用」，直接按想要的键 → 「保存到 InputSettings」写回资产。这是改**默认值**，和玩家自己的键位存档互不覆盖。

**运行时**：`GameInput.Instance.TryRebind(action, slot, key, out InputActionId conflict)`；`allowRuntimeRebinding` 关掉时直接返回 false。成功会按 `persistToPlayerPrefs` 自动写 PlayerPrefs。

**存档格式**（`ring.input.bindings.v1`，纯文本，方便看一眼就懂）：

```
# ring.input.bindings v1
Attack=MouseLeft|None
MoveUp=W|UpArrow
```

存的是**枚举名字**不是数字：以后往枚举中间插一个键，老存档也不会整体错位。

### 4. 接入

1. 场景里放一个空物体 → 加 `GameInput` → 拖 `Assets/Data/Inputs/InputSettings.asset`。
2. 角色脚本里读：`GameInput.Instance.MoveAxis`、`.AttackPressed`、`.SkillPressed(SkillTier.Id)`；要玩家 / AI 同构就统一读 `GameInput.Instance.Intent`。
3. 想换 Input System 包时，只需改 `GameInput.Poll()`（`GetKey*`）与 `BuildIntent()`（`mousePosition` / `GetMouseButtonDown`）两处轮询，其余 API 不用动。

### 5. 鼠标选点（D12）

`GameInput` 每帧把 `UnityEngine.Input.mousePosition` 投到游戏平面得到世界 XY，再用 `GridSpace.WorldToCell` 取整成格坐标，写进 `Intent.aimPoint`。
相机与格参数在 Inspector 里手工指派；默认 `Aim Mode = Hover`，选点不占用任何按键。
完整换算口径、接线步骤、API 速查与验收命令见 **`Docs/12_输入层InputIntent与鼠标选点D12.md`**。

## 三、没做的部分

- 输入映射只有「键位」，没有手柄轴/死区/组合键。
- 选点只落到格坐标；M3 的「缚地荆棘」3×1 地形与前方 4 格射程校验、M6 的 AI 行为决策器仍未实现（见 `Docs/12` 第七节）。
- 角色数值只有数据与校验，没有挂到任何角色预制体上（本轮没有角色实体）。
- 技能与地图：按约定不动。
