# 03 · 游戏流程与界面

本轮新增两块，**刻意分开**：

| 层 | 文件 | 依赖 | 职责 |
|---|---|---|---|
| 流程规则 | `Assets/Scripts/Flow/MatchState.cs`、`MatchFlow.cs` | 纯 C# | 状态机：能不能开始、什么时候进淘汰赛、什么时候算赢/输 |
| 流程外壳 | `Flow/GameFlow.cs`、`MatchSpawner.cs`、`CharacterInstance.cs`、`PlayerMotor.cs`、`MatchDirector.cs` | UnityEngine | 生角色、订阅钟声、判胜负、把结果转成事件 |
| 界面 | `Assets/Scripts/UI/GameUiController.cs`、`UiBuilder.cs` | UnityEngine.UI | 只订阅 `GameFlow.StateChanged`，画面板、响应按钮 |

界面层不读钟声、不读角色数值；流程层不碰任何 UI 类型。加新界面（结算动画、选人页）只需订阅事件，不动规则。

## 一、状态机

```
MainMenu ──StartMatch()──> Loading ──NotifyParticipantsSpawned()──> Collect
                                                                    │
                                       B9 有人集齐 ──NotifyEliminationStarted()
                                                                    ▼
                                                               Elimination
                                                          ┌─────────┴─────────┐
                                           只剩玩家          │            玩家阵亡 / 人机获胜
                                                          ▼                   ▼
                                                       Victory             Defeat
                                                          └──── ReturnToMenu()/StartMatch() ────> MainMenu / Loading
```

| 方法 | 允许的起点 | 说明 |
|---|---|---|
| `StartMatch()` | 主菜单 / 胜利 / 失败 | 清空局内数据 → 准备中 |
| `NotifyParticipantsSpawned(playerId, count)` | 准备中 | 六个实例注册进钟声系统后调用 |
| `NotifyEliminationStarted()` | 收集人设 | 由 `BellSystem.PhaseChanged(Elimination)` 驱动（B9） |
| `NotifyPlayerLastStanding(bool)` | 收集 / 淘汰 | 只剩玩家 → 胜利；`RequireCompleteSetForVictory` 打开时还要求集齐（B14） |
| `NotifyPlayerDefeated(reason)` | 收集 / 淘汰 | 玩家阵亡 → 失败 |
| `NotifyOpponentWon(id)` | 收集 / 淘汰 | 只剩一个人机 → 失败 |
| `ReturnToMenu()` | 除主菜单外的任何状态 | 清空局内数据 |

非法流转不会抛异常，只会走 `TransitionRejected` 事件并在 `LastRejection` 里留一句原因，方便日志与 HUD 显示。

## 二、一局从点击开始到结算发生了什么

1. 点「开始游戏」→ `GameFlow.StartMatch()`
2. `MatchSpawner.SpawnMatch()`：
   - 清空上一局（销毁旧角色、`Registry.Clear()`、`ResetRound()`）
   - 按 `CharacterRoster` 顺序生成 6 个 `CharacterInstance`（六边形站位），玩家由 `playerPersona` 指定
   - 每个实例注册进 `BellSystem`，最后 `DealInitialCards()`（每人随机 1 特质 + 1 技能）
3. `GameFlow` 订阅每个实例的 `Died`，并调 `NotifyParticipantsSpawned()` → 进入 **收集人设**
4. 钟声每 30 秒（或按 B）随机敲一次，特质/技能在六人之间洗牌；某个人集齐一套 → `BellRuntime` 切 `Elimination` → `GameFlow` 收事件 → 进入 **淘汰赛**
5. 淘汰赛里角色阵亡 → `CharacterInstance.Died` → `GameFlow.HandleCharacterDied`
   - 玩家 → `NotifyPlayerDefeated` → **失败界面**
   - 人机 → `BellSystem.NotifyDeath`（B3 必敲位置钟声）→ 检查场上人数 → 只剩玩家 → **胜利界面**
6. 结算界面「返回主菜单」→ `GameFlow.ReturnToMenu()` 销毁角色、清空钟声状态；「再来一局」= 返回 + 立刻开始

**收集阶段阵亡不判负**：按 B8，死亡只是「重新分配到区域并恢复满血」，`GameFlow` 会直接 `Revive()` 并把原因写进日志。只有淘汰赛的死亡才算淘汰。

## 三、场景怎么摆

当前 `SampleScene.unity` 的实际摆法（全是根物体，没有 RingRoot 容器）：

```
InputSystem             (空物体) GameInput
GameFlow                (空物体) GameFlow
MainMenu                (Canvas) 手工搭的主菜单，含 SettingPanel
GameUIController        GameUiController（HUD / 结算由它运行时搭）
BellSystem              BellSystem
Main Camera
EventSystem
```

约束：
- `BellSystem`、`GameFlow`、`GameInput` 都是单例组件，场景里各放一个。
- `MatchSpawner` 目前**还没放进场景**。`GameUiController.autoCreateSpawnerWhenMissing`（默认开）会在编辑器里点「开始游戏」时临时补一个，用 `Assets/Data/Characters/CharacterRoster.asset`；正式做法还是给一个空物体挂 `MatchSpawner` 并指定角色总表。打包后不会自动补，只在 Console 里报警告。
- `MatchSpawner` 最好是 `GameFlow` 的 `spawner`，或至少同场景（留空会自动 `FindObjectOfType`）。
- `PlayerMotor` 由 `MatchSpawner` 自动加到玩家角色上，读 `GameInput.Instance.MoveAxis`。
- 场景文件被 `.gitignore` 忽略（本地文件），所以这里的层级随时可能和文档不一样；`钟声/场景/校验主菜单界面` 菜单会把差异报出来。

## 四、界面

**切换方式：单场景 + 面板切换，不换 Scene。** 换 Scene 就要把 `GameFlow` / `BellSystem` / `GameInput` 和主菜单 Canvas 搬进 `DontDestroyOnLoad`，还要单独保住 `SettingPanel`，收益为零。

### 主菜单（场景里手工搭的）

`GameUiController` 只负责显示/隐藏和接线，不重建。按名字自动找，也可以在 Inspector 里手动拖：

| 名字 | 作用 |
|---|---|
| `MainMenu`（Canvas） | 主菜单根；进入游戏后子物体全部隐藏（进菜单时按 Awake 时的显示状态还原） |
| `Start` | 开始游戏 → `GameFlow.StartMatch()` |
| `Setting` | 打开设置面板 |
| `Exit` | 退出游戏（编辑器里退出 Play，打包后 `Application.Quit()`） |
| `SettingPanel` | 设置面板，独立开合；打开时把 Canvas 的 Sorting Order 抬到 300，压过 HUD（100） |
| `SettingPanel/FullScreen` | 全屏 ↔ 退出全屏，按钮文字跟着 `Screen.fullScreen` 变 |
| `SettingPanel/CloseSetting` | 关闭设置面板 |
| `SettingPanel/AudioSlider` | 音量 → `AudioListener.volume`，存 `PlayerPrefs` |

- 游戏里按 Esc（`GameInput` 的 Pause 键）开/关设置；开着时默认暂停（`pauseWhileSettingsOpen`，`Time.timeScale = 0`）。主菜单上按 Esc 不做任何事。
- `MenuImage` / `SettingImage` 是没贴图的装饰 Image：勾着 `Raycast Target` 会挡住按钮点击，颜色不透明又会把按钮画面整块盖住。运行时有两个开关兜底——`fixBlockingRaycasts` 关掉 Raycast Target，`hideEmptyBackdrops` 关掉「没贴图且不透明」的装饰层（都会打警告）。正式做法还是在场景里给它们贴图、取消勾选 Raycast Target，或者把它们排到按钮前面。

### HUD 与结算（运行时搭）

由 `UiBuilder` 在 `RingCanvas`（Sorting Order 100）上搭出来，不需要预制体：

| 面板 | 显示时机 | 内容 |
|---|---|---|
| Hud | `Loading` / `Collect` / `Elimination` | 阶段与提示、下一次钟声倒计时、自己的血量与牌、场上名单（★=已集齐） |
| Result | `Victory` / `Defeat` | 大字结论、原因、「再来一局」「返回主菜单」 |

字体：`UiBuilder.GetFont()` 优先取系统中文字体（微软雅黑 / 黑体 / 宋体 / Noto CJK），取不到才退回 Unity 内置字体（内置字体没有中文字形，会显示成方框）。

占位美术：角色是 0.9×0.9 的纯色方块（`CharacterInstance.GetPersonaColor` 六人设六色，玩家加亮），换皮只改 `BuildVisual`。

## 五、演示推进（MatchDirector）

没有战斗时，一局不会自己走向结局，所以加了这个可关的组件：

- **收集阶段**：每 `giftIntervalSeconds`（默认 8s）给一个没集齐的人机补一张缺的牌，然后敲一次钟 → B9 触发
- **淘汰赛**：每 `executionIntervalSeconds`（默认 5s）处决一个人机 → 直到只剩玩家
- **调试键**：K 处决玩家（看失败界面）、L 处决一个人机

## 六、这一块没做的

- 技能释放、平 A 命中、碰撞、闪避位移（`PlayerMotor` 只管走路）
- 位置钟声的 `Swaps` 还没有人消费——接场地逻辑时读 `BellResult.Swaps` 移动角色
- 人机 AI（现在只有演示用的随机推进）
- 存档、音效、转场动画
