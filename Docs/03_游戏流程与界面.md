# 03 · 游戏流程与界面

本轮新增两块，**刻意分开**：

| 层 | 文件 | 依赖 | 职责 |
|---|---|---|---|
| 流程规则 | `Assets/Scripts/Flow/MatchState.cs`、`MatchFlow.cs` | 纯 C# | 状态机：能不能开始、什么时候进淘汰赛、什么时候算赢/输 |
| 流程外壳 | `Flow/GameFlow.cs`、`MatchSpawner.cs`、`CharacterInstance.cs`、`PlayerMotor.cs`、`MatchDirector.cs` | UnityEngine | 生角色、订阅钟声、判胜负、把结果转成事件 |
| 界面 | `Assets/Scripts/UI/GameUiController.cs`、`UiBuilder.cs`、`BattleHud.cs`、`BattleHudBuilder.cs`、`HudSprites.cs` | UnityEngine.UI | 只订阅 `GameFlow.StateChanged` / `MapChanged`，画面板、响应按钮；HUD 的血条/技能槽/倒计时读流程层发的数据，不反向改规则 |
| 地图接口 | `Assets/Scripts/Maps/BattleMapId.cs`、`MapScene.cs`、`BattleMapPresenter.cs` | 前者纯 C#，后两者 UnityEngine | 六图随机与场景展示挂接点，含 MapKit 六图映射表与机制状态桥接；场景层级仍待手工搭建（见 `05`、`06_MapKit地图资源与接线.md`） |

界面层不读钟声、不读角色数值；流程层不碰任何 UI 类型。加新界面（结算动画、选人页）只需订阅事件，不动规则。

## 一、状态机

```
MainMenu ──StartMatch()──> Loading ──NotifyParticipantsSpawned()──> Collect
                                                                    │
                                       B9 有人集齐 ──NotifyEliminationStarted()
                                                                    ▼
                                                               Elimination
                                                          ┌─────────┴─────────┐
                                           只剩玩家          │            玩家阵亡 / 人机获胜
                                                          ▼                   ▼
                                                       Victory             Defeat
                                                          └──── ReturnToMenu()/StartMatch() ────> MainMenu / Loading
```

| 方法 | 允许的起点 | 说明 |
|---|---|---|
| `StartMatch()` | 主菜单 / 胜利 / 失败 | 清空局内数据 → 准备中 |
| `NotifyParticipantsSpawned(playerId, count)` | 准备中 | 六个实例注册进钟声系统后调用 |
| `NotifyEliminationStarted()` | 收集人设 | 由 `BellSystem.PhaseChanged(Elimination)` 驱动（B9） |
| `NotifyPlayerLastStanding(bool)` | 收集 / 淘汰 | 只剩玩家 → 胜利；`RequireCompleteSetForVictory` 打开时还要求集齐（B14） |
| `NotifyPlayerDefeated(reason)` | 收集 / 淘汰 | 玩家阵亡 → 失败 |
| `NotifyOpponentWon(id)` | 收集 / 淘汰 | 只剩一个人机 → 失败 |
| `ReturnToMenu()` | 除主菜单外的任何状态 | 清空局内数据 |

非法流转不会抛异常，只会走 `TransitionRejected` 事件并在 `LastRejection` 里留一句原因，方便日志与 HUD 显示。

## 二、一局从点击开始到结算发生了什么

1. 点「开始游戏」→ `GameFlow.StartMatch()`
2. `MatchSpawner.SpawnMatch()`：
   - 清空上一局（销毁旧角色、`Registry.Clear()`、`ResetRound()`）
   - 按 `CharacterRoster` 顺序生成 6 个 `CharacterInstance`（六边形站位），玩家由 `playerPersona` 指定（场景里现在是「精灵游侠」，用于试玩游侠；换回剑士只需把该字段改回「剑士」）
   - 每个实例注册进 `BellSystem`，最后 `DealInitialCards()`（每人随机 1 特质 + 1 技能）
3. `GameFlow` 订阅每个实例的 `Died`，并调 `NotifyParticipantsSpawned()` → 进入 **收集人设**
4. 钟声每 30 秒（或按 B）随机敲一次，特质/技能在六人之间洗牌；某个人集齐一套 → `BellRuntime` 切 `Elimination` → `GameFlow` 收事件 → 进入 **淘汰赛**
5. 淘汰赛里角色阵亡 → `CharacterInstance.Died` → `GameFlow.HandleCharacterDied`
   - 玩家 → `NotifyPlayerDefeated` → **失败界面**
   - 人机 → `BellSystem.NotifyDeath`（B3 必敲位置钟声）→ 检查场上人数 → 只剩玩家 → **胜利界面**
6. 结算界面「返回主菜单」→ `GameFlow.ReturnToMenu()` 销毁角色、清空钟声状态；「再来一局」= 返回 + 立刻开始

**收集阶段阵亡不判负**：按 B8，死亡只是「重新分配到区域并恢复满血」，`GameFlow` 会直接 `Revive()` 并把原因写进日志。只有淘汰赛的死亡才算淘汰。

## 三、场景怎么摆

当前 `SampleScene.unity` 的实际摆法（全是根物体，没有 RingRoot 容器）：

```
InputSystem             (空物体) GameInput
GameFlow                (空物体) GameFlow（含本局地图 CurrentMap / MapChanged）
MainMenu                (Canvas) 手工搭的主菜单，含 SettingPanel
battleCanvas            (Canvas) 手工搭的战斗界面（场景里现名 BattleGround，含 bg1 / CountDown / Setting）
GameUIController        GameUiController（HUD / 结算由它运行时搭）
BattleMapPresenter      (建议新增) 空物体挂 BattleMapPresenter，六个地图槽位拖进 Inspector
BellSystem              BellSystem
Main Camera
EventSystem
```

约束：
- `BellSystem`、`GameFlow`、`GameInput` 都是单例组件，场景里各放一个。
- `battleCanvas` 与六个地图根节点都由用户手工搭、拖进 Inspector；代码只解析引用与切显隐，不自动生成 UI（详见 `05_战斗画布与地图接口.md`）。按名字自动找时优先 `battleCanvas`，兼容旧名 `BattleGround`。
- `MatchSpawner` 目前**还没放进场景**。`GameUiController.autoCreateSpawnerWhenMissing`（默认开）会在编辑器里点「开始游戏」时临时补一个，用 `Assets/Data/Characters/CharacterRoster.asset`；正式做法还是给一个空物体挂 `MatchSpawner` 并指定角色总表。打包后不会自动补，只在 Console 里报警告。
- `MatchSpawner` 最好是 `GameFlow` 的 `spawner`，或至少同场景（留空会自动 `FindObjectOfType`）。
- `PlayerMotor` 由 `MatchSpawner` 自动加到玩家角色上，读 `GameInput.Instance.MoveAxis`。
- 场景文件被 `.gitignore` 忽略（本地文件），所以这里的层级随时可能和文档不一样；`钟声/场景/校验主菜单界面` 菜单会把差异报出来。

## 四、界面

**切换方式：单场景 + 面板切换，不换 Scene。** 换 Scene 就要把 `GameFlow` / `BellSystem` / `GameInput` 和主菜单 Canvas 搬进 `DontDestroyOnLoad`，还要单独保住 `SettingPanel`，收益为零。开局后主菜单**整块 Canvas 关闭**、显示 `battleCanvas`；结算面板与 HUD 叠在它上面。层级从低到高：`battleCanvas` / `MainMenu` 0、`HudCanvas` 90、`RingCanvas` 100、**`TopCanvas` 1000（常驻置顶）**。

> **渲染层级 / 排查「开局后地图与角色不显示」**：地图与角色是挂在 `BattleMaps` 下的**世界空间 `SpriteRenderer`**（sorting order 约 -20/-10/-4），由 `Main Camera` 渲染；而场景里 4 个 UI Canvas（`MainMenu`、`BattleGround`、`TopCanvas`、`HudCanvas`）全是 **Screen Space - Overlay**，永远画在相机画面**之上**。所以只要任意一张「不透明 + 铺满全屏」的 Overlay Image 还开着，就会把整张战场盖掉——现象是「主菜单正常，一开始游戏地图/角色就看不见」，而流程、生成、地图 `Show()` 日志其实全都正常。三道防线：① `HideMenu()` 整块关掉主菜单 Canvas（不再只关直接子物体，避免全屏背景残留）；② `hideBattleBackdrops` 运行时关掉战斗画布里的全屏纯色占位底图；③ `TopCanvas` **常驻激活且常驻置顶**（运行时强制 `SetActive(true)`、Sorting Order = 1000），本身不随状态切换隐藏、也不随设置面板开合还原层级；其下顶层界面各自开合，子面板默认收起，画布是空壳故不会遮挡战场（实测 TopCanvas 下无「有效激活 + 全屏不透明 + 无贴图」的 Image）。

### 主菜单（场景里手工搭的）

`GameUiController` 只负责显示/隐藏和接线，不重建。按名字自动找，也可以在 Inspector 里手动拖：

| 名字 | 作用 |
|---|---|
| `MainMenu`（Canvas） | 主菜单根；进入游戏后**整个 Canvas `SetActive(false)`**（回来时 `SetActive(true)` 并按 Awake 快照还原子物体）。整块关而不是逐个关子物体，杜绝全屏背景 `MenuImage` 残留遮挡战场 |
| `Start` | 开始游戏 → `GameFlow.StartMatch()` |
| `Setting` | 打开设置面板 |
| `Exit` | 退出游戏（编辑器里退出 Play，打包后 `Application.Quit()`） |
| `TopCanvas`（Canvas） | **顶层画布：常驻激活、常驻置顶**（运行时强制 `SetActive(true)` 且 Sorting Order = 1000，高于 `RingCanvas` 100 / `HudCanvas` 90）。用于承载设置 / 结算 / 改键等需要盖住一切的界面；画布本身永不隐藏，只有子面板各自开合 |
| `SettingPanel` | 设置面板，挂在 `TopCanvas` 下（场景里存成激活，运行时由 `HideSettings()` 收起）；打开 / 关闭只切它自己的 `SetActive`，**不再动 `TopCanvas` 的显隐与层级** |
| `SettingPanel/FullScreen` | 全屏 ↔ 退出全屏，按钮文字跟着 `Screen.fullScreen` 变 |
| `SettingPanel/CloseSetting` | 关闭设置面板 |
| `SettingPanel/AudioSlider` | 音量 → `AudioListener.volume`，存 `PlayerPrefs` |
| `SettingPanel/Input` | 「键位调整」→ 打开游戏内改键面板（`KeyBindingPanel`，详见 `Docs/14`） |

**游戏内改键面板**（`Assets/Scripts/UI/KeyBindingPanel.cs`）：给玩家用的，UI 全部由代码在第一次点击时搭到 `TopCanvas` 下，**场景里不需要手搭**。11 行动作 × 主键/备用键，点一下进入捕捉态再按键即可；`Esc` 先取消捕捉、再关面板；「恢复默认」清掉个人键位。打开时暂停，与设置面板的暂停可嵌套，关闭还原 `Time.timeScale`。改键走 `GameInput.TryRebind`，成功即生效并按 `persistToPlayerPrefs` 落盘。

- 游戏里按 Esc（`GameInput` 的 Pause 键）开/关设置；开着时默认暂停（`pauseWhileSettingsOpen`，`Time.timeScale = 0`）。主菜单上按 Esc 不做任何事。改键面板开着时 Esc 优先归它（先取消捕捉、再关面板）。
- `Setting` / `CloseSetting` 两个按钮除了场景里自带的持久 `SetActive`，`GameUiController.BindMenuButtons()` 还会再绑一次 `HandleSettingsClicked` / `HideSettings`；两种绑定叠加执行结果一致，好处是无论从哪条路开合面板，暂停与「顺带收掉改键面板」都会生效。`Update()` 里的 `SyncSettingsState()` 负责把 `settingsOpen` 跟面板真实显隐对齐。
- `MenuImage` / `SettingImage` 是没贴图的装饰 Image：勾着 `Raycast Target` 会挡住按钮点击。运行时 `fixBlockingRaycasts` 会关掉它们的 Raycast Target 并打警告；它们作为背景的**可见性保留**（主菜单整块 Canvas 在开局时关掉，不会污染战场）。正式做法还是在场景里给它们贴图、取消勾选 Raycast Target，或排到按钮前面。
- 注意：设置面板实际挂在 `TopCanvas` 而非 `MainMenu` 下。`TopCanvas` 由 `ResolveTopCanvas()` 按名字（或 Inspector 的 `topCanvas` 槽）解析，`EnsureTopCanvasOnTop()` 在每次状态切换与打开设置前幂等保证「激活 + 置顶」。不要再用 `mainMenuCanvas.sortingOrder` 去抬层级（抬错 Canvas）。

### 战斗画布（场景里手工搭的）

| 名字 / 字段 | 作用 |
|---|---|
| `battleCanvas`（Canvas，场景里现名 `BattleGround`） | 开局后显示、回主菜单隐藏；结算时按 `keepBattleCanvasOnResult` 决定是否保留 |
| `BattleMapPresenter.Scenes[0..5]` | 六个地图槽位，对应 `BattleMapId.Map01..Map06`（= MapKit Z1..Z6）；场景根节点尚未搭建，留空合法 |
| `MapScene` | 每张地图根节点上的组件，`Enter()` / `Exit()` 是可扩展钩子 |

`GameFlow.StartMatch()` 先随机定 `CurrentMap`（`BattleMaps.Pick`），再发 `StateChanged` 与 `MapChanged`；`GameUiController` 收到后显示画布并让展示器切图，并按需刷新两个可选地图标签（地图名 / 机制状态）。**地图不是 Image**：切的是整组场景 GameObject，不是换 Sprite。真实地图中文名、资源目录、配置键与机制脚本由 `BattleMaps.Infos` 映射表提供。接口约定、时序、Inspector 接线步骤与降级行为见 `05_战斗画布与地图接口.md`，MapKit 资产清单与完整接线见 `06_MapKit地图资源与接线.md`。

四个开关：`keepBattleCanvasOnResult`（默认开，结算时透出地图）、`showHudWithBattleCanvas`（默认开，把 HUD 叠在战斗画布上；只想用手工搭的 UI 时关掉）、`hideBattleBackdrops`（默认开，运行时关掉战斗画布里「无贴图 + 不透明 + 四边铺满」的纯色占位底图并打警告——这类 Image 在 Overlay 上会盖住世界空间战场，如早前的 `bg1`）、`keepHudOnResult`（默认关）。

`hideBattleBackdrops` 的判定见 `IsOpaqueFullScreenSolid()`：启用中、`sprite == null`、`color.a ≥ 0.99`、且 `anchorMin (0,0) / anchorMax (1,1)`、四边无缩进。**有美术贴图、半透明、或只是某个定宽控件内部拉伸（如血条 fill）的 Image 一律不动**。正式做法是在场景里直接取消这类占位底图的勾选 / 给它贴图 / 降 alpha。

### HUD（左右血条 + 五个能力槽 + 钟声倒计时）

HUD 由 `BattleHud` 负责，画的是设计稿那一套版式。左右血条**不贴屏幕顶**，整块下移到与倒计时底牌的底边齐平：

```
                              ┌──────┐
                              │  30  │
玩家                           │      │                                    对手
▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁         └──────┘       ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁   ← 血条底边 = 底牌底边
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐     回合 1 / 3   ┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
 特质    普攻    本我    自我    超我                    特质    普攻    本我    自我    超我
 剑客    剑客    钟表师  力士    剑客                    力士    力士    力士    —       力士
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘                  └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

**纵向对齐**（单位均为 1920×1080 参考像素，与 `CanvasScaler` 一致）：中间底牌顶边距顶 8、边长 112，
底边距顶 **120**；左右根物体顶边距顶 **52**，其内血条占 86..120，故血条底边正好落在 120，与底牌底边齐平；
名字在 52..82，技能槽框在 130..214，与底牌下方的「回合 X / Y」（128..158）大致同高。
默认布局由 `BattleHudBuilder.SideTopInset` 推导（`CenterTopInset + BadgeSize - BarTop - BarHeight = 52`）；
场景里手工搭的 HUD 只需把 `Player` / `Opponent` 两个 RectTransform 的 **Pos Y 设为 -52**（Height 保持 176）即可同样对齐。

| 元素 | 数据来源 | 说明 |
|---|---|---|
| 左「玩家」名字 + 血条 | `GameFlow.Player` 的 `CurrentHealth/MaxHealth` | 血条按 `healthSmoothing` 追赶，不会瞬间跳变；数字格式 `healthFormat`（`{0} / {1}`） |
| 右「对手」名字 + 血条 | `HudOpponentPick` 选一个在场人机 | 默认「离玩家最近」；也可选「第一个活着的」或「固定 id」（调试盯人） |
| 双方血条下的虚线框（技能槽） | `CharacterInstance.Loadout`（`AbilityLoadout`） | **固定 5 格**，按 `AbilitySlots.All` 的顺序展示「特质 / 普攻 / 本我 / 自我 / 超我」**各自装的是哪个人设**（如 `特质 剑客`、`本我 钟表师`）；格底色取该人设的辨识色；空格只显示槽位名（灰色）；集齐一套时整个框变金色；还没生成角色时整排收起、显示占位文案「状态栏」 |
| 中间圆角底牌 | `BellSystem.SecondsUntilNextBell` | 距离下一次钟声的秒数（向上取整）；进 `countdownWarnSeconds` 内变红 |
| 底牌下方「回合 X / Y」 | `BellRuntime.SequenceNumber` | **回合 = 已敲响钟声次数 + 1**；总数取 Inspector 的 `roundTotal`（默认 3，设 0 只显示当前回合） |

回合的语义留了旋钮：文档里没有「回合」这一层概念，所以按「第几次钟声」实现，总数可配；
等规则定稿后如果要改成「淘汰赛轮次」，只改 `RefreshRound()` 一处即可。

**怎么接**（两条路，推荐第一条，符合「UI 手工搭」的习惯）：

1. **场景里生成一套再改**：菜单 **钟声 / 界面 / 生成战斗 HUD（场景）** → 在 `HudCanvas`（Sorting Order 90）下生成
   `BattleHud` 整棵树，引用自动填好，之后随便拖位置、改字号、换颜色、加图标；
   删掉用 **钟声 / 界面 / 删除战斗 HUD（场景）**，检查字段用 **校验 HUD 接线**。
2. **完全手搭**：自己摆一套层级，把零件拖进 `BattleHud` 的 Inspector；留空的字段会按名字在子物体里递归找，
   名字对照表见 `BattleHud` 顶部的常量（`PlayerName` / `PlayerBarFill` / `PlayerTraitRow` / `BellValue` / `RoundValue` …）。

两条路都不做也没关系：场景里没有 `BattleHud` 时，`GameUiController` 会运行时用 `BattleHudBuilder` 兜底搭一套，
保证「点开始就有界面」（会在 Console 提示一次）。

**圆角与虚线**：设计稿里的圆角、细描边、虚线框没有对应美术资源，`HudSprites` 按元素的实际像素尺寸
生成贴图（圆角矩形用 SDF 逐像素算，直边虚线按 x/y 相位切），再交给 `Image.color` 染色。
所以：编辑器里看到的是直角矩形，**按 Play 才变成设计稿那样**；自己给某个 `Image` 指定了 Sprite 就不会被覆盖；
元素尺寸变了会自动重生成（`BattleHud` 每 0.5 秒比一次尺寸）。

**可调项**（`BattleHud` 的 Inspector，改完 Play 里立刻见效）：

| 分组 | 字段 |
|---|---|
| 数据来源 | `gameFlow`、`opponentPick`（Nearest / FirstAlive / FixedId）、`fixedOpponentId` |
| 文案 | `playerTitle`、`opponentTitle`、`appendCharacterName`、`traitBoxEmptyText`、`roundFormat`、`roundTotal`、`healthFormat`、`showHealthNumbers`、`showDetails` |
| 布局 | `traitSlotWidth/Height/FontSize/Spacing`（补建槽格的兜底值）、`slotChipHeight`、`slotCaptionFontSize`、`slotValueFontSize`、`fitSlotText` / `fitSlotTextMinFontSize` |
| 文案 | `emptySlotValue`（两行式格子空槽的下行占位）、`traitBoxEmptyText` |
| 外观 | `autoGenerateSprites`、`cornerRadius`、`badgeCornerRadius`、`borderThickness`、`barInset`、`dashPeriod`、`dashRatio` |
| 颜色 | 血条底 / 边框 / 玩家血 / 对手血 / 血条数字 / 名字 / 描边 / 底牌 / 底牌字 / 回合 / 状态框 / 集齐 / 特性标签字 / 倒计时告警 |
| 刷新 | `countdownWarnSeconds`、`healthSmoothing` |

`showDetails` 打开会在左下角补一段调试明细（阶段、在场人数、五个能力槽与冷却），默认关。

**技能槽怎么手搭**（推荐，符合「UI 手搭再拖 Inspector」的习惯）：

- 一根横向的 `HorizontalLayoutGroup` 当行（场景里现名 `PlayerTraitRow` / `OpponentTraitRow`，也认 `PlayerSkillRow` / `OpponentSkillRow`），
  下面挂 5 个格子，顺序就是 `特质 → 普攻 → 本我 → 自我 → 超我`（**顺序由 `AbilitySlots` 枚举决定，不要重排**）。
- 每个格子两种形态都支持：
  - **两行式**（推荐）：`Image`（底色）+ `Caption`（槽位名，13 号）+ `Label`（人设名，20 号）；
  - **单行式**：`Image` + 一个 `Text`，显示成「特质 剑客」。
- 格子不足 5 个时 `BattleHud` 会在运行时补建（沿用第 0 格的实际尺寸与形态，所以补出来的和第 1 格长得一样）；
  一格都没搭（或整行没引用）时才用 Inspector 的 `traitSlotWidth/Height` 兜底。
- 想整排换位置 / 换大小：直接拖动 `PlayerTraitBox` / `PlayerTraitRow`，代码不会去改它们的尺寸；
  槽格底色是 `HudSprites` 按实际尺寸生成的圆角贴图，自己给 `Image` 指定贴图就不会被覆盖。
- 文案口径：特质槽可以囤多张（B6 夺取），格子显示**最后获得**的那张人设名（与「形象跟随特质」一致），
  多出来的显示成 `剑客+1`；完整清单仍在 `showDetails` 的明细里。

### 结算（运行时搭）

由 `UiBuilder` 在 `RingCanvas`（Sorting Order 100）上搭出来，不需要预制体：

| 面板 | 显示时机 | 内容 |
|---|---|---|
| Result | `Victory` / `Defeat` | 大字结论、原因、「再来一局」「返回主菜单」 |

字体：`UiBuilder.GetFont()` 优先取系统中文字体（微软雅黑 / 黑体 / 宋体 / Noto CJK），取不到才退回 Unity 内置字体（内置字体没有中文字形，会显示成方框）。

美术现状：剑士 / 斯巴达 / 力士 / 精灵游侠有序列帧，另外两套人设（蒸汽机械师 / 钟表匠）暂时统一借剑士当占位。**形象跟随「特质」**：手上**最后获得**的那张特质属于哪个人设，角色就是哪个人设的造型（一张特质都没有时按剑士处理），所以换牌/抢牌之后人设与外观会一起变，改人设的序列帧只需在 `CharacterInstance.ResolveVisualPersona` 里放开映射、在 `RefreshVisualAnimation` 里接上组件。`CharacterInstance.GetPersonaColor` 六人设辨识色仍保留，只用于 HUD 五个技能槽格的底色，不再给角色本体染色。详见 `Docs/18_角色形象跟随特质.md`。

## 五、演示推进（MatchDirector）

没有战斗时，一局不会自己走向结局，所以加了这个可关的组件：

- **收集阶段**：每 `giftIntervalSeconds`（默认 8s）给一个没集齐的人机补一张缺的牌，然后敲一次钟 → B9 触发
- **淘汰赛**：每 `executionIntervalSeconds`（默认 5s）处决一个人机 → 直到只剩玩家
- **调试键**：K 处决玩家（看失败界面）、L 处决一个人机
