# 04 · 人设技能系统（五槽模型）

本文对应《技能表.txt》的 30 条人设能力（六人设 × 特质 / 普攻 / 本我 / 自我 / 超我），
以及这些能力如何与第一轮的**人物基础数值**衔接。

---

## 一、基本模型：一个人有 5 个能力槽

钟声系统只知道两种卡：**特质卡**（`TraitCard` = 人设）与**技能卡**（`SkillCard` = 人设 + 本我/自我/超我）。
本轮把「能力」与「卡」拆成两层：

| 概念 | 类型 | 谁发的 | 说明 |
|---|---|---|---|
| 特质卡 | `TraitCard(PersonaId)` | 特质钟声 | 一个人设只有一张特质 |
| 技能卡 | `SkillCard(PersonaId, SkillTier)` | 技能钟声 | 每个等级各 6 张，共 18 张 |
| 普攻 | 生成角色时发 | 角色自身人设 | 不参与任何钟声 |
| **能力卡** | `AbilityCard(PersonaId, AbilitySlot)` | — | 上面三者的统一表示 |

`AbilitySlot` = 特质 / 普攻 / 本我 / 自我 / 超我（`Trait=0, BasicAttack=1, Id=2, Ego=3, Superego=4`）。

**关键点：五个槽是彼此独立的。** 一个角色身上可以同时出现

```
特质：剑客 ｜ 普攻：力士 ｜ 本我：钟表师 ｜ 自我：蒸汽机械师 ｜ 超我：精灵游侠
```

——这正是「特质、普攻、本我、自我、超我 5 个能力可能分散在不同角色身上」的直接表达。
装备表 `AbilityLoadout` 只按槽位存卡：特质槽可叠多张（最多 6），其余四槽各一张，同槽再放会把旧卡顶出来
（`TryAdd(card, out displaced)`），由调用方决定是替换还是退回牌池（B11）。

### 集齐判定：默认不含普攻

钟声原文的「集齐一套」是**特质 + 三个技能等级**（B13 豁免、B14 获胜都用这个口径）。
所以 `AbilityCards.IsCompleteSet(cards, persona)` 默认**不看普攻**；需要「五槽才算齐」时传
`includeBasicAttack: true`。这一条是为了不改变已经跑通的 B1–B14 语义。

### 数值真源：资产，不再是代码常量（M1「改表不改码」）

早期版本把 30 条数值写成 `AbilityCatalog` 的静态代码常量，改一个数字要改 C# 并重新编译，
与架构文档 M1 的验收标准「改表后无需改代码即可生效」有偏差。本轮已改为：

```
Assets/Data/Abilities/AbilityTuning.asset   ← 策划在 Inspector 里改的真源
        │  GameFlow.Awake → AbilityTuningAsset.Apply()
        ▼
AbilityCatalog.SetSource(AbilityDefinitionListSource)  ← 全系统唯一门面
        │  AbilityCard.Definition / AbilityRuntime / Editor 校验 / HUD
        ▼
派生数值 → 战斗层
```

- `AbilityCatalog` 的所有既有 API（`Get` / `TryGet` / `All` / `GetPersona` / `GetSlot` /
  `CollectIssues` / `ToOverview`）签名不变，战斗层与离线测试无需改动；
- `BuildAll()` 里的 30 条降级为**代码种子**，只用于生成资产、离线测试与资产缺失时回退；
- 种子仍保留编译期查漏（`CollectIssues` 报「某人缺某槽」「同一对 (人设,槽) 重复」），
  资产侧则由 `AbilityTuningData.CollectIssues` 做同样的自检；
- 离线回归 `.check/numericlayer` 断言：把资产里「突进斩」伤害改成 99、CD 改成 7 后，
  `AbilityCard.Definition` 与 `AbilityRuntime.GetCooldownSeconds` 立即读到新值，`ResetToSeed()` 后恢复 12 / 2。

## 三、与人物属性的衔接

`AbilityRuntime.ComputeDerived()` 是一条单向管线，**基础值永远来自角色数值，能力只做修正**：

```
CharacterBaseStats（或 CharacterStatBlock 快照）
        ↓ CharacterStatAdapter / FromDocument
   生命 / 防御 / 减伤 / 速度 / 移速 / 跳跃 / 攻击间隔
        ↓ ① 普攻数值覆盖（伤害、前摇、射程）
        ↓ ② 特质被动（剑意增伤、斯巴达 +8 防御、精灵之目射程 8、过载损耗移速×生命比）
        ↓ ③ 限时修正（施放技能挂上的乘区/加区，按秒衰减）
        ↓ ④ 联动（攻击间隔 ÷ 攻速倍率、间隔覆盖取最小、射程取最大）
   DerivedAbilityStats → 移动、平A、HUD 全部读这一份
```

| 衔接点 | 例子 |
|---|---|
| 移速 | `PlayerMotor` 用 `CharacterInstance.MoveSpeedCellsPerSecond`（派生值），所以「剑意/过载损耗/高性能模式/慢摆」都会自然影响走位；定身时 `Derived.Immobile` 直接拦住移动 |
| 攻击间隔 | 普攻冷却 = 派生 `AttackIntervalSeconds`；「高性能模式」×1.5 攻速会把间隔压短，「狂战」的 `AttackIntervalOverride 0.5` 直接覆盖 |
| 减伤 | `CharacterInstance.TakeDamage` 用 `CharacterBalance.ApplyReduction(原伤害, 派生减伤) × 派生受伤倍率`，所以「敛息 +30%」「绝对防御 ×0.1」「催龄 −20% 防御」都走同一处 |
| 防御 | 派生伤害用防御反算减伤（防御/500），斯巴达韧性的 +8 会抬高整体减伤 |
| 生命 | `AbilityRuntime` 镜像当前生命，逆时靠它回滚；`Reset/Revive` 会同步 |
| 回血 | 斯巴达韧性 0.5/s、沉腰调息 4/s 由 `Tick` 累计，`ConsumeRegen()` 交给 `CharacterInstance.HealSilently` |

## 五、逐条说明（原文数值）

### 剑客（Swordsman）

- **特质｜剑意**：每次造成伤害（平A/任意技能）得 1 层，持续 2 秒，上限 3 层，叠层刷新；每层 +10% 最终伤害（全局增伤乘区，不绑定技能）。
- **普攻｜近战横斩**：正前方 1 格长 × 2 格宽矩形；前摇 0.15s；伤害 4。
- **本我｜突进斩**：向输入方向突进 2 格，覆盖长 3 × 宽 2 线性区域；伤害 12；CD 2s（全表最短）。
- **自我｜敛息**：立即清除自身所有负面效果；1.5s 内 +30% 减伤；回复 10 生命；CD 5s。
- **超我｜剑域**：自身周围 2.5 格半径领域持续 2s；施法者在域内时攻击转化为等量全领域剑气；域内敌人移速 −30%、受到伤害 +15%；CD 5s。

### 蒸汽机械师（SteamMechanic）

- **特质｜过载损耗**：实际移速 = 基础移速 ×（当前生命 / 生命上限），回血同步恢复；每累计受击 3 次进入「蓄势」，下次平A命中 ≥1 枚时击退 1 格并消耗蓄势。
- **普攻｜蒸汽铳（散弹）**：正前方 5 格扇形，总散射角 28°（±14°）；弹速 6 格/s；前摇 0.2s；4 枚散弹，每枚 2 伤害。
- **本我｜高压喷射**：前方 4 格扇形，总散射角 36°（±18°）；7 枚蒸汽弹，每枚 2 伤害；命中 ≥3 枚时目标移速 −30% 持续 0.5s；弹速 6 格/s；前摇 0.3s；CD 4s。
- **自我｜紧急排气**：原地停止 0.5s（无无敌帧）；立即回复 15；清除自身所有减速/定身；随后 2s 受伤 −25%；CD 5s。
- **超我｜高性能模式**：2s 内移速与攻击力 ×1.5；结束后 1s 内两者降为 70% 再恢复；CD 5s。

### 斯巴达战士（Spartan）

- **特质｜斯巴达韧性**：「半举盾」姿态：基础防御 +8；每秒回复 0.5 生命。
- **普攻｜长矛突刺**：前方 2 格长 × 1 格宽矩形；前摇 0.2s；伤害 5。
- **本我｜战阵横扫**：前方 2×2 矩形蓄力横扫；伤害 10；命中目标移速 −20% 持续 1.5s；CD 4s。
- **自我｜绝对防御**：「全举盾」2s：正前方 180° 扇形受伤 −90%；自身移速 −50%；禁止普攻与本我技能；可再次点击提前解除；CD 5s。
- **超我｜狂战**：投矛前方 5 格（弹速 8 格/s，宽 1 格），首个目标 8 伤害；随后「单刀狂战」3s：防御 −30%，平A 改单刀（射程 1 格、单发 2 伤害、间隔 0.5s）；姿态结束 1.5s「重新装备」硬直（移速 −30%、无法攻击）；CD 6s。

### 精灵游侠（Ranger）

- **特质｜精灵之目**：射程 8 格；每次平A或本我技能命中得 1 层「风之优雅」，持续 2s，上限 3 层，每层 +5% 移速；满 3 层时下一次平A消耗层数变「重箭」，该次伤害 +2。

- **超我｜缚地荆棘**：鼠标指定前方 4 格内任一格为中心，生成 3 格长 × 1 格宽荆棘地形持续 2s；敌人试图离开时被缠绕定身 0.75s；游侠自身穿越不受影响；CD 4s。

### 钟表师（Clockmaker）

- **特质｜逆时**：受到必定致死一击时，把自身状态（生命、坐标、增益/减益）倒回 3 秒前，该次致死伤害作废；CD 30s。

- **超我｜慢摆**：改变周围半径 5 格时间流速 2s：域内目标动作速度 ×0.6（移速、攻速、施法读条、起跳动作均变慢）；前摇 0.4s；CD 6s。

### 力士（Strongman）

- **特质｜力量**：对同一目标每累计第 3 次平A附带 1s 眩晕，计数清零；按目标独立计数，1.5s 未命中该目标清零；目标眩晕结束后获得 1.5s 眩晕抗性（免疫新眩晕）。

- **超我｜虚手锚定**：前摇 0.3s，前方 4 格长 × 2 格宽直线（遇墙在墙前停止），命中首个敌人 2 伤害并记为「锚点」；目标 1s 内可自由行动，1s 结束时被强制拉回锚点坐标并定身 0.5s；CD 5s。

## 六、13 类效果原语 → 字段映射

《技能表.txt》末尾归纳了 13 类效果原语。`AbilityDefinition` 用「少量通用字段 + `AbilityShape`」覆盖它们，
不写 30 个特化类：

| 原语 | 落点字段 | 备注 |
|---|---|---|
| ① 直线弹道 | `Shape=Line` + `RangeCells` / `AreaWidthCells` / `ProjectileSpeed` | 命中判定由战斗层做 |
| ② 扇形多弹丸 | `Shape=Fan` + `SpreadDegrees` / `PelletCount` / `PelletDamage` | 蒸汽铳、高压喷射 |
| ③ 折返弹丸 | `Returns=1` + `ProjectileSpeed` | 时钟飞刃 |
| ④ 矩形/圆形即时判定 | `Shape=Rect` / `Circle` + `AreaLengthCells` / `AreaWidthCells` / `RadiusCells` | 横斩、剑域、慢摆 |
| ⑤ 突进/冲刺（分段判定） | `DashCells` + `DashSpeedCellsPerSecond` + `Notes` 记录分段档位 | 崩进冲撞的分段表在 Notes，运行时只暴露总伤害 |
| ⑥ 位移/强制拉回 | `Shape=Line` + `RootSeconds` + `Notes` | 虚手锚定 |
| ⑦ 击退 | `KnockbackCells`（特质被动走 `NotifyBasicAttackHit`） | 蓄势 |
| ⑧ 眩晕/定身/减速 | `StunSeconds` / `RootSeconds` / `SlowPercent` + `SlowSeconds`；抗性 `StunResistanceSeconds` | 力量 |
| ⑨ 增益减益与乘区 | `DamageTakenMultiplier` / `MoveSpeedMultiplier` / `AttackSpeedMultiplier` / `DefenseMultiplier` / `DamageTakenBonusPercent` | 乘区在运行时相乘、减伤相加 |
| ⑩ 治疗与护盾 | `HealAmount` / `HealPerSecond` / `ShieldAmount` + `ShieldSeconds` | 敛息、自然恩赐、沉腰调息 |
| ⑪ 净化 | `Notes` 标注 + 施放时 `CancelCast` / 清负面（战斗层实现） | 敛息、紧急排气、自然恩赐 |
| ⑫ 姿态/状态切换 | `DurationSeconds` + `BasicAttackDamageOverride` / `AttackIntervalOverride` / `MoveSpeedScalesWithHealth` | 高性能模式、狂战、过载损耗 |
| ⑬ 地形生成与时间流速场 | `Shape=Ground` / `Circle` + `DurationSeconds` + `SlowPercent` | 缚地荆棘、慢摆 |

约定：**0 表示不生效，倍率 0 表示无修正**（不是「乘 0」）。所以 `DamageTakenMultiplier=0.75` 才是「受伤 −25%」。

### 六·补、effectRefs → 执行器映射（本轮补齐）

架构文档 §6 定义 `SkillDefinition` 应带 `effectRefs[]`「指向 M3 执行器组合」，M3 3.1 的验收标准是
「新增一个技能 = 组合已有原语 + 配表，不写新框架代码」。改造前这两点在代码里都不存在：
上面那张表只是**文档说明**，`AbilityDefinition` 是扁平字段，没有任何「原语 ID → 可执行对象」的映射，
新增技能仍要改 `AbilityCatalog` 与 `AbilityRuntime`。

本轮补齐三层：

| 层 | 类型 | 作用 |
|---|---|---|
| 键 | `AbilityEffectId`（13 类，只追加不重排） | 稳定 ID，写进 `.asset` 存档 |
| 引用 | `AbilityEffectRef`（EffectId / Scope / Parameter / Note） | 资产里可增删改的 `effectRefs[]` 元素 |
| 值 | `IAbilityEffectExecutor` + `AbilityExecutorRegistry` | 按 ID 解析成执行器，生成 `AbilityEffectInstance` |

| # | 原语 | 执行器 | 落地状态 |
|---|---|---|---|
| ① | 直线弹道 | `LineProjectileExecutor` | 登记入口（空间判定待战斗层） |
| ② | 扇形多弹丸 | `FanPelletsExecutor` | 登记入口 |
| ③ | 折返弹丸 | `ReturningProjectileExecutor` | 登记入口 |
| ④ | 矩形/圆形即时判定 | `InstantAreaExecutor` | 登记入口 |
| ⑤ | 突进/冲刺 | `DashExecutor` | 登记入口 |
| ⑥ | 位移/强制拉回 | `ForcedDisplacementExecutor` | 登记入口 |
| ⑦ | 击退 | `KnockbackExecutor` | **已由 `AbilityRuntime` 落地** |
| ⑧ | 眩晕/定身/减速 | `CrowdControlExecutor` | **已落地** |
| ⑨ | 增益减益与乘区 | `StatModifierExecutor` | **已落地** |
| ⑩ | 治疗与护盾 | `HealShieldExecutor` | **已落地** |
| ⑪ | 净化 | `CleanseExecutor` | 登记入口（负面类型系统待战斗层） |
| ⑫ | 姿态/状态切换 | `StanceExecutor` | **已落地** |
| ⑬ | 地形与时间流速场 | `TerrainTimeFieldExecutor` | 登记入口 |

- **`AbilityEffectRefs.InferFrom(definition)`** 把「字段 → 原语」的映射变成可执行规则：
  生成资产时自动为 30 条能力填好 **58 条 effectRefs**，策划在 Inspector 里再按需增删；
  「逆时 / 回溯」的状态快照不属于 13 类原语，统一登记为 ⑫ 并在 `Note` 里注明
  「由 M2.5 / `AbilityRuntime` 实现」，不虚报 M3 已实现。
- **`AbilityExecutorRegistry.Register(executor)`** 允许战斗层实现真实命中判定后直接替换同名执行器，
  不用改 `AbilityDefinition` / `AbilityCatalog` —— 即 M3 3.1 的「不写新框架代码」。
- **校验闭环**：`AbilityDefinition.CollectIssues` 会检查每条 effectRef 的 ID 是否属于 13 类、
  是否已有登记的执行器、是否重复引用；引用 `(AbilityEffectId)999` 会在校验器里报 Error，
  而不是运行时静默失效。
- `AbilityDefinition.DescribeEffects()` 返回 `IReadOnlyList<AbilityEffectInstance>`，
  战斗层、Editor 校验、文档生成都消费同一份解析结果。

## 七、运行期语义

- **冷却**：`CooldownSeconds > 0` 用自身冷却；`=0` 的普攻用派生攻击间隔。`Tick` 每帧递减。
- **施法期状态**：`ImmobileSeconds`（定身）、`InvulnerableDuring`（无敌）、`CanCancelEarly`（可提前解除）由
  `TryActivate` 设置，`CancelCast` 或到期清除。移动与受伤都读派生值，不需要每个技能单独接线。
- **限时修正**：施放后把移速/攻速/受伤/减伤/间隔/射程/回血挂成 `TimedModifier`，按 `DurationSeconds` 递减；
  `ComputeDerived` 里乘区相乘、减伤相加、间隔取最小、射程取最大。
- **叠层**：剑意（`NotifyDamageDealt`）、风之优雅（`NotifyBasicAttackHit`）、过载损耗（`NotifyDamageTaken` 计数）、
  力量（按 `targetId` 独立计数 + 抗性窗口）——全部在 `AbilityRuntime` 内部，不依赖战斗层重复实现。
- **逆时**：`TryConsumeLethalHit` 用 3 秒生命快照（每 0.1s 采样，环形 64 格）回滚，消耗特质槽 30s 冷却并清空增益。
- **生命镜像**：`SetHealth/NotifyHealth/Reset` 由 `CharacterInstance` 驱动，保证派生数值与回血读的是同一份生命。

## 八、Unity 侧接线（已接好）

| 位置 | 做了什么 |
|---|---|
| `CharacterInstance.Initialize` | 建 `AbilityLoadout` + 开局普攻卡 + `AbilityRuntime`（统计来源 `CharacterStatAdapter`），并 `RefreshLoadout()` |
| `CharacterInstance.TakeDamage` | 走派生减伤与受伤倍率；无敌直接免伤；致死先问 `TryConsumeLethalHit`（逆时），没救回才 `Died` |
| `CharacterInstance.Update` | `abilities.Tick` + 生命同步 + `ConsumeRegen` 自动回血 |
| `CharacterInstance.RefreshLoadout` | 钟声换牌后 `SyncFromBellCards(特长, 技能, out rejected)`，五槽与钟声手牌保持一致 |
| `PlayerMotor` | 定身时不动；移速用派生值（速度 ×0.03 再乘能力修正） |
| `AbilityCaster` | 1/2/3 施放本我/自我/超我；左键平A（找射程内最近目标 → `NotifyBasicAttackHit` → `TakeDamage` → 击退/眩晕） |
| `MatchSpawner` / `GameFlow` | 开局与每次钟声后 `RefreshLoadouts()`；玩家物体自动补挂 `PlayerMotor` + `AbilityCaster` |
| `GameUiController` | HUD 显示派生生命/防御(减伤)/移速，逐槽列出能力与冷却，并显示剑意/风之优雅等状态 |
| **`GameFlow.Awake` / `ApplyNumericLayer`** | **把 `AbilityTuning.asset` 拖进 Inspector 的「数值层」字段后注入 `AbilityCatalog` + `CharacterBalance`；留空回退代码种子** |
| **`AbilityTuningAsset.Apply`** | **校验 30 条完整性 → `SetSource(...)` + `BalanceDecisionRuntime.Configure(...)`，一次调用让全系统改读资产** |

`AbilityCaster` 是**演示用战斗壳**：真做命中判定（射线/扇形检测、弹道、地形）时，把这个类整块替换即可，
`AbilityRuntime` 与 `AbilityCatalog` 不用动。数值真源从代码常量换成 Inspector 资产后，
这条结论依然成立 —— 战斗层只通过 `AbilityCatalog` 门面取数，不知道背后是种子还是资产。
