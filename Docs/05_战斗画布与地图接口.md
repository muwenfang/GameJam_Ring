## 三、六个地图的接口约定

### 编号与槽位

`BattleMapId` 的成员名是中性占位名 `Map01`…`Map06`，值 **0..5 连续**。**11-25 刻意保留成员名与值不改**：它们是 Inspector 里已序列化的枚举值，改名会让已存下来的 `Fixed Map` 等字段产生歧义。六张地图的真实身份（中文名、Z 区根节点名、`MapKit/Maps/0X` 资源目录、`map_config.json` 键、机制脚本名）统一放在 `BattleMaps.Infos` 映射表里，按编号查询即可 —— 完整对照表见 `Docs/06` 第三节。

```
Scenes[0] → Map01 / Z1 雨夜竹林    Scenes[1] → Map02 / Z2 蒸汽井盖    Scenes[2] → Map03 / Z3 竞技场
Scenes[3] → Map04 / Z4 精灵森林    Scenes[4] → Map05 / Z5 钟塔        Scenes[5] → Map06 / Z6 洞穴
```

`BattleMaps` 提供 `Count` / `All` / `Infos` / `Info` / `IndexOf` / `FromIndex` / `Pick(int)` / `Pick(Random)` / `ClampToValid` / `IsDefined` / `ToDisplayName`，以及 `ToZoneName` / `ToZoneFolder` / `ToAssetPath` / `ToConfigKey` / `ToMechanicScript` / `ToMechanicSummary` 六个 MapKit 映射扩展方法。随机源由调用方注入：Unity 侧传 `UnityEngine.Random.Range(0, 6)` 的结果，纯映射逻辑本身不碰 Unity API，因此可以离线测边界。

> 注意与 B8「六区域」区分：`BattleMapId` 是**这一局选哪张地图**；每张地图内部的 6 个区域锚点是 `MapScene.RegionAnchors`，属于另一个层次。上传的设计场景 `MapDesign_钟声.unity` 把 Z1..Z6 六个区域放在同一张图里做机制验证，与本枚举 0..5 一一对应，但层次不同，未强行统一。

### 为什么地图不是 Image

`battleCanvas` 里现有一张全屏 `bg1` 背景图，但**地图不等于换这张图的 Sprite**。一张地图是一整棵可带脚本的 GameObject 层级：背景分层、地面与碰撞、出生点、灯光、粒子、动画，将来甚至可能是叠加加载的独立 Scene。所以接口设计为：

- 切换单位 = `MapScene`（挂在一张地图的**根节点**上），不是 `Sprite` / `Image`；
- `BattleMapPresenter.Show(id)` = 其余五张 `Exit()` + 选中的 `Enter()`，不碰任何贴图字段；
- `MapScene.Enter()` / `Exit()` 是 `virtual`，默认只做 `gameObject.SetActive(true/false)`。做地图实体时按需重写：初始化地形与碰撞、摆出生点、切相机边界、播放入场演出、`SceneManager.LoadSceneAsync(..., Additive)`、退出时卸载；
- `MapScene.RegionAnchors`（可选 6 个 `Transform`）预留给 B8 六区域与位置钟声 `BellResult.Swaps` 的空间落点，`GetRegionAnchor(i)` 未配置返回 null；
- `MapScene.StatusText()`（11-25 新增）用反射读取拖进 `Zone Mechanic` 槽位的 MapKit 机制组件，供 HUD 显示运行状态；不拖时返回空串。

`MapScene` 刻意不是 `abstract`：MapKit 资源虽已入库，场景层级仍由用户手工搭；在那之前挂一个空根物体占位即可验证随机链路。

## 四、开局时序

```
点「开始游戏」
  → GameUiController.HandleStartClicked
  → GameFlow.StartMatch()
      ① CurrentMap = BattleMaps.Pick(Random.Range(0, 6))   ← 先定本局地图
      ② Flow.StartMatch() → StateChanged(MainMenu → Loading)
           → GameUiController.ApplyState(Loading)
               battleCanvas.SetActive(true)
               BattleMapPresenter.Show(CurrentMap)
               RefreshMapLabels(CurrentMap)（可选标签）
      ③ MapChanged 事件 → HandleMapChanged → Show(CurrentMap)（幂等，直接返回）
  → 生成六人 → StateChanged(Loading → Collect) → ApplyState 再 Show（幂等）
  → 结算 / 返回主菜单 → ApplyState(MainMenu) → battleCanvas 隐藏 + Hide() + 清空标签
```

**先赋值 `CurrentMap`、再 `Flow.StartMatch()`** 是刻意的：`StateChanged` 在 `Flow.StartMatch()` 内部触发，UI 收到 `Loading` 时读到的必须已经是本局的地图，否则会闪一帧上一局的值。

`GameFlow` 上另有两个调试字段：`Randomize Map`（默认开）与 `Fixed Map`。关掉随机后固定用 `Fixed Map`，方便只测某张地图（`Map01`=Z1 雨夜竹林 … `Map06`=Z6 洞穴）。

## 五、Inspector 接线清单（需要你做的）

1. **战斗画布**（二选一）
   - 把场景里现有的 `BattleGround` Canvas 改名为 `battleCanvas`；或
   - 保持原名也行 —— 代码按 `battleCanvas` 优先、`BattleGround` 兼容、大小写不敏感自动查找；最稳妥是直接把它拖进 `GameUiController` 的 **Battle Canvas** 槽位。
2. **挂展示器**：新建一个空物体（或挂在 `battleCanvas` 上），加 `BattleMapPresenter`。场景里没有时代码会自动找；找不到会打警告，但不阻断开局。
3. **六张地图实体**：11-25 起 MapKit 资源已入库（`MapKit/Maps/01..06`）。每张地图建一个根 GameObject → 挂 `MapScene` → 设置 `Map Id` → 建议根节点在场景里**存成隐藏**（`Show` 只会激活选中的那张，初始全激活会六张叠在一起）→ 依次拖进 `Scenes[0..5]`。机制组件、物体命名与层级依赖、两个可选 HUD 标签的完整步骤见 **`Docs/06_MapKit地图资源与接线.md` 第六节**。
4. **可选开关**：`Keep Battle Canvas On Result`（结算是否保留战斗画布）、`Show Hud With Battle Canvas`（是否叠加运行时 HUD）。

`battleCanvas` 与 `BattleMapPresenter` 都是序列化字段，C# 侧给了默认值/自动查找兜底，**即使一个槽位都不拖，Play 也能正常开局**（自动找到 `BattleGround` 并显示），只是地图场景不会切换。

## 六、降级行为与日志

| 情况 | 行为 |
|---|---|
| 没挂 `BattleMapPresenter` | 每局仍随机地图，`[流程] 本局地图：Z1 雨夜竹林`（真实中文名）照常打印；界面不切地图，启动时打一条警告 |
| 选中槽位为空（`Scenes[i] == null`） | 其余五张 `Exit()`，本局不显示地图，每局打一条明确警告指向槽位下标与真实地图名 |
| 收到非法编号 / Inspector 里手填了越界值 | `Pick` / `ClampToValid` 折回合法范围，不抛异常；`Info()` 返回 null，映射扩展方法返回空串或「未知地图」 |
| 找不到 `battleCanvas` | 启动时打警告，界面切换仍按主菜单 / HUD / 结算原逻辑工作 |
| 没拖 `Zone Mechanic` / 两个地图标签 | 机制照常运行，HUD 显示「机制：待命」或不显示文字，不阻断开局 |

`BattleMapPresenter.Show()` 是**幂等**的：`Loading → Collect → Elimination` 每次状态切换都会调，但同一张地图不会反复触发 `Enter()`；回主菜单 `Hide()` 后下一局重新 `Show` 才会再次进入。
