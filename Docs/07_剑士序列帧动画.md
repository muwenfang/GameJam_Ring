# 07 剑士序列帧动画

## 一、结论摘要

剑士（`PersonaId.Swordsman`）的挥剑、跑步与突刺动作已做成可播放的序列帧动画，并接入移动、普攻与本我技能代码：

- **动画资产**：`Assets/Animations/Swordsman/` 下四个标准 `AnimationClip`——`Swordsman_Idle`、`Swordsman_Run`、`Swordsman_Attack`、`Swordsman_Dash`。
- **运行时表现**：由 `SwordsmanSpriteAnimation` 直接切帧（角色为运行时生成、无 prefab，因此不走 Animator 状态机）。
- **接入点**：`PlayerMotor` 驱动跑动状态，`AbilityCaster.BasicAttack()` 驱动挥剑，`AbilityCaster.ExecuteSwordsmanDash()` 驱动突刺，`CharacterInstance.BuildVisual()` 负责外观装配。

三段动作的帧序、帧率与 `.anim` 资产完全一致，便于后续换成 Animator 时对拍。

---

## 二、素材规格

素材位于 `Assets/Resources/Swordsman/`，均为 8-bit RGBA、背景透明（约 84% 像素 `alpha = 0`），导入类型已是 **Sprite（`spriteMode = 1`、`PPU = 100`）**，无需再改导入设置。

| 序列 | 文件 | 帧数 | 画布尺寸 | 脚底距画布底 |
|---|---|---|---|---|
| 挥剑 | `Attack_00` ~ `Attack_05` | 6 | 256 × 240 | 约 20 px |
| 跑步 | `Run_00` ~ `Run_06` | 7 | 219 × 240 | 约 66 px |
| 突刺 | `Dash_00` ~ `Dash_04` | 5 | 302 × 250（`Dash_04` 为 291 × 250） | 约 17 px |

需要注意的既有问题：**三套序列的画布基准并不一致**。若都按 Sprite 中心摆放，跑步切到挥剑时人物会上下跳约 46 px、水平错位约 18 px；突刺与挥剑之间也有约 7 px 的垂直差。本次实现按「脚底锚定」消除这些跳动（见第四节）。

## 三、动画资产

目录：`Assets/Animations/Swordsman/`

| 剪辑 | 帧序 | 帧率 | 时长 | 循环 |
|---|---|---|---|---|
| `Swordsman_Idle.anim` | `Attack_00` 单帧 | 12 fps | 0.083 s | 是 |
| `Swordsman_Run.anim` | `Run_00` → `Run_06` | 12 fps | 0.583 s | 是 |
| `Swordsman_Attack.anim` | `00 → **01 → 01** → 02 → **03 → 03** → 04 → 05` | 14 fps | 0.571 s | 否 |
| `Swordsman_Dash.anim` | `00 → 01 → 02 → **03 → 03** → 04` | 16 fps | 0.375 s | 否 |

**关于「挥剑补一两帧」**：没有新增图片素材，而是在时间轴上给关键姿势补停留帧——

- 蓄力帧 `Attack_01`（举刀过顶）多停 1 帧：挥砍前的预备动作更清晰。
- 刀光帧 `Attack_03`（斩击末端）多停 1 帧：强调出刀的那一下。

6 帧 → 8 个采样点，`14 fps` 下时长 0.571 s，与剑士 0.7 s 的攻击间隔（`CharacterBalance`）基本贴合，收招后留约 0.13 s 回正。跑步保持现有 7 帧原样，未做增删。

**关于突刺的节奏**：5 帧按 16 fps 播放（比挥剑更快，突出突进的迅捷），并在刀光爆发帧 `Dash_03` 多停 1 帧强调命中。5 帧 → 6 个采样点，时长 0.375 s。突刺技能（本我「突进斩」）的 CD 为 2 s，动画只占其中约 19%，其余时间为收招与走位。

动作分镜：`Dash_00` 压低身位蓄势 → `Dash_01` 前倾冲刺 → `Dash_02` 出刀 → `Dash_03` 刀光爆发 → `Dash_04` 收招站定。

> 这些 `.anim` 目前作为**可预览、可微调的标准资产**存在：在 Unity 里可直接拖进 Animation 窗口检查帧序，或拖到带 `SpriteRenderer` 的物体上让 Unity 自动生成 Animator。运行时实际播放走的是代码切帧（原因见下节）。

## 四、运行时实现与关键决策

### 4.1 为什么用代码切帧而不是 Animator

角色是 `MatchSpawner.CreateInstance()` 运行时 `new GameObject()` 生成的，项目里没有任何角色 prefab。若走 Animator，就必须在代码里 `AddComponent<Animator>()` 并赋 `RuntimeAnimatorController`，本质仍是代码装配，还多一层状态机维护成本。

因此沿用项目已有思路：**`SwordsmanSpriteAnimation` 直接按时间切 Sprite**。该组件原本已存在但不可用（见 4.3），本次重写。

### 4.2 脚底锚定

组件对三套序列分别给一个「脚底到 Sprite 中心」的像素偏移（`attackFeetOffsetPixels = 100`、`runFeetOffsetPixels = 54`、`dashFeetOffsetPixels = 107`），每帧同时设置：

```csharp
transform.localScale   = new Vector3(scale, scale, 1f);            // 0.75
transform.localPosition = new Vector3(0f, feetOffsetPx / 100f * scale, 0f);
```

效果是无论播哪一帧，**脚底都落在角色 transform 原点**，跑步、挥剑、突刺互相切换时人物不漂移。缩放 0.75 时人物本体约 1.1 世界单位高，与其余五个人设的 0.9 单位占位块量级接近。

> 突刺序列**刻意不做水平锚定**：其素材自带速度线与位移构图，水平居中会削弱冲刺感；且 `transform.localPosition.x` 归零只是让 Sprite 居中于新位置，位移已由技能逻辑一次性完成（见第八节）。

### 4.3 修复的既有缺陷

| 问题 | 原实现 | 处理 |
|---|---|---|
| 帧加载永远为空 | `Resources.LoadAll<Sprite>("Swordsman/Run_")` —— 该 API 只接受**文件夹**路径，不做前缀匹配，因此返回空数组，动画根本不播 | 改为 `LoadAll<Sprite>("Swordsman")` 取整包，再按 `Run_` / `Attack_` / `Dash_` 前缀分组并按文件名排序 |
| 剑士被染成蓝色 | `BuildVisual()` 对所有人设统一 `renderer.color = GetPersonaColor(...)` | 剑士分支改为 `Color.white`，保留水墨原色 |
| 剑士套着占位方块 | 先赋 4×4 白色占位 sprite，再挂动画组件 | 剑士分支不赋占位 sprite，尺寸交由动画组件接管 |
| 跨动作切换跳动 | 三套序列画布基准不同，按中心摆放 | 脚底锚定（见 4.2） |
| 突刺沿用挥剑参数 | dash 骨架里 `DashSequence()` 直接复用 `attackFramesPerSecond`（14 fps）与 `attackFeetOffsetPixels`（100 px），突刺会被按挥剑的节奏与脚底基准播放 | 拆出独立的 `dashFramesPerSecond`（16）、`dashFeetOffsetPixels`（107）与 `dashImpact*` 补帧参数 |
| 突刺收招不回移动态 | `DashSequence()` 结束直接 `ApplyCurrentState()`，边跑边突会瞬间切回站立帧 | 抽出 `ResumeLocomotion()`，与挥剑共用，按 `moving` 恢复跑步或待机 |
| 朝向翻转与缩放冲突 | `PlayerMotor` 用负 `localScale.x` 翻转 | 改用 `SpriteRenderer.flipX`，避免覆盖动画组件的缩放 |
| 只能玩家动 | 动画组件自己读 `GameInput` | 改为 `SetMoving(bool)` 由 `PlayerMotor` 驱动，表现层与输入解耦 |

### 4.4 状态机

```
          SetMoving(true)
   Idle ─────────────────► Run
    ▲  ◄─────────────────┘
    │     SetMoving(false)
    │
    │  PlayAttack()                PlayDash()
    ├───────────────► Attack ──播完──┐
    │                                ├──► 按 moving 恢复 Idle / Run
    └───────────────► Dash   ──播完──┘
```

- `Attack` / `Dash` 期间 `Update` 不接管帧，播完由 `ResumeLocomotion()` 按当前 `moving` 恢复跑步或待机。
- 两者共用一把动作锁（`actionRoutine`），互斥播放：挥剑中按突刺会打断挥剑，反之亦然。对外用 `IsActing` / `IsAttacking` / `IsDashing` 区分当前动作。
- 挥剑中重复 `PlayAttack()` 会从头重播（配合 0.7 s 攻击间隔，正常不会触发）；突刺同理。
- 待机帧用挥剑序列的起手帧 `Attack_00`（持刀站立），比跑步第一帧更适合静止。

## 六、可调参数

都在 `SwordsmanSpriteAnimation` 的 `[SerializeField]` 上（`AddComponentMenu`：`钟声/剑士序列帧`）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `runFramesPerSecond` | 12 | 跑步帧率 |
| `attackFramesPerSecond` | 14 | 挥剑帧率 |
| `dashFramesPerSecond` | 16 | 突刺帧率（略快于挥剑） |
| `attackFeetOffsetPixels` | 100 | 挥剑序列脚底到中心距离（像素） |
| `runFeetOffsetPixels` | 54 | 跑步序列脚底到中心距离（像素） |
| `dashFeetOffsetPixels` | 107 | 突刺序列脚底到中心距离（像素） |
| `visualScale` | 0.75 | 整体缩放 |
| `windUpFrameIndex` / `windUpHoldFrames` | 1 / 1 | 挥剑蓄力帧下标与额外停留帧数 |
| `impactFrameIndex` / `impactHoldFrames` | 3 / 1 | 挥剑刀光帧下标与额外停留帧数 |
| `dashImpactFrameIndex` / `dashImpactHoldFrames` | 3 / 1 | 突刺刀光爆发帧下标与额外停留帧数 |

> 由于角色是运行时生成，这些值取自代码默认值，**没有把它挂在 Inspector 上预设**。若后续把角色 prefab 化，可以直接在 Inspector 拖引用与调参；届时也可以把 `Assets/Animations/Swordsman` 下的 `.anim` 挂到 Animator 上替换代码切帧。

## 七、验证方法

1. 进入 Play，开局后剑士应显示为**黑白水墨人物**（不再是蓝色方块），站在六边形站位点上。
2. 按 WASD 移动：播 7 帧跑步循环，左右移动朝向正确翻转。
3. 松开移动键：回到持刀站立帧。
4. 鼠标左键普攻：播 8 帧挥剑（起手 → 举刀停顿 → 横斩 → 刀光停顿 → 收刀 → 回站立）。
5. 按 `1`（本我「突进斩」）：人物沿输入方向瞬移 2 格，随即播 6 采样突刺（蓄势 → 冲刺 → 出刀 → 刀光停顿 → 收招），并结算 3×2 范围伤害。
6. 边跑边按 `1`：突刺播完应直接回到**跑步循环**，而不是闪一下站立帧。
7. 观察跑步、挥剑、突刺互相切换的瞬间：**脚底不应上下跳**。若跑步偏移，微调 `runFeetOffsetPixels`；若突刺偏移，微调 `dashFeetOffsetPixels`（当前 107）。

## 八、已知限制

- **突刺位移与动画不同步**：`ExecuteSwordsmanDash()` 用一次性 `transform.position = start + direction * dashDistance` 完成 2 格位移，紧随其后才 `PlayDash()`。所以视觉上是「先瞬移到落点，再原地播突刺分镜」，而非「边冲边刺」。若要做到位移与动画同步，需要把一次性赋值改成按 `DashSpeedCellsPerSecond` 的协程位移，并让动画时长与位移时长对齐——但剑士「突进斩」目前只配了 `DashCells = 2`，没有配冲刺速度，属既有玩法设计，本次未改。
- 只有玩家挂 `PlayerMotor`，因此**人机侧剑士保持站立帧**，不会播跑步与挥剑。若需要，可在 AI 移动逻辑里同样调用 `SetMoving()`、在 AI 出手时调用 `PlayAttack()` / `PlayDash()`。
- 动画未做死亡/受击的专门表现，阵亡后保持最后一帧。
- 若美术后续补充了真正的「待机」与「受击」序列，按 `Idle_` / `Hit_` 前缀放进同一目录即可，组件已按前缀分组，只需在 `LoadFrames()` 里加一行。
