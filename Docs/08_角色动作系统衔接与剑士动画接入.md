# 08 角色动作系统衔接核查与剑士动画接入

> 本轮目标：核查「玩家输入 → 对应函数」「动画状态切换」「动画 → 伤害判定」三条链是否真正闭合，补齐没有衔接的部分，并说明剑士已有动画的接入方式。
> 只改 `.cs`，未改任何场景 YAML / prefab / UI 物体，未自动生成 Animator Controller（相关接线留给 Inspector 手动拖）。

## 一、结论摘要

| 核查项 | 结论 |
|---|---|
| 输入 → 函数（WASD / 左键 / 1-2-3 / Esc） | **已正确接通**，枚举值与槽位一一对应 |

`SwordsmanSpriteAnimation` 的四态机本身是完整的：`SetMoving()` 驱动 Idle ↔ Run，`PlayAttack()` / `PlayDash()` 进入单次动作，共用 `actionRoutine` 动作锁互斥，播完由 `ResumeLocomotion()` 按 `moving` 回到跑步或待机。脚底锚定、朝向 `flipX`、帧分组加载均正常。**这一段不需要改。**

## 三、本次改动

### 3.1 动画命中帧驱动伤害判定

`SwordsmanSpriteAnimation` 的 `PlayAttack` / `PlayDash` 改为 `bool PlayXxx(System.Action onImpact = null)`：

- 回调在**命中帧**触发一次：挥剑取 `impactFrameIndex`（刀光帧），突刺取 `dashImpactFrameIndex`（刀光爆发帧）。
- 返回 `false` 表示动画未真正播放（未就绪 / 帧缺失），调用方立即自行结算，保证不会「按了没反应」。
- `FireImpact()` 统一在**命中帧、动作播完、动作被打断**三处兜底触发，只触发一次：既不会提前，也不会因为连点或切技能而丢伤害。

`AbilityCaster` 把伤害结算抽成 `ResolveBasicAttackHit()` / `ResolveDashHit()`，作为回调传入；派生数值、目标扫描、特质附加效果、击退都在回调里**重新取一次**（前摇期间增益/目标位置可能变化，这是动作游戏的正确行为）。

| 动作 | 时间轴 | 帧率 | 命中帧索引 | 判定时刻 | 总时长 |
|---|---|---|---|---|---|
| 挥剑 | `0,1,1,2,3,3,4,5` | 14 fps | `i = 4` | ≈ 0.286 s | 0.571 s |
| 突刺 | `0,1,2,3,3,4` | 16 fps | `i = 3` | ≈ 0.188 s | 0.375 s |

与 `AbilityCatalog` 中剑士平 A 的 `WindupSeconds = 0.15 s` 量级一致（刀光帧略晚于前摇，留出视觉出刀时间）。若觉得判定偏晚，把 `impactFrameIndex` / `dashImpactFrameIndex` 调小即可，不必改战斗层。

涉及文件：`Assets/Scripts/Characters/SwordsmanSpriteAnimation.cs`、`Assets/Scripts/Flow/AbilityCaster.cs`。

### 3.2 混装判定修正

`Cast()` 原条件 `instance.Persona == PersonaId.Swordsman` 判断的是**角色人设**，而能力槽支持拆卡混装（玩家可能拿着力士/钟表师的本我卡）。此时 `definition.DashCells` 多为 0，却仍会执行瞬移、播剑士突刺、套 3×2 命中框。已改为判断**实际施放的那条定义**：

```csharp
if (slot == AbilitySlot.Id && activation.Definition != null
    && activation.Definition.Persona == Ring.Characters.PersonaId.Swordsman)
```

### 3.3 闪避 / 跳跃输入接线

`CharacterBaseStats` 里闪避数值本来就齐备（`DodgeDistanceCells = 3` / `DodgeDurationSeconds = 0.25` / `DodgeCooldownSeconds = 3` / `DodgeGrantsInvulnerability = true`）以及 `JumpHeightCells = 2`，但没有任何代码消费。本轮在 `PlayerMotor` 接线：

- `TryDodge(Vector2 axis)`：按资产距离做一次短距冲刺（沿用项目既有的一次性位移风格，与突进斩一致），带冷却、遵守 `clampToArena`，无移动输入时按 `flipX` 朝向。位移数值来自资产，不硬编码。
- `TryJump()`：显式入口 + Console 反馈。项目是 XY 平面俯视 2D，Z 轴位移不改变画面观感，也没有跳跃序列帧，因此**不擅自发明跳跃表现**，避免输入被静默吞掉。
- 三个 `[SerializeField]` 开关（`enableDodge` / `enableJump` / `logActionInputs`）可在 Inspector 关闭或静音；角色运行时生成，取代码默认值即可，无需拖引用。

## 四、剑士动画「如何接入」

### 4.1 现状：已经接入，走的是代码切帧

角色由 `MatchSpawner.CreateInstance()` 在运行时 `new GameObject()` 生成，工程里**没有任何角色 prefab**。因此项目选择不用 Animator 状态机，而是由 `SwordsmanSpriteAnimation` 直接按时间切 `SpriteRenderer.sprite`。完整链路已经接通：

```
MatchSpawner.CreateInstance()
  └─ CharacterInstance.Initialize() → BuildVisual()
       └─ persona == Swordsman → Visual 子物体 AddComponent<SwordsmanSpriteAnimation>()
            └─ Awake → Resources.LoadAll<Sprite>("Swordsman") → 按 Run_/Attack_/Dash_ 分组

GameInput.MoveAxis      → PlayerMotor.Update()      → SetMoving(true/false)   → Idle / Run
GameInput.AttackPressed → AbilityCaster.BasicAttack() → PlayAttack(onImpact)  → Attack → 刀光帧结算
GameInput.SkillPressed(1)→ Cast(Id) → ExecuteSwordsmanDash() → PlayDash(onImpact) → Dash → 冲击帧结算
GameInput.DodgePressed  → PlayerMotor.TryDodge()   → 位移（播跑步/待机帧）
```

`Assets/Animations/Swordsman/` 下的四个 `.anim`（Idle / Run / Attack / Dash）目前是**可预览、可微调的标准资产**：帧序、帧率、补帧与代码时间轴完全一致，但运行时不播放它们。也就是说，如果你只是想「让剑士动起来」，**已经接好了，不需要额外操作**。

### 4.2 若要用标准 Animator 接入这四个 `.anim`（手动步骤）

工程内目前 **没有任何 `.controller` 文件**。这条路需要在 Unity 编辑器里手工完成（不自动生成，符合项目约定）：

1. **做 prefab**（推荐）：把运行时生成的角色结构固化成 prefab——根物体挂 `CharacterInstance` / `PlayerMotor` / `AbilityCaster`，子物体 `Visual` 挂 `SpriteRenderer`。否则仍需在代码里 `AddComponent<Animator>()`，本质上还是代码装配。
2. **创建 Controller**：在 `Assets/Animations/Swordsman/` 右键 → Create → Animator Controller，命名 `Swordsman.controller`。
3. **拖入 4 个 clip**：把 `Swordsman_Idle` / `_Run` / `_Attack` / `_Dash` 拖进 Animator 窗口。`.anim` 的 sprite 绑定 `path` 为空，**`Animator` 必须与 `SpriteRenderer` 在同一个 GameObject（即 `Visual`）上**。
4. **设参数**：`Bool IsMoving`、`Trigger Attack`、`Trigger Dash`（另可加 `Bool IsDead`）。
5. **建 Transition**：
   - `Idle ↔ Run`：条件 `IsMoving = true/false`，`Has Exit Time = false`；
   - `Any State → Attack`：`Attack` Trigger，`Has Exit Time = false`；
   - `Any State → Dash`：`Dash` Trigger，优先级高于 Attack；
   - `Attack / Dash → Idle`：`Has Exit Time = true`，退出后由 `IsMoving` 决定进 Idle 还是 Run。
6. **挂组件**：给 `Visual` 加 `Animator`，把 `Swordsman.controller` 拖进 `Controller` 槽。
7. **改代码驱动**：`PlayerMotor` 改调 `animator.SetBool("IsMoving", moving)`；`AbilityCaster` 改调 `animator.SetTrigger("Attack"/"Dash")`。`SwordsmanSpriteAnimation` 可保留做无 Animator 时的兜底，或整体移除。

**两个必须注意的坑**：

- **脚底锚定会失效**。现在 `ApplyFrame()` 每帧设 `transform.localScale` 与 `localPosition`（`Attack 100px / Run 54px / Dash 107px`）来对齐三套画布基准；改用 Animator 后只切 sprite、不改 transform，切换动作会重现「上下跳约 46 px」的问题（`Docs/07` 第二节）。解决办法：在 png 的导入设置里把三套序列的 **pivot 统一到脚底**（Custom Pivot），或用一个父物体按序列做分层补偿。
- **`flipX` 仍可用**，朝向逻辑不用改；但不要再同时挂 `SwordsmanSpriteAnimation`，否则两者会争抢 `sprite` 与 `localPosition`。

**取舍对比**：

| | 代码切帧（现状） | Animator Controller |
|---|---|---|
| 角色运行时生成、无 prefab | 天然适配 | 必须先在代码里装配 Animator |
| 命中帧驱动判定 | 直接：回调挂在时间轴下标 | 需用 Animation Event 或 `StateMachineBehaviour` 转发 |
| 帧序/补帧调整 | 改 `[SerializeField]` 参数 | 在 Animation 窗口拖关键帧 |
| 脚底对齐 | 组件统一处理 | 需靠 pivot / 父物体单独处理 |
| 状态机可可视化 | 否 | 是 |

对当前「运行时生成角色 + 需要命中帧精确判定」的结构，**继续用代码切帧是更简单、风险更低的选择**；`.anim` 保留作对拍与预览。

### 4.3 后续补动画

若美术补了真正的「待机」「受击」序列，按 `Idle_` / `Hit_` 前缀放进 `Assets/Resources/Swordsman/`，组件已按前缀分组，只需在 `LoadFrames()` 里加一行并补一个状态；走 Animator 则直接加 clip 与 Transition。

## 七、遗留边界（本轮未改，需确认后再动）

- **突刺位移仍是瞬移**：`transform.position` 一次性赋值，视觉上是「先瞬移到落点、再原地播突刺」。改成边冲边刺需要把位移改为按 `DashSpeedCellsPerSecond` 的协程，并让动画时长与位移时长对齐；剑士「突进斩」目前只配了 `DashCells = 2`，没有配冲刺速度，属既有玩法设计（`Docs/07` 第八节）。
- **平 A 判定仍是「射程内最近的单体」**：`AbilityCatalog` 里剑士平 A 定义是 `AbilityShape.Rect`、正前方 `1×2` 矩形且带 `WindupSeconds`，但 `FindNearestTarget()` 是圆形射程内单体、**不判朝向**（背对也能打中）。改成矩形多目标会改变平衡，需策划确认后单独做。
- **闪避无敌帧未实现**：`CharacterInstance.IsInvulnerable` 只读自 `AbilityRuntime.ComputeDerived()`，没有「外部设定无敌」的接口；`DodgeGrantsInvulnerability` 与 `DodgeDurationSeconds` 暂未消费。要补需先给纯 C# 规则核心加接口。
- **跳跃表现未定义**：俯视 2D 下需要先定义「跳起」的视觉语义（缩放 / 投影 / sortingOrder）并补序列帧。
- **人机侧无动画**：只有玩家挂 `PlayerMotor` / `AbilityCaster`，人机剑士保持站立帧；死亡 / 受击没有专门表现。
- **参数未挂 Inspector**：角色运行时生成，所有 `[SerializeField]` 取代码默认值；prefab 化后才能在 Inspector 调。

## 八、普攻不再生成飞行物 / 横版瞄准压平（2026-11-28）

### 现象

任意角色按**鼠标左键（普攻）**，场上会飞出一个白色的东西（游侠是箭矢序列帧，其他人设是 `ProjectileView` 的 1×1 白点），而且它**往斜上方飘**，从不命中。

### 根因（两条，缺一不可）

1. **普攻走了弹道分支**：`AbilityCaster.ResolveBasicAttack()` 开头有
   `Shape==Line/Fan && ProjectileSpeed>0 → SpawnProjectiles(..., BasicAttack)`。
   玩家的人设由 `MatchSpawner.playerPersona` 决定（场景里目前是 `3`=精灵游侠），
   而**形象跟着特质卡走**（`CharacterInstance.VisualPersona` 取最后一张特质的人设）。
   于是「看起来是剑士/斯巴达/力士」的玩家，普攻实际打的是**游侠短弓**——
   所以换什么造型都在射箭，表现成一个「所有角色都在发射东西」的 bug。
2. **瞄准方向带竖直分量**：`GetAimDirection()` 用鼠标投到 `z=0` 世界平面的落点减角色位置。
   横版地面锁定后角色站在地面线（比平面低 3~4 个单位），这个向量天然是斜的，
   弹道与近战矩形/扇形判定都会朝斜上方。§22 的 `lockToGround` 引入后没有回头压平这里。

### 改动

| 位置 | 改动 |
| --- | --- |
| `AbilityCaster.ResolveBasicAttack` | 删掉弹道分支；普攻一律「动画命中帧 + 沿朝向的瞬时判定」 |
| `AbilityCaster.SpawnProjectiles` | 入口处对 `AbilitySlot.BasicAttack` 直接 return（防御性兜底，普攻任何路径都不得生成飞行物） |
| `AbilityCaster.ResolveBasicAttack` | 散弹（`Fan` + `PelletCount>1` + `PelletDamage>0`）伤害合并为 `PelletDamage × PelletCount`，保持 4×2=8，不至于因为去掉 4 条弹道被削成 2 |
| `AbilityCaster.FindBasicAttackTarget` | 形状判定放行 `AbilityShape.Line`，远程人设（短弓 / 飞刃）按直线判定，不再退化成「身边最近的人」 |
| `AbilityCaster.GetAimDirection` | `body.IsGroundLocked` 时按鼠标左右把方向压成 `(±1, 0)`；`SetFacing` 统一走这里 |

技能槽的弹道（斯巴达「狂战」投矛、游侠「破甲重箭」、机械师「高压喷射」、钟表师飞刃）**保持不变**，
只是方向同样被压平，不会再有斜上方飘的弹道。

### 遗留 / 待确认

- **形象人设 ≠ 普攻人设**：`playerPersona=3` 时，玩家夺到别人的特质后形象会换，
  但普攻卡仍是游侠短弓（伤害 3 / 射程 8 格 / 前摇 0.15s）。
  现在没有箭矢视觉了，会出现「剑士造型挥剑却能打到 8 格外的对手」。
  两种收口方案，等策划选：① 普攻卡跟随 `VisualPersona` 一起换；② 玩家形象锁定为 `playerPersona`。
- `ProjectileView` 与 `arrowFrames` 只为技能弹道服务了；若后续技能弹道也改用纯特效/瞬时判定，
  可以整块删掉（`Docs/19` 里的箭矢序列帧仍作为资产保留）。
