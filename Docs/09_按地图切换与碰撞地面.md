# 09 · 按抽中地图切换 + 碰撞地面

> 2026-11-25。本轮目标：**根据抽中的地图切换到不同地图**、**只变地图与对应效果**、**按地图在场景里生成碰撞地面用于放角色**。
> 本文先给结论，再给核查证据、改动清单、Unity 操作步骤与验证记录。
>
> 前置阅读：`Docs/05_战斗画布与地图接口.md`（接口与时序）、`Docs/06_MapKit地图资源与接线.md`（六图身份映射与 Inspector 接线）。本文只记录增量。

## 一、结论（先看这一段）

| 需求 | 结论 | 落地方式 |
|---|---|---|
| 按抽中地图切换不同地图 | **代码链路本来就完整，但场景没接线，所以此前实际没生效** | 完善 `BattleMapPresenter` 健壮性 + 新增一次性 Editor 菜单生成六张地图根节点并自动连线 |
| 仅地图和对应效果变，其他属性不变 | **已保证** | 地图切换只读写地图根节点的 `SetActive` 与 `Enter/Exit`，不触碰角色、数值、输入、钟声、技能、胜负 |
| 按地图在场景中生成碰撞地面 | **可行（作为地图实体 / 碰撞层）** | Editor 菜单一次性生成：每图一个背景 `SpriteRenderer` + 一个地面 `SpriteRenderer` + `BoxCollider2D`；运行时按地图随根节点启停，零 `new GameObject` |
| 让角色「物理站」在碰撞地面上 | **当前架构下不行** | 工程零物理：角色没有 `Rigidbody2D` / `Collider2D`，`PlayerMotor` 直接写 `transform.position`。见第六节给出的完整改法 |

**「如果不行则告诉我要怎么做」的答案**：地图切换与碰撞地面的生成都做得到；唯一做不到的是「角色靠物理站在地面上」——那需要改角色移动系统，与「其他属性都不变」冲突，本轮刻意没动，第六节给出逐步做法。

## 四、切换链路（改后）

```
点「开始游戏」
  → GameUiController.HandleStartClicked → GameFlow.StartMatch()
      ① CurrentMap = Pick(Random.Range(0,6)) 或 fixedMap
      ② Flow.StartMatch() → StateChanged(MainMenu → Loading)
           → GameUiController.ApplyState(Loading)
               battleCanvas.SetActive(true)
               BattleMapPresenter.Show(CurrentMap)
                   其余五张：Exit() + 兜底 SetActive(false)
                   选中那张：Enter() → SetActive(true) + 恢复地面碰撞体 enabled
                   机制组件 / 地面碰撞体作为子节点，随根节点一起启停
               RefreshMapLabels(CurrentMap)
      ③ MapChanged → HandleMapChanged → Show（幂等，直接返回）
  → Loading → Collect → Elimination：每次 ApplyState 都 Show，幂等不重复 Enter
  → 结算：keepBattleCanvasOnResult 默认开，保留当前地图
  → 返回主菜单：battleCanvas 隐藏 + Presenter.Hide()（收起全部）+ 清空标签
```

`Awake()` 里 `ResolveScenesByMapId()` 的顺序校正规则：六个 `MapScene.MapId` 各出现一次且都在 0..5 → 按编号重排运行时数组；只要有空槽、重复或全留默认 `Map01`，就**保持 Inspector 里的下标顺序不动**（避免把用户手工摆好的顺序打乱），只打一条提示。该逻辑只重排运行时数组，不改序列化数据。

**「其他属性都不变」的边界**：`Show()` / `Hide()` 只读写 `MapScene` 根节点的激活状态与 `Enter/Exit` 钩子；`CurrentGroundSurfaceY` 是只读查询。地图切换不写任何角色字段、不触发钟声、不改移速/血量/能力槽、不改输入映射、不改胜负判定。

## 五、碰撞地面：生成了什么、参数怎么定

### 层级（由菜单生成，保存进场景）

```
BattleMaps                       ← 容器，必须保持 Active（否则子节点 Show 也看不见）
  ├─ Z1_雨夜竹林   [MapScene, MapId=Map01, 初始 Inactive]
  │    ├─ BG_背景           [SpriteRenderer, sortingOrder = -20]
  │    └─ Ground_地面25格   [SpriteRenderer, sortingOrder = -10, BoxCollider2D]
  ├─ Z2_蒸汽井盖   [MapScene, MapId=Map02, 初始 Inactive]
  ├─ ... Z6_洞窟   [MapScene, MapId=Map06, 初始 Inactive]
BattleMapPresenter               [BattleMapPresenter, Scenes[0..5] 已连]
GameUiController.Battle Map Presenter ← 已自动连上展示器
```

- 地面命名沿用 MapKit 的 `Ground_地面25格` 约定（`SteamMechanic` 按此名查找子节点）。
- 每个根节点**存成隐藏**；`Show()` 只激活抽中的那张。
- 六个 `Map Id` 由工具强制写入 `Map01..Map06`，不会全是默认值。
- `battleCanvas` 下的 `bg1` 纯色 `Image` 由工具关闭（Overlay 遮挡，见第六节）；它不在 `BattleMaps` 层级内，属于必要的配套改动。

### 几何参数（工具内常量，可改）

| 参数 | 值 | 依据 |
|---|---|---|
| 地面顶面 Y | `-3.5` | 相机可见 `y ∈ [-5,5]`；最下方角色脚底 `y=-3.5`（六边形站位半径 3.5） |
| 地面宽度 | `18` | 覆盖 16:9 下 ≈17.8 的可见宽度 |
| 地面厚度 | `1` | 视觉与碰撞厚度 |
| 地面中心 Y | `-4.0` | `顶面 -3.5 − 厚度/2` |
| 背景尺寸 | `18 × 10` | `2 × orthographicSize = 10`，铺满相机 |
| `BoxCollider2D` | `size = sprite.bounds.size`、`offset = 0`、`isTrigger = false` | 配合 `localScale` 缩放后，世界尺寸正好 `18 × 1` |
| `GroundSurfaceY` | `center.y + size.y/2 × lossyScale.y = -3.5` | 由 `MapScene.GroundSurfaceY` 手算，不依赖非激活碰撞体的 `bounds` |

贴图来源：优先 `MapKit/Maps/0X/Ground/*.png`；`04_ElfForest` 没有 `Ground` 目录，退化到 `Backgrounds` 里名字含 `base` 的图。`02_Steam` 会跳过名字含 `warn` 的预警贴图。

> `MapScene.GroundSurfaceY` 是**只读查询**，供后续「把角色放到地面上」的消费方使用；本轮没有任何代码去移动角色。

## 六、你要在 Unity 里做的

### 做法 A：菜单一键生成（推荐）

1. 打开 `Assets/Scenes/SampleScene.unity`，确认 Console 无编译错误。
2. 菜单 **「钟声 / 地图 / 生成六张地图与碰撞地面」**。
   - 首次执行：创建六个根节点 + 背景 + 碰撞地面 + `BattleMapPresenter`，并把 `Scenes[0..5]`、`GameUiController.Battle Map Presenter` 全部连好，随后自动保存场景。
   - 再次执行（容器已存在）：弹窗二选一 ——「重新生成」会删旧建新（**会丢失你在这些物体上的手工调整**）；「只补连线」保留现有物体，仅重连引用并纠正非法 `Map Id`。
3. 菜单 **「钟声 / 地图 / 校验地图接线」**：Console 会逐张打印 `MapId` 是否匹配、地面顶面 Y、根节点是否存成隐藏，以及 `GameUiController` 是否连上展示器。理想结果 `6/6 张地图接线完整`。
4. Play → 点「开始游戏」。用 `GameFlow` 的 `Randomize Map` 关掉 + `Fixed Map` 逐张验证六图切换；Console 会打印 `[地图] 展示 Z? ... 地面顶面 Y=-3.50`。
5. 想撤销生成：菜单 **「钟声 / 地图 / 移除生成的地图与展示器」**（也可 `Ctrl+Z`）。

> **遮挡问题（工具已自动处理，但你要知道）**：`battleCanvas` 下的 `bg1` 是 **Screen Space Overlay、不透明、无贴图的纯色 Image**（`Color.a=1`），Overlay Canvas 永远绘制在世界空间 `SpriteRenderer` 之上，不处理会把地图背景整块盖住 —— 表现为「点完菜单，Play 后什么都没变」。生成工具会按与 `GameUiController.hideEmptyBackdrops` 相同的判定（无 sprite + 不透明）把 `bg1` 的 `Image.enabled` 关掉，并用 `Undo` 记录，你随时能在 Inspector 里勾回来或 `Ctrl+Z`。「校验地图接线」也会检查这一项。
>
> 如果你选择**不点菜单**（做法 B），请手动把 `bg1` 的 `Image` 组件取消勾选，或把它的 `Color.a` 设为 0；否则看不到地图。

### 做法 B：纯手工（不点菜单，完全自己拖）

1. 场景里建一个空物体 `BattleMaps`（**保持 Active**），其下建六个根节点，命名 `Z1_雨夜竹林` … `Z6_洞窟`，各自**取消勾选激活**。
2. 每个根节点挂 `MapScene`，`Map Id` 依次设 `Map01..Map06`。
3. 每个根节点下建两个子物体：
   - `BG_背景`：加 `SpriteRenderer`，指定该图 `Backgrounds` 里的图，`Sorting Order = -20`，缩放到约 `18 × 10`。
   - `Ground_地面25格`：加 `SpriteRenderer`（该图 `Ground` 里的图，`Sorting Order = -10`）与 `BoxCollider2D`（取消 `Is Trigger`），放在 `y = -4.0`，让碰撞体顶面落在 `y = -3.5`。
4. 在 `MapScene` 上把 `Ground_地面25格` 拖进 **Ground Root**（Ground Collider 会自动补上，也可手拖）。
5. 新建空物体挂 `BattleMapPresenter`，把六个根节点按 `Map01..Map06` 顺序拖进 `Scenes[0..5]`。
6. 把展示器拖进 `GameUiController` 的 **Battle Map Presenter** 槽位（不拖也会自动查找）。
7. 按 `Docs/06` 第六节接 `XXXMechanic` 机制组件与两个可选 HUD 标签。

### 做法 C：让角色**物理**站在地面上（本轮没做，需要你确认）

当前生成的是一个「带碰撞体的地图实体」，角色不会掉、也不会被它托住 —— 因为角色没有刚体。若目的是「角色站在地面上」，需要按以下步骤改角色系统（**这会改变移动与属性，超出了「其他属性都不变」的范围，故本轮未做**）：

1. 给六个角色都加 `Rigidbody2D` + `BoxCollider2D`（不只玩家）。生成点在 `MatchSpawner.CreateInstance()`；碰撞体按 `map_config.json` 的 `actorWidth=1, actorHeight=2` 设 `size=(1,2)`、`offset=(0,1)`，让脚底对齐 transform 原点。
2. 决定重力：俯视 2D 通常 `Gravity Scale = 0`，此时碰撞地面只提供边界，角色仍由 `PlayerMotor` 驱动；若要用重力下落，设 `Gravity Scale > 0` 并让地面 `BoxCollider2D` 承重。
3. 改 `PlayerMotor.Update()`：把 `transform.position = next` 换成 `Rigidbody2D.MovePosition(next)`（保持现有移速与闪避逻辑不变）。
4. 若启用重力，`clampToArena` 的圆形限制（半径 6.5）会把角色拉回圆内，需改成矩形边界或关掉，否则与地面碰撞打架。
5. 用 `BattleMapPresenter.CurrentGroundSurfaceY` 获取当前地图地面顶面 Y，作为出生 / 复活的落点；`MatchSpawner` 目前是六边形固定站位，需要时按该值重算 `y`。

**更轻量的替代**（不引入刚体，推荐先试）：保留现有 `PlayerMotor` 纯坐标移动，只在写入 `transform.position` 前把 `y` 下限钳到 `CurrentGroundSurfaceY`：

```csharp
// PlayerMotor.Update()，transform.position = next 之前
float floor = GameFlow.Instance != null
    ? /* 从 BattleMapPresenter 取 */ CurrentGroundSurfaceY
    : -3.5f;
if (next.y < floor) next.y = floor;
transform.position = next;
```

这样「放角色」有明确落点且完全不引入物理，但仍属于修改 `PlayerMotor`（角色移动系统），本轮为避免动「其他属性」没有写入。需要的话我可以直接加上。

## 八、边界与降级

- 六张地图根节点初始为空 / `Scenes[i]` 未连：`Show()` 每张图只打一条警告，不阻断开局；`Awake()` 仍会收起已接的地图。
- 六个 `Map Id` 未构成 0..5 唯一排列：保持 Inspector 下标顺序，不重排，不报错。
- `Ground Root` / `Ground Collider` 留空：`HasGround` 为 false，`GroundSurfaceY` 返回 0，地图显隐与机制照常运行。
- 机制效果（落雷、蒸汽、竞技场加成、藤蔓、钟声加速、落石）仍是 MapKit 的纯视觉演示，**未接入 `CharacterInstance` 与胜负判定**；本次也未把地面碰撞体接到任何伤害 / 命中逻辑。
- 没有转场动画、没有按地图切 BGM / 相机边界，没有把地图做成独立 Scene。
- 未改 `SampleScene.unity` 的 YAML（场景物体由你在 Unity 里点菜单生成并保存），未改 MapKit / Screenshots 任何资源。
