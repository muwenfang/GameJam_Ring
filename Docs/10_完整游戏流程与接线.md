# 10 · 完整游戏流程（六区域 / 三场 1v1 / 钟声 / 重开）

> 本轮（2026-11-25）按需求把「从开局到结算」的链路补齐：**六区域抽三场、开局随机分配位置、死亡必定位置钟声、B8 满血重分配与重匹配、B9 淘汰制、B14 胜利条件、返回后 initializeGame、相机跟随与 HUD 常显**。
>
> 协作约定保持不变：**uGUI 层级、Panel、按钮、地图根节点仍由用户在 Unity 编辑器手工搭建并拖入 Inspector**；本轮没有新增任何自动创建 UI 控件、自动挂载组件到 Canvas 的代码。新增的 `CameraFollow` 是相机逻辑组件，不是 UI。
>
> 本文是**代码说明**，按约定使用 Markdown；一般说明文档才生成 docx。

## 二、状态机

宏观状态仍是 `MatchFlow` 的六个状态，没有新增枚举值（UI 与既有离线测试不受影响）：

```
MainMenu ──StartMatch()──> Loading ──NotifyParticipantsSpawned()──> Collect
                                                                     │
                                     B9 有人集齐 ──NotifyEliminationStarted()
                                                                     ▼
                                                               Elimination
                                              ┌──────────────────────┴──────────┐
                                  只剩玩家且集齐(B14)              玩家阵亡 / 只剩人机
                                              ▼                                 ▼
                                          Victory                          Defeat
                                              └──── ReturnToMenu()/StartMatch() ────> MainMenu / Loading
```

**死亡分支是新流程的关键**，两个阶段不再走同一条路：

| 阶段 | 死亡处理 | 在场人数 |
|---|---|---|
| `Collect`（无人集齐 = 普通阶段） | B3 位置钟声 → 消费 `Swaps` 重匹配 → B8 满血复活 + 重新分配区域 → 仍是 3 场 1v1 | **不变**（6 人） |
| `Elimination`（淘汰制） | B3 位置钟声 → `StoreEliminatedCards` 卡牌入组件池 + `IsInPlay = false` → 判胜负 | 递减，直到 1 人 |

> `MatchFlow.NotifyPlayerDefeated` 在纯状态机层仍允许 `Collect` 结算（保持既有离线回归），但 **Unity 壳在收集阶段不会调用它**，而是走 B8 复活。分层口径：核心提供能力，壳决定何时使用。

## 三、一局的完整时序

1. 点「开始游戏」→ `GameUiController.HandleStartClicked` → `GameFlow.StartMatch()`。
2. `StartMatch()` 先判 `CanStartMatch()`，再 `InitializeGame()` 幂等清场（**重开必然初始化**）。
3. 抽本轮 3 个区域（`PickDistinct`），记入 `initialMaps`；`displayedMap` 预置为第 1 个，供 `Loading` 阶段 UI 读取。
4. `Flow.StartMatch()` → `Loading`；`MatchSpawner.SpawnMatch()` 生成 6 个 `CharacterInstance`、注册进 `BellSystem`、`DealInitialCards()` 发特质与技能。
5. `GameFlow` 订阅每个实例的 `Died`。
6. `RebuildArenas(null, -1, initialMaps)`：洗牌 6 人 → 3 场 1v1 → `MatchSpawner.ApplyPlan()` 把每场双方摆到区域中心左右，并把玩家所在擂台中心交给 `PlayerMotor`。
7. `Flow.NotifyParticipantsSpawned()` → `Collect`；UI 显示 `battleCanvas` / HUD，展示器 `Show(CurrentMap)`（玩家所在区域）。相机绑到玩家。
8. 钟声按 B4 每 30 秒随机敲一次；特质 / 技能钟声只同步五个能力槽，位置钟声额外重建三场配对。
9. 有人集齐 → B9 → `Elimination`；此后死亡不再复活，逐人淘汰，奇数人由 B12 复制体补齐对决。
10. 只剩 1 人 → `EvaluateOutcome()` → `Victory` / `Defeat`；结算面板「返回」或「再来一局」→ `ReturnToMenu()` + `InitializeGame()` → 干净重开。

### 一次「死亡 → 钟声 → 重匹配」的时序（收集阶段）

```
CharacterInstance.Kill()/TakeDamage()
  → Died → GameFlow.HandleCharacterDied
      ├─ pendingDeathVictim = 该角色
      └─ BellSystem.NotifyDeath(id)
          → BellRuntime.Ring(Position, Death)
              → PositionBellEffect 产出 Swaps（3 组两两配对）
              → BellRung → GameFlow.HandleBellRung
                  ├─ RebuildArenas(Swaps, relocateId)  ← 消费 Swaps，重抽场地
                  ├─ spawner.RefreshLoadouts()
                  ├─ victim.Revive()                    ← 满血、清冷却与增益
                  └─ EvaluateOutcome()
```

## 四、六区域与三场 1v1 的数据模型

新增 `Assets/Scripts/Maps/ArenaPlan.cs`（**纯 C#，零 UnityEngine，已纳入离线回归**）：

| 类型 | 职责 |
|---|---|
| `ArenaDuel` | 一场 1v1：`Map`（区域）、`FirstId` / `SecondId`、`AgainstClone`（B12 复制体对决）；提供 `OpponentOf(id)` |
| `ArenaPlan` | 一轮只读快照：`ActiveMaps`（抽中的区域）、`Duels`；提供 `MapOf` / `OpponentOf` / `DuelOf` / `CoversExactly` / `Describe` |
| `ArenaPlanGenerator` | `Create(orderedIds, fixedMaps, maxBattles, random, allowClone)`；`ShuffleIds`；`PickDistinct` 由 `BattleMaps` 提供 |

设计要点：

- **唯一权威**：`CurrentPlan` 只在「开局 / 位置钟声 / B8 死亡重分配」三个时机由 `GameFlow.RebuildArenas` 重建；不存在第二处改写「角色 ↔ 区域 ↔ 对手」的代码。
- **钟声系统不碰位置实体**：`BellRuntime` 仍只产出 `BellResult.Swaps` 配对数据，由流程层消费，保持原有分层（核心可离线测）。
- **场地沿用 vs 重抽**：普通位置钟声（30 秒 / 追踪）只换对手，沿用本轮场地；**死亡触发的 B8 位置钟声重抽场地**，让「重新分配到六区域之一」可见。若重抽后仍落在原区域，最多再抽 3 次。
- **场次数自适应**：`battles = min(3, ceil(在场人数/2))`。开局 6 人 = 3 场；淘汰制 5 人 = 2 场正常 1v1 + 1 场复制体对决（B12）。
- **落位**：`MatchSpawner.GetRegionCenter` 优先读 Inspector 拖入的 6 个区域落点；未配置时按 2 行 3 列计算中心（`arenaSpacing` 默认 14），每场双方偏移 `duelOffset`（默认 2.2）。`PlayerMotor.SetArenaCenter` 让圆形边界跟着玩家所在擂台，避免被 `clampToArena` 拉回原点。
- **平A 不跨场**：`AbilityCaster.FindNearestTarget` 现在只命中 `CurrentPlan.OpponentOf(自己)`，即本场对手。

> `BattleMapPresenter.Show()` 仍只激活**玩家所在**的那一张地图根节点；另外两场按架构文档 §5.3「看不到但存在」在逻辑层并行。三个擂台在世界坐标里分开摆放，相机跟随玩家，所以玩家场次始终在视野内。

## 五、钟声触发规则（本轮明确的口径）

| 触发源 | 条件 | 种类 | 重置 30 秒计时 |
|---|---|---|---|
| B3 死亡 | **任何阶段**，出现死亡一定触发 | 必定 `Position` | 是 |
| B4 定时 | `BellPhase.Normal`（无人集齐）且期间未因死亡触发 | 三种随机 | 敲响后归零 |
| B5 追踪 | 击杀后选择追踪 | 必定 `Position` | 是 |
| 手动 / 演示 | 调试键 B、`MatchDirector` 推进 | 随调用方式 | 是 |

**淘汰制定时钟声（Q8）**：按 B4 原文「**无人集齐人设时**」的前提，淘汰制已不满足该条件，因此**淘汰制不再定时敲钟，只由死亡（B3）驱动**；B3、B1/B2 三类重分配、B13 集齐者豁免仍生效，差异集中在 B10/B11/B12 与「死亡不再复活」。这对应需求「淘汰制和之前规则多数一致」。该口径由离线断言 `TestTimerOnlyRunsInNormalPhase` 保护。

## 六、胜负口径（B14）

`GameFlow.requireCompleteSetForVictory` 默认 **true**，注入 `MatchFlow.RequireCompleteSetForVictory`。

| 场上情况 | 结果 |
|---|---|
| 只剩玩家，且 `Player.HasCompleteSet` | `Victory` |
| 只剩玩家，但未集齐 | `Defeat`，原因「B14：活到最后但未集齐完整特质与技能，无法合成完整人设」 |
| 只剩一个人机 | `Defeat` |
| 关掉 Inspector 开关 | 退回旧口径「只剩自己即胜」 |

> **边缘兜底的理由**：场上已无对手、也不再可能通过钟声凑齐卡牌，若只拒绝判胜会把游戏卡在无法结束的死局，因此明确结算为失败。由于 B9 要求「有人集齐」才进淘汰制、B13 让集齐者免疫洗牌，正常流程里玩家若先集齐就能稳定走到胜利。

`MatchDirector` 演示推进随之调整：收集阶段**优先给玩家补缺牌**，让玩家先集齐触发 B9，否则演示会走到「玩家活到最后却没集齐 → 失败」，看不到胜利界面。收集阶段按 B8 死亡只复活，因此调试键 K 要在淘汰赛阶段按才能看到失败界面。

## 七、InitializeGame 与重开

`GameFlow.InitializeGame()` 是**公开、无参、幂等**的方法，可直接绑到按钮 OnClick。清场清单：

| 类别 | 动作 |
|---|---|
| 角色 | 退订 `Died`、`MatchSpawner.DespawnAll()`（销毁角色并逐个从名册注销） |
| 钟声 | `Registry.Clear()` / `Tracking.Clear()` / `Pool.Clear()` / `ResetRound()` / `ResetTimer()` / `TimerEnabled = true` |
| 场地与配对 | `CurrentPlan = null`、`initialMaps.Clear()`、`pendingDeathVictim = null`、随机源重置、`displayedMap` 复位 |
| 时间 | `Time.timeScale = 1f`（避免设置面板暂停状态残留） |
| 状态机 | `MatchFlow.InitializeGame()` 清 `PlayerId` / `ParticipantCount` / `LastRejection`，**不改状态** |
| 事件 | 触发 `GameInitialized`，相机与 HUD 据此丢弃旧目标 / 旧数值 |

调用点：`Start()` 首次进场景、`StartMatch()` 开头、`ReturnToMenu()`、结算面板「返回主菜单」与「再来一局」。

**按钮绑定注意（11-26 补）**：Unity 的 `Button.OnClick` 下拉只会列出**返回 void 的无参方法**——`StartMatch()` / `ReturnToMenu()` 因返回 `bool`，不会出现在 Inspector 列表里（`InitializeGame()` 返回 void，所以能看到）。为此 `GameFlow` 新增两个 void 包装，专供 Inspector 拖绑：

| 按钮 | 绑定方法 | 行为 |
|---|---|---|
| 开始游戏 / 再来一局 | `GameFlow.StartMatchFromUi()` | 调 `StartMatch()`；被状态机拒绝时把 `MatchFlow.LastRejection` 的原因打进 Console |
| 返回主菜单 | `GameFlow.ReturnToMenuFromUi()` | 调 `ReturnToMenu()`；同样输出拒绝原因 |

`InitializeGame()` 本身可直接绑（适合做「局中重置」这类不切状态的场景），但开局 / 返回请优先绑上面两个包装。

**「键位调整」按钮（11-27 补，详见 `Docs/14`）**：`TopCanvas/SettingPanel` 下名为 `Input` 的按钮（文字标签「键位调整」）不在 `MainMenu` Canvas 子树里，原先的按名查找只扫主菜单，因此既没引用也没回调。`GameUiController` 现在按「设置面板子级 → 主菜单 → 全场景」解析 `inputButton`（大小写不敏感），在 `BindMenuButtons()` 里运行时绑定 `HandleInputClicked()`；同时提供 public 的 `OpenKeyBindingsFromUi()` 供 Inspector 手工拖 OnClick。**两种绑定方式二选一**，同时绑会让一次点击把面板切换两次（打开后立刻关闭）。

点击行为：**打开游戏内改键面板**（`Assets/Scripts/UI/KeyBindingPanel.cs`，UI 由代码搭建，第一次点击时挂在 `TopCanvas` 下），再点一次或按 `Esc` 收起。面板里的逐行捕捉、冲突提示、恢复默认都走 `GameInput.TryRebind` / `ResetBindings`，改完即生效并按 `persistToPlayerPrefs` 落盘。详见 `Docs/14`。编辑器窗口 `InputRebindWindow` 改为只负责改**默认键位**。

新增事件：`ArenasChanged(ArenaPlan)`（场地 / 对手重排，HUD 与相机订阅）、`GameInitialized()`、`MapChanged(BattleMapId)`（改为在玩家换区域时触发）。

## 八、相机与 HUD

### 相机（`Flow/CameraFollow.cs`，新增）

挂在 **Main Camera** 上（用户手工挂组件）。`LateUpdate` 用 `SmoothDamp` 跟随目标 XY，**Z 保持相机自身深度不变**；订阅 `GameFlow.StateChanged` / `GameInitialized` / `ArenasChanged`：

- 开局 / 复活 / 状态切换 → 自动绑到 `GameFlow.Player` 并 `Snap()`；
- 位置钟声、B8 重分配玩家瞬移到别的擂台 → `Snap()` 立即对齐，避免相机横穿地图慢慢滑；
- 返回主菜单 / `InitializeGame` → `ClearTarget()`，不跟已销毁的角色。

### HUD

- `GameUiController.ApplyState`：`HUD` 在 `running`（Loading / Collect / Elimination）**全程显示**；新增 `keepHudOnResult`（默认关）可让结算页也保留 HUD。
- 订阅 `ArenasChanged` → 立刻 `battleHud.RefreshNow()`；订阅 `GameInitialized` → 清上一局数值。
- `BattleHud.preferPairedOpponent`（默认开）：右侧「对手」优先显示 `GameFlow.CurrentPlan.OpponentOf(玩家)`，即本场 1v1 对手；关掉则回退到原来的「最近 / 第一个活着 / 固定 id」。

## 十一、本轮没做的 / 已知取舍

- **B12 复制体实体**：钟声系统仍只产出 `BellCloneRequest`，`MatchSpawner` 对落单者只摆本体，复制体的生成与结算留给后续战斗层。
- **三场同时渲染**：`BattleMapPresenter` 仍是「六选一」互斥显隐，只展示玩家所在区域；另外两场在逻辑层并行、角色在世界坐标里分擂台摆放。接入真实地图 / AI 场次时需再决定是三图同屏还是切镜。
- **AI 主动战斗**：`MatchDirector` 仍只是演示推进（补牌 / 处决），人机会被钟声换牌但不会主动走位放技能。
- **技能命中判定**：平A 仍是「射程内最近目标」的简化判定（加了「不跨场」过滤）；**剑客本我突进斩已实现 3×2 矩形投影判定并挂到刀光帧**（`AbilityCaster.ResolveDashHit`，2026-11-26 起同样限定只命中本场对手）。扇形多弹丸 / 折返飞刃 / 弹道飞行 / 地形 / 分段冲刺及其余 28 个技能槽的真实空间判定仍未实现。
- **地图场景层级与机制数值**：MapKit 六区根节点、碰撞地面、机制接入战斗数值仍需手工搭建，见 `Docs/06`。
- **夺取 / 追踪 / 组件池的玩家选择面板**：规则已在 `BellRuntime`，UI 选择面板仍属用户手工搭建范围。
