# 11 · 数值层（M1）资产化与验收对照

本文记录本轮针对「数值层」三个偏差的改造，供开发接线与回归复跑使用。
面向策划 / 验收的结论版见 `output/数值层完善与验收对照说明.docx`。

---

## 一、验收标准出处

《GameDesign/钟声_架构分析_详版.md》：

| 位置 | 验收标准 |
|---|---|
| M1 1.1 人设数值表 | **改表后无需改代码即可生效**；移速/减伤由公式自动算出 |
| M1 1.2 技能定义表 | 每个技能有唯一 ID；可被 M4 按 ID 重分配 |
| M1 1.5 换算公式 | 与文档 6 行数值逐条对齐（**游侠例外需确认 Q1**） |
| 里程碑 1.1 | **改表不改码**；公式与文档逐行对齐（先解决 Q1） |
| M3 3.1 效果执行器 | **新增一个技能 = 组合已有原语 + 配表，不写新框架代码** |
| §6 数据结构 | `SkillDefinition` 带 `effectRefs[]`，**指向 M3 执行器组合** |
| §9 Q1 | 减伤公式不一致，建议统一为 ÷5 并确认游侠值 |

## 二、改造前的三点偏差（含证据）

| # | 偏差 | 证据 |
|---|---|---|
| 1 | 技能是代码常量，改数值需改码 | `Assets/Scripts/Abilities/AbilityCatalog.cs`：`BuildAll()` 里 30 条 `AbilityDefinition` 全部硬编码；`AbilityCard.Definition` → 静态 `AbilityCatalog.Get()`。注释里提到的 `Assets/Data/Abilities/AbilityTuning.asset` **当时并不存在**（无目录、无 `AbilityTuning.cs`、无引用） |
| 2 | `effectRefs → 执行器` 映射不存在 | `AbilityDefinition` 只有扁平字段 + `AbilityShape`；`Docs/04` 第六节那张「13 类原语 → 字段映射」只是文档说明。没有原语 ID、没有 `effectRefs` 字段、没有注册表 |
| 3 | Q1 只做「保留文档值」的取舍 | `CharacterBalance.HasDocumentedException()` 是 `return persona == PersonaId.Ranger`；公式除数 `500f` / `0.03f` 是 const；`CharacterReferenceTable` 与 `CharacterStatBlock.FromDocument` 各自又硬编码一份 `0.125f`。没有记录问题、选项、决议人、后续动作，也没有切换手段 |

## 三、改造后的数据流

```
AbilityCatalog.BuildAll()  ──代码种子（30 条默认）──┐
                                                    ├─→ .check/assetgen（反射序列化）
Assets/Data/Abilities/AbilityTuning.asset            │        ↓
  ├─ Definitions[30]  (每条含 EffectRefs[])         │   Assets/Data/Abilities/AbilityTuning.asset
  └─ Balance          (Q1 决策 + 换算参数)          │
                                                    │
  GameFlow.Awake → AbilityTuningAsset.Apply()  ─────┘
        ├─ AbilityCatalog.SetSource(AbilityDefinitionListSource)
        └─ BalanceDecisionRuntime.Configure(Balance) → CharacterBalance 读 Active
                    ↓
  AbilityCard.Definition / AbilityRuntime / Editor 校验 / HUD  ← 唯一门面
                    ↓
  AbilityDefinition.DescribeEffects() → AbilityExecutorRegistry.Resolve(id)
                    ↓
  IAbilityEffectExecutor → AbilityEffectInstance（战斗层消费）
```

**回退**：资产缺失 / 未拖入 / 条目不完整时，`Apply()` 与 `ApplyFromResourcesOrDefault()`
显式恢复代码种子 + 文档默认 Q1 决策，不会全员 0 数值。

## 五、effectRefs → 执行器 映射

| ID | 原语 | 执行器 | 消费字段（摘要） | 状态 |
|---|---|---|---|---|
| 1 | 直线弹道 | `LineProjectileExecutor` | RangeCells / AreaWidthCells / ProjectileSpeed / Damage | 登记入口 |
| 2 | 扇形多弹丸 | `FanPelletsExecutor` | SpreadDegrees / PelletCount / PelletDamage | 登记入口 |
| 3 | 折返弹丸 | `ReturningProjectileExecutor` | Returns / SecondaryDamage | 登记入口 |
| 4 | 矩形/圆形即时判定 | `InstantAreaExecutor` | AreaLengthCells / AreaWidthCells / RadiusCells | 登记入口 |
| 5 | 突进/冲刺 | `DashExecutor` | DashCells / DashSpeedCellsPerSecond | 登记入口 |
| 6 | 位移/强制拉回 | `ForcedDisplacementExecutor` | RootSeconds / Notes(锚点) | 登记入口 |
| 7 | 击退 | `KnockbackExecutor` | KnockbackCells | 已落地 |
| 8 | 眩晕/定身/减速 | `CrowdControlExecutor` | StunSeconds / RootSeconds / SlowPercent | 已落地 |
| 9 | 增益减益与乘区 | `StatModifierExecutor` | 各 Multiplier / Bonus / Stack* | 已落地 |
| 10 | 治疗与护盾 | `HealShieldExecutor` | HealAmount / HealPerSecond / ShieldAmount | 已落地 |
| 11 | 净化 | `CleanseExecutor` | Notes(清除负面) | 登记入口 |
| 12 | 姿态/状态切换 | `StanceExecutor` | DurationSeconds / Override / CanCancelEarly | 已落地 |
| 13 | 地形与时间流速场 | `TerrainTimeFieldExecutor` | Shape / DurationSeconds / SlowPercent | 登记入口 |

- 30 条能力全部自动推导出 effectRefs（共 **58 条**）；「逆时 / 回溯」的状态快照归入 ⑫ 并在 Note 注明由 M2.5 / `AbilityRuntime` 实现。
- `AbilityExecutorRegistry.Register()` 允许战斗层替换执行器而不改框架代码（M3 3.1）。
- 非法引用（未定义 ID、未注册执行器、重复引用）由 `CollectIssues` 拦截，离线回归有断言。

## 六、Q1 决策结构

```
BalanceDecision
  ├─ DefenseToReductionDivisor / SpeedToCellsPerSecond / Tolerance   ← 可配
  ├─ Policy : FormulaOnly | DocumentExceptions | OverrideOnly
  ├─ Overrides[] : { Persona, DamageReduction, Reason, Source,
  │                  DecidedBy, DecidedOn, FollowUp }
  └─ Q1Status / Q1Question / Q1Options / Q1Decision /
     Q1DecidedBy / Q1DecidedOn / Q1FollowUp / Notes
```

三种策略的实测行为（离线回归覆盖）：

| 策略 | Ranger(75) | Swordsman(70) |
|---|---|---|
| `DocumentExceptions`（默认，含 Ranger 覆盖 0.125） | 12.5% | 14% |
| `FormulaOnly` | 15% | 14% |
| `OverrideOnly`（清空覆盖表） | 0% | 0% |
| `DocumentExceptions` 且除数改 600 + `FormulaOnly` | 12.5% | 14% |

## 七、操作步骤

### 策划改数值（不改代码）

1. Unity 里选中 `Assets/Data/Abilities/AbilityTuning.asset`。
2. 展开 `Data → Definitions`，按 `(Persona, Slot)` 找到技能，直接改字段；
   要换效果组合就改 `EffectRefs` 里的 `EffectId` / `Scope` / `Parameter`。
3. 改 Q1：展开 `Data → Balance`，切 `Policy`、改除数或覆盖表，填 `Q1Status` / `DecidedBy`。
4. `Ctrl+S` 保存；「钟声 / 数值层 / 立即注入当前数值资产」可在编辑器里立刻验证。
5. 「钟声 / 数值层 / 应用 Q1 决策到六个角色资产」把决策同步到六份 `Character_*.asset`。

### 开发接线（一次）

- 把 `AbilityTuning.asset` 拖进场景 `GameFlow` 的「数值层 / Ability Tuning」字段。
- 建议点一次「钟声 / 数值层 / 从代码种子生成技能数值资产」，让 Unity 用原生序列化器重写资产
  （会覆盖手改值，仅需首次做一次）。

### 代码种子变更后重新生成资产

```powershell
& 'C:\Program Files\dotnet\dotnet.exe' run --project '.check\assetgen\assetgen.csproj' -- 'D:\unity\GameJam_Ring'
& 'C:\Users\Muwen\.workbuddy\binaries\python\versions\3.13.12\python.exe' '.check\assetgen\verify_asset.py' 'D:\unity\GameJam_Ring'
```

> 生成器用反射按 C# 字段名输出 YAML，因此新增 `AbilityDefinition` 字段时无需改生成器。

## 九、边界与未做

- **空间判定仍未实现**：13 类执行器中 6 类只做解析与摘要，命中检测 / 弹道 / 地形仍需战斗层；
  实现后用 `Register()` 替换，框架代码不动。
- **Q1 未闭环**：当前是「工程侧取舍 + 待策划确认」，不是「已解决」。策划确认后改资产即可。
- **离线生成的 YAML**：结构已通过 51 项校验，但 Unity 原生反序列化建议在编辑器里点一次生成菜单确认。
- **UI 未自动生成**：按项目约定，Inspector 拖拽由人工完成；本轮只新增 `GameFlow` 的一个序列化字段。
