## 二、素材规格（实测）

目录 `Assets/Resources/Strongman/`，共 **33 张** 8-bit RGBA、背景透明，导入类型已是 Sprite（`spriteMode = 1`、`PPU = 100`、`pivot` 居中），`.meta` GUID 均为有效 32 位十六进制，无需改导入设置。

| 序列 | 文件 | 帧数 | 画布 (px) | 脚底到中心 (px) | 人物实际高度中位数 (px) | 设计稿 |
|---|---|---|---|---|---|---|
| 跑动 | `Run_00` ~ `Run_06` | 7 | 219 × 250 | **109** | 190 | 力士跑动动作帧动画表 |
| 崩进冲撞 | `Dash_00` ~ `Dash_05` | 6 | 256 × 240 | **88** | 153 | 力士冲撞动作帧动画表 |
| 连环拳 | `Punch_00` ~ `Punch_11` | 12 | 362 × 362 | **153** | 249 | 力士连环拳动画稿 |
| 跳跃 | `Jump_00` ~ `Jump_07` | 8 | 192 × 200 | **82** | 181 | （无独立设计稿） |

**脚底到中心**由 alpha 包围盒实测：取每帧 `alpha > 32` 的最底行 `y_bottom`，则 `offset = y_bottom - height / 2`。该公式已用剑士既有参数反验通过（Run 54 / Attack 100 / Dash 107 与 `SwordsmanSpriteAnimation` 的默认值吻合）。

关键问题：**四套画布基准不一致**。若统一按 Sprite 中心摆放，脚底最大差 `153 - 82 = 71 px`，在 `scale = 0.72`、`PPU = 100` 下约 **0.51 世界单位**——从跳跃切到出拳时人物会明显上下跳。连环拳画布 362×362 的人物固有偏大约 30%，属素材差异，不是锚定误差。

## 三、动画资产

目录：`Assets/Animations/Strongman/`（新增 `.meta` 目录项）。格式与 `Assets/Animations/Swordsman/*.anim` 同构：单条 `m_Sprite` PPtr 曲线 + `pptrCurveMapping`，`path` 为空（作用于挂载物体自身的 `SpriteRenderer`），`m_Events: []`。

| 剪辑 | 帧序 | 帧率 | 时长 (`m_StopTime`) | 循环 | 命中帧 |
|---|---|---|---|---|---|
| `Strongman_Idle.anim` | `Run_00` 单帧 | 10 fps | 0.1000000 s | 是 | — |
| `Strongman_Run.anim` | `Run_00` → `Run_06` | 10 fps | 0.7000000 s | 是 | — |
| `Strongman_Punch.anim` | `Punch_00` → `Punch_11` | 14 fps | 0.8571429 s | 否 | `Punch_04`（t = 0.2857 s） |
| `Strongman_Dash.anim` | `Dash_00` → `Dash_05` | 14 fps | 0.4285714 s | 否 | `Dash_05`（t = 0.3571 s，冲击爆发帧） |
| `Strongman_Jump.anim` | `Jump_00` → `Jump_07` | 18 fps | 0.4444444 s | 否 | — |

- **跳跃时长**：8 帧 / 18 fps = 0.444 s，与 `CombatBody.jumpDurationSeconds = 0.45f` 贴合，一套分镜正好覆盖整段滞空。
- **未做补帧**：与剑士不同，本轮剪辑逐帧直放，与组件时间轴严格一一对应。若要在 Animation 窗口里给某个姿势补停留，需同步修改组件的时间轴参数，否则「对拍」会失效。
- **命中帧未写成 Animation Event**：`.anim` 保持与剑士同构（纯 Sprite 曲线）。运行时伤害由代码回调在命中帧结算，不由剪辑驱动；改为 Animator 方案时需另加 Event（见第七节）。

> 与剑士一致，这些 `.anim` 是**可预览、可微调的标准资产**：在 Unity 里可直接拖进 Animation 窗口检查帧序，或拖到带 `SpriteRenderer` 的物体上让 Unity 自动生成 Animator。**运行时实际播放仍走代码切帧**。

生成脚本：`.tools/strongman_anim/gen_anims.py`（从 `.png.meta` 直接读真实 GUID，确定性生成、回读校验、默认不覆盖已有剪辑）。重生成：`python .tools/strongman_anim/gen_anims.py --force`。

## 四、运行时组件改动

文件 `Assets/Scripts/Characters/StrongmanSpriteAnimation.cs`。**全部 public API 签名与既有序列化字段名保持不变**（`SetMoving` / `PlayDash(Action)` / `PlayPunch(Action)` / `PlayJump()` / `Renderer`、`targetRenderer` / `runFps` / `actionFps`），因此 `AbilityCaster` / `CharacterInstance` 的接线零改动、Inspector 上已拖的引用不丢；本轮仅**追加**字段与方法，并在 `PlayerMotor` 补一处显式绑定（见第十节）。

| 项 | 改写前 | 改写后 |
|---|---|---|
| 脚底锚定 | 无；四套画布共用中心锚点 | 每套独立偏移（109 / 88 / 153 / 82），`ApplyFrame` 按 `offset / PPU × scale` 设 `localPosition.y`，脚底恒在 transform 原点 |
| 显示尺寸 | 固定 `0.72` | 统一缩放 + 每套独立倍率（默认全 1），Inspector 可微调 Punch 偏大问题 |
| 跑动计时 | `Time.time * runFps` 取模 | `Time.deltaTime` 累加，`SetMoving` 切换时重置索引，不受绝对时间/时间缩放影响 |
| 命中回调 | 打断时 `StopCoroutine` 直接丢弃 **→ 连点攻击会丢伤害** | `FireImpact()` 在命中帧 / 动作播完 / 动作被打断三处兜底且只触发一次 |
| 命中帧 | 硬编码（Punch=4、Dash=末帧、Jump=`int.MaxValue`） | Inspector 参数 `punchImpactFrameIndex = 4`、`dashImpactFrameIndex = -1`（末帧语义） |
| **跳跃绑定** | `PlayJump()` 存在但**无任何调用者**，只靠组件内部轮询 `IsAirborne` 隐式触发 | **`PlayerMotor` 在 `RequestJump()` 成功后显式调用 `PlayJump()`**；轮询降级为幂等兜底，覆盖 AI / 技能起跳（详见第十节） |
| 状态恢复 | 动作结束直接交回 `Update` | `ResumeLocomotion()` 先套当前状态帧，避免闪一帧 |
| 状态属性 | 仅 `Renderer` | 增加 `IsActing` / `IsDashing` / `IsPunching` / `IsJumping` / `IsMoving` / `ClipsBound` / `JumpClip` / `DescribeClipBindings()` / `RefreshVisual()` |
| **资产绑定** | 无；五个 `.anim` 是孤立资产 | 新增 `idleClip` / `runClip` / `punchClip` / `dashClip` / `jumpClip` 五个 `AnimationClip` 字段 + `[ContextMenu("校验 AnimationClip 绑定")]` |
| 容错 | 无 | `ready` 标志、Sprites 空包警告、逐套缺帧警告；帧缺失时 `PlayXxx` 返回 `false`，调用方立即结算伤害 |

**层级**：`CharacterInstance`(根，同时挂 `CombatBody` / `PlayerMotor` / `AbilityCaster`) → `JumpOffset` → `Visual`(挂 `SpriteRenderer` + 本组件)。兜底轮询用 `GetComponentInParent<Ring.Flow.CombatBody>()` 向上取。人体高度仍由 `CombatBody.LateUpdate` 驱动 `JumpOffset` 子物体，组件只切姿态帧，不叠加任何 Y 位移。

## 五、输入 → 函数 → 动画 的当前链路

| 输入 | 函数链 | 动画 |
|---|---|---|
| WASD | `PlayerMotor.Update` → `CombatBody.SetMoveInput` + `SetAnimationsMoving` | `SetMoving` → 7 帧跑动循环 / 站立帧 |
| 左键 | `AbilityCaster.BasicAttack()` → `PlayPunch(resolve)` | 12 帧连环拳，伤害在 `Punch_04` 结算 |
| 键 1（本我·崩进冲撞） | `AbilityCaster.ExecuteDash()` → `CombatBody.MoveInstant` + `PlayDash(resolve)` | 6 帧冲撞，伤害在 `Dash_05` 结算 |
| 空格 | `PlayerMotor` → `CombatBody.RequestJump()`（返回 true）→ **`StrongmanAnimation.PlayJump()` 显式绑定** | 8 帧跳跃分镜（0.444s）；组件对 `IsAirborne` 的轮询仅作幂等兜底 |
| 右键 | `CombatBody.RequestDodge()` | **无专用序列帧**，本轮未改表现 |
| Esc / 键 2 / 键 3 | 暂停 / 自我·沉腰调息 / 超我·虚手锚定 | 无动作表现 |

`CharacterInstance.BuildVisual()` 在 `persona == Strongman` 分支自动 `AddComponent<StrongmanSpriteAnimation>()`，玩家与 AI 力士实例都会挂上。剑士（`PersonaId.Swordsman`）**没有 `Jump_*.png` 序列帧**，因此空格起跳时剑士保持跑动/站立帧，不套用跳跃分镜；`PlayerMotor` 只对力士调用 `PlayJump()`。

## 七、三种「绑定」的区别与 Animator 迁移步骤

先分清「绑定」的三层含义，本轮修复的是第一层：

| 层次 | 含义 | 当前状态 |
|---|---|---|
| **运行时绑定** | 输入/技能 → 显式调用动画函数，Play 时真的播出来 | **本轮已修复**：`PlayerMotor` 调 `PlayJump()`，其余四个动作本来就有显式调用点 |
| **资产绑定（Inspector）** | `.anim` 被某个序列化字段引用，Unity 里能看到引用关系 | **本轮已提供入口**：组件新增 `Idle/Run/Punch/Dash/Jump Clip` 五个 `AnimationClip` 字段，拖入即绑定；右键「校验 AnimationClip 绑定」会逐个核对 `帧数 = length × frameRate` 是否与 `Resources` 帧数一致（Idle 1 / Run 7 / Punch 12 / Dash 6 / Jump 8）。**字段不参与运行时播放**，切帧仍读 `Resources/Strongman` |
| **Animator 状态机绑定** | `.controller` + `Animator` 组件驱动 `m_Sprite` | 工程**没有** controller，也没改任何场景 / prefab；属另一条路线，需按下方步骤手工完成 |

> 注意：角色由 `MatchSpawner` **运行时生成**，`AddComponent` 出来的组件在退出 Play 后不存在，因此组件字段上的拖线不会自动持久化。若要把「资产绑定」固化到工程里，需先按下方步骤 1 做角色 prefab，再在 prefab 的 `Visual` 子物体上拖入五个 `.anim`。这一层 UI 操作按约定留给你。

若要把这 5 个剪辑改成 Animator 状态机播放，需在 Unity 里手工完成：

1. 把运行生成的角色固化成 prefab（当前 `MatchSpawner` 是 `new GameObject()` 装配）。
2. 新建 `Strongman.controller`，拖入 5 个 clip：`Idle` 为默认状态，`Run` 勾 Loop Time。
3. 建参数：`Bool IsMoving`；`Trigger Punch` / `Trigger Dash` / `Trigger Jump`。
4. 建 Transition：`Idle ↔ Run`（`IsMoving`）、`Any State → Punch / Dash / Jump`（对应 Trigger，播完回 `Idle`/`Run`）。
5. 把 `Animator` 挂在**与 `SpriteRenderer` 同一个 Visual 物体**上——clip 的 `path` 为空，挂在父级会找不到渲染器。
6. 代码侧把 `SetMoving` / `PlayPunch` / `PlayDash` / `PlayJump` 改为 `SetBool` / `SetTrigger`；命中帧判定改用 **Animation Event** 转发（当前靠代码回调，剪辑里没有 Event）。

**两个坑**：
- 脚底锚定会失效。现有组件每帧按动作设 `localPosition.y`；clip 只切 `m_Sprite`，不带 Transform 曲线。改用 Animator 前必须把 33 张 png 的 pivot 统一到脚底，否则第四节修掉的 0.51 单位跳动会原样复现。
- 命中帧与伤害判定会脱节。除非加 Animation Event，否则伤害仍由代码在 `Punch_04` / `Dash_05` 结算，而 Animator 的播放节奏由状态机决定，两者可能不同步。

以当前「运行时生成 + 需要精确命中帧」的结构，继续代码切帧风险更低。

## 十、跳跃动画绑定修复（2026-11-27 20:35）

### 10.1 问题定性

反馈为「动画绑定有问题，跳跃动画未绑定」。逐层排查结论：

另有独立事实：工程里**没有任何 `.controller`**，`SampleScene.unity` 里也没有 `Animator` 组件。因此五个 `.anim` 在 Unity 的资产依赖图里是孤立资产，Inspector 上看不到「跳跃动画已绑定」的证据。

### 10.2 隐式轮询的四个缺陷

1. **上升沿被吞**：原条件 `airborne && !wasAirborne && action == null`。出拳/冲撞期间 `action != null`，上升沿被跳过，但 `wasAirborne` 仍被置 `true` —— 本轮起跳**永久不播**。
2. **击飞误触发**：`CombatBody.ApplyLaunch()` 也会置 `airborne = true`，受击时错误套用起跳分镜。
3. **依赖执行顺序与序列化默认值**：轮询在 `Update()` 里，时机受 `StrongmanSpriteAnimation` / `PlayerMotor` / `CombatBody` 三者 Update 顺序影响；`autoPlayJumpOnAirborne` 是本轮新增的序列化字段，Unity 未刷新脚本时旧实例可能取到 `false`。
4. **绑定不可见**：没有任何显式调用点，也没有 `AnimationClip` 引用字段，无法在 Inspector 核对。

### 10.3 改动明细

| 文件 | 改动 |
|---|---|
| `Assets/Scripts/Flow/PlayerMotor.cs` | `if (input.JumpPressed && body.RequestJump())` 成功后取 `StrongmanAnimation` 并调 `PlayJump()`，与 `SetAnimationsMoving` 同属输入适配层；剑士无跳跃帧，不处理 |
| `Assets/Scripts/Characters/StrongmanSpriteAnimation.cs` | ① `PlayJump()` **幂等**：`action != null && activeAction == "jump"` 时直接返回 `true`；② `PollJumpState()` 排除 `IsLaunched`、放开 `action == null` 限制、改用 `activeAction != "jump"` 防重；③ 新增五个 `AnimationClip` 字段 + `ClipsBound` / `JumpClip` / `DescribeClipBindings()` + `[ContextMenu("校验 AnimationClip 绑定")]` + `ValidateClipBindings()`；④ 更新过时注释 |

**为何不会重复播放**：显式调用在 `PlayerMotor.Update()` 内立即把 `activeAction` 置为 `"jump"`；下一帧兜底轮询检测到上升沿时 `activeAction == "jump"`，被条件跳过。三个脚本的 Update 无论谁先谁后，结果一致。

**为何打断出拳不会丢伤害**：`Play()` 在 `StopCoroutine` 前先调 `FireImpact()` 补结算，与第二轮修好的「打断不丢伤害」机制复用同一条路径。

### 10.5 若你指的是 Inspector / Animator 里的「未绑定」

- **组件字段绑定**：把 `Assets/Animations/Strongman/Strongman_Jump.anim` 拖到 `Visual` 上 `StrongmanSpriteAnimation` 的 `Jump Clip` 字段即可；五个都拖完 `ClipsBound` 为 `true`。右键「校验 AnimationClip 绑定」会逐项核对帧数。**运行时生成的角色退出 Play 后组件不存在，拖线不会持久化**——要固化请先按第七节步骤 1 做角色 prefab。
