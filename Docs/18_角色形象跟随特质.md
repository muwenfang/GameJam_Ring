## 二、为什么是「最后一张」

`BellParticipant.Traits` 是**有序列表**，一个人可以同时持有多张特质：

- 开局 `BellRuntime.DealInitialCards()`（`Assets/Scripts/Bells/BellRuntime.cs:369`）一人一张；
- B6 `TryStealOneCard`（`Assets/Scripts/Bells/BellRuntime.cs:232-261`）夺走对手一张后自己变 2 张；
- 特质钟声 `TraitBellEffect.Execute`（`Assets/Scripts/Bells/TraitBellEffect.cs:37-113`）把所有人的特质收上来洗牌，再按原持有量重发。

多张时必须挑一张定形象。取**最后获得的那张**，是因为「夺取别人的特质」是最需要即时反馈的行为——若取第一张，抢完牌外观纹丝不动，看起来就像没刷新。代价是特质钟声的洗牌重发会打乱多张持有者的顺序，人设可能跟着变（这本身就是「牌被重新分配」的可见结果）。

## 三、形象构建（`Assets/Scripts/Flow/CharacterInstance.cs`）

构建链：`CharacterInstance` 根 → `JumpOffset`（跳跃纵向偏移）→ `Visual`（唯一 `SpriteRenderer`）→ 序列帧组件挂在 `Visual` 上。

| 位置 | 内容 |
|---|---|
| `CharacterInstance.cs:200` | `public PersonaId TraitPersona`：取 `Participant.Traits[Count-1].Persona`，空列表退剑士 |
| `CharacterInstance.cs:214` | `public PersonaId VisualPersona`：`ResolveVisualPersona(TraitPersona)` |
| `CharacterInstance.cs:223` | `public static PersonaId ResolveVisualPersona(PersonaId)`：**唯一的人设→美术映射表** |
| `CharacterInstance.cs:954` | `BuildVisual()`：人设没变 → `RefreshVisualAnimation` 只刷新当前帧；人设变了 → `ClearVisualExtras` 清旧表现层、复位 sprite/缩放/位置、补写 `flipX`，再挂新组件 |
| `CharacterInstance.cs:1018` | `RefreshVisualAnimation(GameObject, PersonaId)`：按人设 `GetComponent`，没有就 `AddComponent`（`Awake` 自动加载帧），有就 `RefreshVisual()` |
| `CharacterInstance.cs:1090` | `ClearVisualExtras(GameObject)`：销毁 `Visual` 的子物体，再把除 `Transform` / `SpriteRenderer` 外的组件全部 `enabled = false` 后销毁 |
| `CharacterInstance.cs:1120` | `DestroyVisualObject(UnityEngine.Object)`：运行期 `Destroy`（帧末生效）/ 编辑期 `DestroyImmediate` |

要点：

- **不能套占位色块**：序列帧是水墨图，染色会把整张人物图染成人设色，方块缩放也会盖住人物；所以旧分支里的 `GetPlaceholderSprite()` + `GetPersonaColor` 染色已删除，尺寸 / 脚底对齐全交给动画组件。
- **不能同时挂两个动画组件**：两套组件都会写同一个 `SpriteRenderer` 与 `Visual.localPosition`。先禁用再销毁，销毁在帧末生效，期间旧组件已不参与表现。
- **连子物体一起清**：游侠的 `ElfRangerSpriteAnimation` 会在 `Visual` 下自建 `Halo` 子物体（施法光晕），只销毁组件会留下一个漂浮精灵；`ClearVisualExtras` 先销毁 `Visual` 的全部子物体。
- **清理不按组件类型枚举**：销毁组件时只跳过 `Transform` / `SpriteRenderer`，其余一律清掉——以后给新人设加表现组件，这里不用再改一行。
- **重建后要补 `flipX`**：`CombatBody.SetFacing`（`Assets/Scripts/Flow/CombatBody.cs:188-212`）在朝向没翻转时提前 return，重挂渲染器不会自动补朝向，所以 `BuildVisual` 里按 `Body.FacingSign < 0` 写一次。
- **`Destroy` 而非 `DestroyImmediate`**：钟声结算可能在物理 / 触发回调里发生，运行时的 `DestroyImmediate` 会被 Unity 拒绝。
- `GetPersonaColor(PersonaId, bool)` 保留为 `public static`，只服务 HUD（`Assets/Scripts/UI/BattleHud.cs:571`）。

## 四、刷新时机

形象的刷新点全部收敛在 `CharacterInstance.RefreshLoadout()`，因此**不需要**在每处改牌的地方单独补刷新：

| 时机 | 调用链 |
|---|---|
| 开局发牌 | `MatchSpawner.SpawnMatch` → `DealInitialCards()` → `RefreshLoadouts()`（`Assets/Scripts/Flow/MatchSpawner.cs:169`） |
| 每次钟声结算后 | `BellSystem.BellRung` → `GameFlow.HandleBellRung` → `spawner.RefreshLoadouts()`（`Assets/Scripts/Flow/GameFlow.cs:548`） |
| 演示补牌 | `MatchDirector.GiveMissingCard` 改牌后 `RingNowRandom` 敲钟 → 同上 |
| 兜底提升为玩家 | `PromoteToPlayer()` 内部直接 `BuildVisual()` |

`MatchSpawner.RefreshLoadouts()`（`Assets/Scripts/Flow/MatchSpawner.cs:254-263`）逐个人物调 `RefreshLoadout()`；`RefreshLoadout()` 里先同步能力槽与最大生命，最后 `BuildVisual()`（`Assets/Scripts/Flow/CharacterInstance.cs:786`）。
开局「先建角色、再发牌」中间会短暂是剑士造型，但两步在同一帧内完成，不会渲染出中间状态。

## 六、已知取舍 / 边界

1. **玩家提升不再换色**：旧代码靠占位方块「玩家加亮」区分玩家与人机；现在两者同图，只差 `sortingOrder`（玩家 10 / 人机 5）。若需要更强区分，建议在 HUD 或脚下加标记，而不是给水墨图染色。
2. **挥砍中换人设**：钟声恰好落在某角色的攻击 / 突刺序列里时，旧组件被销毁会连带中断该次动作协程，那一下的命中回调可能丢失（动画与结算同生命周期是既有设计）。概率低，未做额外缓冲。
3. **精灵游侠已接入**（2026-11-28，与本次改动同一批）：`Assets/Scripts/Characters/ElfRangerSpriteAnimation.cs` 提供 `Idle/Run/Attack/Heavy/Heal/Halo/Dodge/Jump` 与光晕，`ResolveVisualPersona` 已放行 `PersonaId.Ranger`，`PlayerMotor` 也接了游侠的移动 / 跳跃表现。**仍缺美术的只剩蒸汽机械师和钟表匠**，它们继续借剑士占位。
4. **数值人设没变**：形象与战斗是两条线，`CharacterInstance.Persona`（来自 `CharacterBaseStats`）继续决定血量、普攻与技能卡池。

## 七、Play 模式验证清单

1. 开局：观察每个角色是不是**自己那张特质**对应的造型（剑士 / 斯巴达 / 力士 / 精灵游侠各显示本人设；持蒸汽机械师 / 钟表匠特质的显示持剑水墨人物）。
2. 特质钟声结算后：所有人造型跟着新特质变（持 1 张时必然换；蒸汽机械师 / 钟表匠的特质仍显示剑士）。
3. 抢牌（B6）后：被抢者与夺取者造型各自刷新，夺取者按「最后获得」的那张；**从游侠换成别的人设时，游侠施法光晕（`Halo` 子物体）不能残留在场上**。
4. 打架 / 移动 / 闪避：换过人设后仍能正常出招、位移、朝向翻转（`AbilityCaster` 重新取到新组件）。
5. Console 无 `没有找到 SpriteRenderer` 警告、无 `MissingReferenceException`。
