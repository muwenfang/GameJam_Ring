## 二、素材转换口径

源目录 `桌面/精灵游侠素材` 的文件名是 GBK↔UTF-8 乱码字面量，脚本先做编码还原再归集到 `.tools/elf_ranger/src/`（ASCII 名），全部转换逻辑集中在 `.tools/elf_ranger/build_frames.py`，可重跑。

| 步骤 | 做法 | 为什么 |
|---|---|---|
| 白底转 alpha | 取通道最小值 `m = min(R,G,B)`，`a = clamp((235-m)/20)` | 纯阈值会把弓弦这类浅色细节一起抠掉；软阈值保留半透明过渡 |
| 去白污染 | 反解 `C = (P - (1-a)·255) / a` | 白底稿的抗锯齿边缘是「角色色 + 白」，直接用会在暗色地图上出现白边 |
| 饱和度补偿 | 对近白淡绿区域做饱和度提升 + 乘色 `(0.52,0.86,0.60)` | 治疗/光环的原始光晕是 209/249/216 的淡绿近白，暗底上就是一坨白 |
| 边缘外扩（bleed） | 不透明邻居颜色向透明区扩 6 圈 | 双线性采样会把透明像素的白 RGB 混进边缘 |
| 统一画布 | 角色帧一律 800×800，脚底 `y=799`、水平中心 `x=400`、人物高 583 px | 13 组素材画布尺寸不一（627/800/876/644），统一后脚底与重心天然对齐 |

`PPU` 按用途分组写在 `.meta` 里：角色与光环 **292**（583 px → 2.0 世界单位），荆棘 **292**（876×292 → 3×1 格），箭矢 **500**（644×210 → 1.29×0.42 世界单位）。

## 四、四层技能落地对照

数值层（`AbilityCatalog.BuildRanger()`）上一轮已按规格写好，本轮补的是**表现与两处判定缺口**。

| 层级 | 技能 | 表现 | 判定/时序 |
|---|---|---|---|
| 特质 | 精灵之目（射程 8、风之优雅叠层） | 常驻待机帧 | 纯数值，`AbilityRuntime` 既有效果 |
| 普攻 | 游侠短弓 | `PlayAttack` | 箭在撒放帧（0.30 s）生成弹道；弹道视觉换成 `ElfRanger_Arrow_*` 序列帧 |
| 本我 | 破甲重箭 | `PlayHeavy` | 撒放帧（0.389 s）生成弹道；`StopOnFirst` 命中首个目标结算 8 伤 + 减速 |
| 自我 | 自然恩赐 | `PlayHeal(1.5s)` + 光环叠加层循环 1.5 s | 治疗与减伤仍由 `AbilityActivation` 在施法瞬间结算（未改规则核心），动画只负责表现 |
| 超我 | 缚地荆棘 | `PlayHeavy` + 生成荆棘地形 | 鼠标落点夹在 4 格内 → 3×1 荆棘；`ElfRangerBrambleZone` 逐帧跟踪，目标离开时 `ApplyRoot(0.75s)`；施法者本人免疫 |

**两处判定缺口**（本轮补的）：

1. `AbilityShape.Ground` 之前只登记了 `EffectRefs`，运行时既无地形也无缠绕——超我技能实际是「按下后什么都没发生」。现由 `SpawnBrambleZone` 接管。
2. 弹道类技能原先在 `ExecuteAbility` 里**立即**生成，与动画完全脱钩；现改为在撒放帧回调里生成，箭的飞行起点与画面出箭同帧。

混装（拆卡换牌）时动画按**施法者**选而不是按技能来源人设选：游侠放别人的近战技能会播重箭抬手（`TryPlayCasterAction`），放位移技能会播前闪（`TryPlayCasterDash`），不会出现「血条掉了人不动」。

## 五、组件与脚底锚定

`Assets/Scripts/Characters/ElfRangerSpriteAnimation.cs`

| 项 | 说明 |
|---|---|
| 脚底锚定 | 全部角色帧共用 800×800 画布、脚底 `y=799`、画布中心 `y=400` → 偏移恒为 **399.5 px**。`ApplyFrame` 每帧设 `localPosition.y = 399.5/292 × scale`，脚底恒在 transform 原点 |
| 显示尺寸 | `visualScale = 0.7` → 人物高约 1.40 世界单位（剑士 1.43 / 斯巴达 1.33，同一量级） |
| 命中帧 | `attackImpactFrameIndex = 6`、`heavyImpactFrameIndex = 7`、`healImpactFrameIndex = 4`，与 `.anim` 严格对应 |
| 打断 | `FireImpact()` 在命中帧 / 播完 / 被打断三处兜底且只触发一次 → 连点平A 不丢箭 |
| 光环 | `Halo` 子物体 + 独立 `SpriteRenderer`，`sortingOrder = 角色 + 1`，短暂点亮后自动关闭；组件销毁时一并清理（否则残留渲染器会被下一个动画组件误当作渲染目标） |
| 绑定校验 | 13 个 `AnimationClip` 字段 + `ClipsBound` + `[ContextMenu("校验 AnimationClip 绑定")]`，仅作状态核对，不参与播放 |

## 六、荆棘地形与箭矢视觉

**`ElfRangerBrambleZone`**：`Spawn(center, direction, 3, 1, 2s, ownerId)` → 生成独立世界物体，按朝向旋转（长边对齐瞄准方向），`sortingOrder = 2`（压在地图之上、角色之下）。时序：长出 0.5 s → 保持约 1.2 s → 消散 0.3 s → `Destroy`。

判定：维护「曾在范围内」的 id 集合，每帧比对；离开者 `ApplyRoot(0.75s)`；`ownerId` 直接跳过（规格：游侠自身穿越不受影响）。

**箭矢**：`ProjectileView.ApplyFrames(frames, 30fps, 1.25 世界单位, flipX)`。只对游侠的实例启用，其他人设仍用默认白点，避免影响既有手感。

## 七、若改用标准 Animator（留给用户手工操作）

工程里**没有** `ElfRanger.controller`，也没改任何场景 / prefab。要改成 Animator 状态机播放，需在 Unity 里手工完成：

1. 把角色固化成 prefab（当前角色由 `MatchSpawner` 运行时生成，Play 结束后组件不存在，Inspector 拖线不会持久化）。
2. 建 `ElfRanger.controller`，拖入 13 个 clip（Idle/Run 设 Loop）。
3. 参数：`Bool IsMoving`、`Trigger Attack/Heavy/Heal/Jump/DodgeFwd/DodgeBack`。
4. 建 Transition：`Idle ↔ Run`（IsMoving）；`Any State → Attack`（Trigger，Has Exit Time 关）。
5. Animator 挂在**与 SpriteRenderer 同一个 Visual 物体**上（clip 的 path 为空）。
6. 代码改调 `SetBool/SetTrigger`，并**删掉 `ElfRangerSpriteAnimation`**。

两个必须注意的坑：

- **pivot**：现有帧是 800×800 画布、中心 pivot、靠代码上移 399.5 px 对齐脚底。改用 Animator 后这层补偿消失，必须把 101 张 png 的 pivot 统一改到底部（或用 Sprite Editor 批量设 `Bottom Center`），否则整体会下坠约 1.37 世界单位。
- **命中帧**：伤害改为 Animation Event 转发，事件要加在 `Attack_06` / `Heavy_07` 上，否则又回到「按下即结算」。

两条路线互斥：代码切帧与 Animator 同时写 `SpriteRenderer.sprite` 会互相覆盖。

## 八、Play 验收清单

1. 开局把玩家特质换成游侠（或用 `Character_Ranger` 出战），确认人物是**透明背景的精灵**、无白框白边。
2. 站定 1 秒：待机 6 帧循环，不抖不闪。
3. WASD 移动：跑动 6 帧循环；停下回到待机；脚底不上下跳。
4. 左键平A：先抬手拉弓，约 0.30 s 后箭离弦；箭是**精灵图**不是白点，命中扣血。
5. 连续快速点左键：每次都结算，不因打断而丢箭。
6. 按 1（破甲重箭）：重箭分镜，0.389 s 后出箭，命中首个目标掉 8 血。
7. 按 2（自然恩赐）：治疗分镜 + 绿色光环铺开约 1.5 s，血量上升。
8. 按 3（缚地荆棘）：鼠标落点长出荆棘，敌人走进去再走出来会被定身约 0.75 s；游侠自己穿过不受影响；约 2 s 后荆棘消散销毁。
9. 右键闪避：按方向输入的前后关系播 `DodgeFwd` / `DodgeBack`。
10. 空格跳跃：播 6 帧跳跃分镜，身体高度由 `JumpOffset` 抬升，无双重位移。
11. 换人设（换牌）后形象立即切换，且**不残留绿色光环**。
12. Animation 窗口拖入 `ElfRanger_Attack.anim` 可逐帧预览 10 张姿势。

## 九、遗留边界

- **自我「自然恩赐」的时序**：治疗与减伤仍在施法瞬间结算，动画 0.8 s 只是表现。若要求「播到光晕帧才回血」，需要在规则核心把治疗拆成延迟结算，属于玩法取舍，本轮未动。
- **前摇字段与可见撒放帧不完全一致**：技能表里游侠短弓写 `WindupSeconds = 0.15`、破甲重箭写 `0.2`，但按素材实际帧位，箭在 0.30 s / 0.389 s 才离弦（素材只有 10/12 帧，压到 0.15 s 会让撒放帧落在第 3 帧、画面还没拉开弓）。当前以**可见出箭为准**；若要严格 0.15 s，应缩短动画或加帧。
- **朝上/朝下的表现**：素材只有水平朝向（靠 `flipX` 左右翻转）。俯视 2D 下向正上方射箭时人物仍是水平姿势。
- **荆棘的格对齐**：落点用鼠标世界坐标（夹在 4 格内），未吸附到格中心；宽 1 格的判定是连续矩形而非格离散。
- **AI 侧表现**：`CharacterInstance.BuildVisual` 对人设统一挂组件，AI 游侠也会有动画；但 AI 是否调用技能动画走的是同一条 `AbilityCaster` 路径，未单独做 AI 专项验证。
- **死亡/受击表现**：无对应序列帧，仍沿用既有占位逻辑。
- **旧素材未删**：桌面原始目录与 `.tools/elf_ranger/src` 保留，便于换阈值重跑；`build_frames.py` 可整体重生成。
