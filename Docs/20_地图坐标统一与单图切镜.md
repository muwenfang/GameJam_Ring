# 20 · 地图坐标统一（25×12 格）+ 单图切镜落位

> 2026-11-28。对应 `地图.docx`「地图层」进度表的 **5.1 需要检查项：25×12 格坐标与角色坐标统一；当前是圆形擂台 / 6 锚点布局**，
> 以及「表现」行的 **三场同屏 / 切镜策略**。
>
> 一句话结论：**把地图根节点整体放进 MapKit 的 25×12 设计坐标系**，格子、地面、机制特效、角色落位、输入选点、技能射程从此共用一套换算；三场 1v1 采用**单图切镜**——只把玩家那一场摆进当前展示的地图，其余两场停到场外。

---

## 一、问题定位（三条互相独立的错位）

| 现象 | 根因 |
|---|---|
| 机制特效（藤蔓、雷击、井盖）位置不对 | MapKit 脚本按「左下角原点、25×12、地面在 y=1」摆特效，而地图根节点在原点、缩放 1；上一版只缩放 `BG_背景` 与 `Ground_地面25格`，**根节点没进设计坐标系** |
| 地图跟着相机跑出屏幕 | `CameraFollow` 自由跟随玩家，`MapScreenFitter` 只在 `OnEnable` 算一次几何；相机一移动，背景就离开对齐位置 |
| 角色站在半空 / 跑到地图外 | `MatchSpawner` 把三场 1v1 按 `arenaSpacing=14` 摆成 3 列（x ≈ -14 / 0 / +14），而屏幕上只展示一张居中地图；玩家场次的落点常年在地图之外 |

三条的共同点是：**「世界坐标」有四个各自为政的来源**——地图背景、MapKit 机制、角色落位、输入格。本轮把它们收敛到 `MapStage` 一个快照上。

## 二、坐标口径（唯一换算）

设相机正交 `orthographicSize = 5`（视口高 10）、背景 sprite 原始尺寸 25×12、设计 25 列 × 12 行、地面占最底 1 行：

```
s            = max(视口高 / 12, 视口宽 / 25)          // cover，等比、不变形
地图根节点    localScale = s
              位置      = 背景左下角（世界）
BG_背景       localScale = (25 / spriteW, 12 / spriteH)  → 原始 25×12 的图即 (1,1)
              localPos   = (12.5, 6)
Ground        localScale = 1，localPos = (12.5, 0.5)，BoxCollider2D.size = (25, 1)
格            CellSize = 20.833 / 25 = 0.8333；原点 = 背景左下角；25 列 × 12 行
地面顶面      根节点底边 + 10 × (1/12) = -4.167
角色可活动圆  圆心 (0, 0.417)，半径 4.583 → 最低点 = 地面上沿，最高点 = 背景顶边
```

独立复算（`orthographicSize=5`，双方相距 6 格）：

| Game 视图 | s | 背景世界尺寸 | 视口 | 格宽 | 地面上沿 | 可玩圆半径 | 双方落点 x |
|---|---|---|---|---|---|---|---|
| 16:9 | 0.8333 | 20.833 × 10.000 | 17.778 × 10 | 0.8333 | **-4.167** | 4.583 | -2.500 / +2.500 |
| 25:12（设计比例） | 0.8333 | 20.833 × 10.000 | 20.833 × 10 | 0.8333 | -4.167 | 4.583 | -2.500 / +2.500 |
| 4:3 | 0.8333 | 20.833 × 10.000 | 13.333 × 10 | 0.8333 | -4.167 | 4.583 | -2.500 / +2.500 |
| 21:9 | 0.9333 | 23.333 × 11.200 | 23.333 × 10 | 0.9333 | -4.667 | 5.133 | -2.800 / +2.800 |

> 16:9 下背景比视口宽 3.06 单位，左右各裁 1.53；这是 cover 的正常行为（背景是横向延展的场景图）。
> 超宽屏反过来按宽度铺满，地面带会有一部分在屏幕下方，角色仍站在地面上沿。

**为什么必须缩放根节点，而不是只缩放两个子物体**
MapKit 的机制脚本都把特效放在 `transform`（也就是地图根节点）的局部坐标里：藤蔓 `localPosition = (格+0.5, 1)`、竹叶雷从 `y=12` 落下、蒸汽井盖贴在 `y=0..1`。只要根节点 = 设计坐标系，这些数值**不用改一行代码**就自动落到地面上沿 / 背景顶边。只缩放 BG 和 Ground 的话，特效会停在半空（`y=1` 世界坐标）并排到 25 列之外。

### 修订：角色可玩区从「圆」改为「矩形」

上表与本节最初记录的是**圆形**可玩区（`PlayableCenterY` / `PlayableRadius`）。本次修复后，落位层已改用**轴对齐矩形**；上面那些圆的数值仍保留在 `MapStage` 里作为历史口径与旧逻辑兜底，但 `MatchSpawner.ConfigureBody()` 不再使用它们。

| 项 | 旧（圆形） | 新（矩形） |
|---|---|---|
| 几何 | 圆心 `(0, 0.417)`、半径 `4.583` | `PlayableRectMin = WorldRect.xMin/yMin`、`PlayableRectMax = WorldRect.xMax/yMax` |
| 求解器 | `MotionSolver.Move` → `ClampToCircle` | `MotionSolver.MoveRect` → `ClampToRect`（边界按 `bodyRadius` 内缩） |
| `CombatBody` 配置 | `ConfigureArena(center, clamp, radius, units)` | `ConfigureArenaRect(min, max, units)` |
| Y 下界 | 地面上沿（圆最低点） | 背景底边（地面带下沿） |

**为什么要改**：圆的最低点正好压在 `GroundSurfaceY`，而角色落位时脚底就放在那里 —— 角色一出生就贴在圆弧最低点。由此产生两个直接后果：

- **S（向下）无位移**：任何 `delta.y < 0` 都会在下一次 `ClampToCircle` 里被拉回圆上，视觉上完全不动。
- **W（向上）像跳跃**：角色 `x` 偏离中轴约 3 格，圆在该处的下边界本就高于地面，角色被夹到「离地的圆弧」上；加上无刚体、Y 是连续位移，观感与 `Space` 的抛物线跳跃相近。
- A/D 沿圆弧左右移动，是唯一「正常」的方向 —— 这正是「角色只能在地面左右走」的来源。

> **后续变更（同日）**：策划确认角色**只能在地面左右移动**，因此 `CombatBody` 增加了地面锁定
> （`lockToGround` + `groundLineY`，求解走 `MotionSolver.MoveGround`），竖向不再参与角色移动；
> `PlayableRectMin/Max` 现在只提供**左右**边界。A/D 左右移动，W 与 Space 跳跃，S 无功能。
> 详细实现与验证见 `Docs/22_横版地面锁定与跳跃键位.md`。

## 四、切镜规则（三场 1v1 怎么看）

- 屏幕上永远只展示**玩家所在区域**的那一张地图（`BattleMapPresenter` 六选一互斥，原有逻辑不变）。
- 玩家这一场的双方摆在当前地图中轴左右各 3 格，脚底落在地面上沿（+0.02 余量）。
- 另外两场仍在逻辑层并行（`ArenaPlan` 不改），但**角色停到地图右边界 +30 / +60 单位**，圆形边界半径压到 0.5；相机又被限制在场地内，所以永远看不到。
- 位置钟声把玩家换到另一张图时：`MapChanged → Show → 新图 Enter → 算场地 → MapShown → MatchSpawner 重摆`，落点自动跟着新图走。

如果你更想要「三场同屏」，需要三台相机 + 三块视口（或把三张图横向拼成一张），属于另一套表现方案，本轮未做——见第七节。

## 五、你在 Unity 里要做的

**不需要点任何菜单。** 现在 `MapScene.Enter()` 会自己算场地，直接 Play 即可。

1. 打开 `SampleScene`，Play，点「开始游戏」。
2. 期望结果：
   - 背景铺满 Game 视图、不变形；
   - 底部只有一条地面（不再是整屏），角色脚底正好站在它上沿；
   - 玩家和对手在地图中间对峙，另外四人不在画面里；
   - Console 出现 `[地图] 展示 Z? …场地 20.83×10.00 …格 25×12，格宽 0.833，地面顶面 Y=-4.17` 与 `[落位] 切镜：… 格距 0.833 已同步`。
3. 想确认格子对不对：用鼠标点画面里的任意位置，`GameInput` 的 `Aim Cell` 应落在 0..24 / 0..11；点地面那一行应为 `Row = 0`。

**可调参数（都在 Inspector，不用改代码）**

| 位置 | 字段 | 作用 |
|---|---|---|
| 各图根节点 `MapScene` | `Auto Fit On Enter` | 关掉则完全使用场景里保存的静态数值（不再随视口重算） |
| 各图根节点 `MapScene` | `Design Columns / Rows`、`Ground Rows` | 设计网格口径；`Ground Rows` 调大等于把地面加厚、顶面抬高 |
| `MapState` 上的 `MatchSpawner` | `Stage Into Current Map` | 关掉回到旧的「2 行 3 列分擂台」落位（需要宽相机） |
| `MatchSpawner` | `Duel Separation Cells` | 双方相距几格，默认 6 |
| `MatchSpawner` | `Sync Cell Scale` | 关掉则不改 `unitsPerCell` / 输入格，角色手感按各自 Inspector 值 |
| `Main Camera` 上的 `CameraFollow` | `Clamp To Stage` | 关掉则相机自由跟随（地图会被跟出屏幕，仅调试用） |

> 注意：根节点现在带缩放（16:9 下 `0.833`）和位移。这是刻意的——它代表「设计坐标系 → 世界」的变换。运行时每次 `Enter()` 会重算并覆盖，所以不要靠手工拖根节点来微调位置；要调构图请改相机或 `Ground Rows`。

## 七、边界与遗留

1. **角色仍无刚体**：工程里 `Rigidbody2D` / 重力 / 碰撞响应依旧是 0，`CombatBody` 直接写 `transform.position`。地面碰撞体是地图实体，不会「托住」角色；角色站得对是因为**落位时把脚底放在地面上沿**，并由矩形边界保证不会陷到画面外。真物理站立（加 `Rigidbody2D` + 改用 `MovePosition`）见 `Docs/09` 第六节，属于独立的大改动，本轮未做。
2. **机制数值未接入**（`地图.docx` 5.3 / 5.4）：`CharacterInstance` 已经有 `TakeDamage` / `ApplyStun` / `ApplySlow`，但六个 MapKit 机制目前只有视觉演示，没有在「生效」时调用这些接口。建议的接入点：`ZoneMechanicBase` 增加 `batch → 选格 → 提前 1s 预警 → 生效 → 清理` 的公共骨架（D5），生效回调里按格查当前格上的角色再施加状态；「约 20%」「不连成 4 格」已在 `ForestMechanic` 里实现，可提为公共选点器。
3. **区域归属与竞技场加成**（5.5）：`ArenaPlan.MapOf()` 已有权威归属，但「离开竞技场清除 +15% 攻击」还没实现，需要一层 `MapAffinity` 在落位 / 换图时施加与清除状态。
4. **三场同屏未做**：当前是单图切镜。若要做同屏，需要三台相机 + 三个 `Camera.rect` 视口，或把三张图横向拼成一张 75×12 的背景。
5. **BGM / 音效按地图切换未做**：工程内 `Assets` 下**没有任何音频文件**（`.mp3/.wav/.ogg` 为 0），需要先补资源。
6. **超宽屏（>25:12）**：按宽度 cover，地面带会有一部分落到屏幕下方；角色仍站在地面上沿。若要求任何比例都完整看到地面，需改成 letterbox（会留黑边），本轮未改。
