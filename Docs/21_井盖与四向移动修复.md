# 21 · 蒸汽井盖恢复一排 + 角色四向移动修复

> **⚠ 玩法口径已于同日变更**：策划随后明确「角色只能在地面左右移动，W 触发跳跃，S 无功能」。
> 本文**第二节（W/S 四向）的结论已被 `Docs/22_横版地面锁定与跳跃键位.md` 取代**；
> 第一节（井盖）与第三节（改键存档校验）仍然有效。
> 矩形求解器 `MoveRect` 保留为 `lockToGround = false` 时的路径，未删除。

> 本次处理两条反馈：①「蒸汽房井盖有一排会移动的井盖为什么只剩一个了，应该固定大小，多个排成一排」；
> ②「角色只能在地面左右走、跳跃、冲刺等，W 也是跳跃，S 无功能」。
>
> **结论先行**：两个问题都与键位配置无关。井盖是 `GetComponentsInChildren` 把地面节点自身算进去导致只识别出 1 个格；
> W/S 是 `CombatBody` 的**圆形场地约束**把贴地角色卡在圆弧底部。前者改 `SteamMechanic` 的格子来源，后者把场地约束改成矩形。

## 一、问题一：蒸汽井盖只剩一个

### 定位

`Assets/MapKit/Scripts/Mechanics/SteamMechanic.cs` 旧实现：

```csharp
var g = transform.Find("Ground_地面25格");
if (g != null) cells = g.GetComponentsInChildren<SpriteRenderer>(true);
```

`GetComponentsInChildren<T>(true)` **包含调用节点自身**。场景 `SampleScene.unity` 里 `Z2_蒸汽井盖` 下的
`Ground_地面25格` 只有 1 个 `SpriteRenderer`（`steam_manhole.png` 被当作整条地面贴图），且没有 25 个子格。
因此：

- `cells.Length == 1`；
- `PickVents()` 里 `n = 1`，`want = max(1, round(1 × 0.2)) = 1`，每批只能选 0 号口；
- `Wisp()` / `Puff()` 的局部坐标恒为 `x = cell + 0.5 = 0.5`，喷烟永远只在最左边一处。

这就是「只剩一个会动的井盖」。四个 sprite 引用（`manholeSprite` / `warnSprite` / `puffSprite` / `wispSprite`）
在场景里其实都已正确赋值，不是资源缺失。

### 修复

改写 `SteamMechanic`，格子解析按三级优先：

1. **手工优先**：Inspector 指定的 `Manhole Container`，或场景里已存在的 `Manholes_25格` 容器；
   里面若有 ≥2 个 `SpriteRenderer`，直接采用，代码不创建任何物体。
2. **运行时兜底**（`Build Manholes If Missing`，默认开）：生成 `manholeCount`（25）个固定大小井盖格，
   位置按 25×12 设计坐标 `localPosition = (column + 0.5, manholeLocalY)`，`localScale` 按 sprite 原始宽度
   **等比归一化到 1 格宽** —— 25 个格子大小完全一致、不变形、排成一排。
3. **开关关闭时**退回旧行为（可能仍只有 1 个），保留是为了不破坏已经手工搭好的场景。

另外两处配套修改：

- 生成成功后把 `Ground_地面25格` 自身那张长条 `SpriteRenderer` 设为 `enabled = false`，避免与 25 个格子重叠；
  **不动 `BoxCollider2D`**，其它五张地图不受影响。
- `cells` 只取容器里的格子（排除容器自身），并按相对容器的局部 X 排序，保证 `cells[c]` 严格对应第 `c` 列，
  这样 `Wisp` / `Puff` 的 `cell + 0.5` 才能和井盖对齐。喷发结束后用 `resolvedNormalSprite` 还原井盖图，
  Inspector 没拖 `manholeSprite` 时自动借地面贴图。

`PickVents()` / `Wisp()` / `Puff()` / `NewFx()` / `StatusText()` 的算法保持不变。

### 新增 Inspector 字段（都有默认值，不拖也能跑）

| 字段 | 默认 | 作用 |
|---|---|---|
| `Manhole Count` | 25 | 一排井盖数量 |
| `Manhole Width Cells` | 1 | 单格宽度（设计格），固定值 |
| `Manhole Local Y` | 0.5 | 井盖中心局部 Y（地面带中心） |
| `Manhole Sorting Order` | -9 | 绘制层级：地面 -10、角色约 -4，井盖夹在中间 |
| `Manhole Container` | 空 | 手工搭好的容器；留空自动找名为 `Manholes_25格` 的子节点 |
| `Build Manholes If Missing` | 开 | 关掉则完全不生成，只用已有格子 |

> **重要**：运行时兜底生成的井盖是 Play 模式下的临时物体，**不会写回场景 YAML**。
> 若要把 25 个井盖永久固化在场景里，请在 Editor 中手工搭 `Manholes_25格` 容器并关掉该开关（符合「UI/场景物体优先手工搭」的约定）。

## 二、问题二：W/S 与只能左右走（本节结论已作废，见 `Docs/22`）

### 键位链路逐层核对：本来就是对的

| 层 | 实际值 | 结论 |
|---|---|---|
| `InputKey` 枚举 | `W=23`、`S=19`、`A=1`、`D=4`、`Space=37` | 正确 |
| `Assets/Data/Inputs/InputSettings.asset` | `MoveUp=23`、`MoveDown=19`、`MoveLeft=1`、`MoveRight=4`、`Jump=37` | 正确 |
| `InputActions.DefaultPrimary` | `W / S / A / D / Space` | 正确 |
| `InputKeyCatalog.ToKeyCode` | 按成员名 `Enum.TryParse` 到 `UnityEngine.KeyCode` | 正确 |
| `GameInput.MoveAxis` | 四个动作组装二维轴，斜向归一化 | 四向可用 |
| `GameInput.JumpPressed` | 只读 `InputActionId.Jump`（Space） | 与 W 无关 |
| `PlayerMotor` → `CombatBody.SetMoveInput` | 传入二维 `moveInput` | 四向可用 |

因此**没有改任何默认键位**。唯一残留风险是运行时改键存档（`PlayerPrefs`）被误改，见第四节。

### 真正根因：圆形场地约束

`MatchSpawner.ConfigureBody()` 旧代码把 `MapStage.PlayableCenterY` / `PlayableRadius` 喂给
`MotionSolver.Move` → `ClampToCircle`。该圆的**最低点正好等于 `GroundSurfaceY`**，而角色落位时脚底就放在地面上沿
（`+0.02` 余量）—— 角色一出生就贴在圆弧最低点：

- **S（Y 减小）**：每一步位移都在 `ClampToCircle` 里被拉回圆上，视觉上完全不动 → 「S 无功能」。
- **W（Y 增大）**：角色 `x` 偏离中轴约 3 格，圆在该处的下边界本就高于地面，角色被夹到「离地的圆弧」上；
  加上没有 `Rigidbody2D`、Y 是连续位移，观感与 Space 的抛物线跳跃相近 → 「W 也是跳跃」。
- **A / D**：沿圆弧左右移动，是唯一看起来正常的方向 → 「只能在地面左右走」。

25×12 的横版地图是**矩形**，用圆形约束本身就是几何口径错误。

### 修复：改成轴对齐矩形约束

| 文件 | 改动 |
|---|---|
| `Assets/Scripts/Combat/CombatMotion.cs` | 新增 `MotionSolver.MoveRect(...)` / `ClampToRect(...)`：轴分离滑墙 + 矩形四边独立裁剪，边界按 `bodyRadius` 内缩；**原 `Move`（圆形）一行未动**，保证既有回归不破 |
| `Assets/Scripts/Maps/MapStage.cs` | 新增 `PlayableRectMin` / `PlayableRectMax` = 背景世界矩形的左下 / 右上角；Y 下界取**背景底边**而非地面上沿，这样 S 有可见位移 |
| `Assets/Scripts/Flow/CombatBody.cs` | 新增 `useRectArena` / `arenaRectMin` / `arenaRectMax` 与 `ConfigureArenaRect(min, max, units)`；`Update()` 与 `MoveInstant()` 统一走 `SolveMotion()` 分流；暴露 `UsesRectArena` |
| `Assets/Scripts/Flow/PlayerMotor.cs` | `Awake()` 起始态也用矩形配置，避免第一帧暂态回圆形 |
| `Assets/Scripts/Flow/MatchSpawner.cs` | `ConfigureBody` / `ConfigureBodyAt` / `SetBodyArena` 全部改调 `ConfigureArenaRect`；`SetArenaCenter` 改传 `stage.Center` |

矩形四条边独立裁剪后，W/S/A/D 都在场地内有位移；W 是持续上移，与 Space 的起跳—落地明显不同。
跳跃仍由 `JumpPressed`（Space）触发，`RequestJump()` 逻辑未动。

> 构图上地面只占最底 1 行（约 0.83 世界单位），所以 S 向下约 0.5~0.6 格、W 向上可走到背景顶边 —— 四向**并非等距**，
> 这是「地面在画面最底部」的自然结果。要给 S 更大纵深，调大 `MapScene.Ground Rows` 抬高地面顶面（会同时改变地面碰撞体高度），
> 或减小 `CombatBody.Body Radius`。若要真正物理站立（加 `Rigidbody2D` + `MovePosition`），见 `Docs/09` 第六节，属独立大改动，本次未做。

## 三、附带修复：改键存档的防御校验

`GameInput.LoadBindings()` 现在会在反序列化成功后用 `ValidationReport` 检查 Error 级问题
（同一键绑给多个动作、关键动作没绑键等）。若有，丢弃存档、删除 `PlayerPrefs` 键、回退到设计默认键位并打一条警告。

理由：损坏的存档可能造成「W 被绑到跳跃、S 无绑定」这类串位，现象与物理 bug 极难区分。正常存档、无存档时行为完全不变。

## 六、Unity 里需要检查 / 验收的位置

切回 Unity 让它重新编译导入后，Play 一次：

1. **进入 Z2 蒸汽房**：Console 应打印 `[机制验证] 蒸汽 井盖数=25`（旧值是 1）。
   Hierarchy 里 `Z2_蒸汽井盖` 下应出现 `Manholes_25格`，含 `井盖_00` … `井盖_24`，大小一致、横向排成一排。
2. **等一个批次**（4~5 秒）：`[机制验证] 蒸汽批次#N 预警井口=...` 应是多个逗号分隔的索引，分散在 0..24，
   且能看到多个井盖同时换预警图、冒烟。`StatusText()` 会显示「蒸汽批次 N，最近：预警X口 / 喷发X口」。
3. **移动**：A/D 左右、W 持续向上、S 向下（约半格）、Space 单独起跳落回。W 不再表现为「腾空一下」的跳跃。
4. **若曾改过键**：Console 出现「本地按键映射存在冲突或缺失，已回退到默认键位」说明存档曾被判为损坏并已自动清档。
5. **若要把井盖固化进场景**：在 Editor 里手工搭 `Manholes_25格` 容器（25 个子格），
   拖进 `SteamMechanic.Manhole Container`，并把 `Build Manholes If Missing` 关掉。

**离线校验覆盖不到的部分**：MonoBehaviour 生命周期、`SpriteRenderer` 的实际渲染层级与尺寸、
`Camera.aspect` 在 Game 视图的真实值、Inspector 序列化连线。这些必须按上面在 Unity 里实测一次。
