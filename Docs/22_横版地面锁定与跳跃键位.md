# 22 · 角色改为「只能在地面左右移动」+ W 触发跳跃

> 需求原话：「现在场景中的角色可以到处走。但是游戏需要把角色改为只能在地面左右移动。让 W 也映射到跳跃，S 无功能。」
>
> 本文记录这次**玩法口径变更**的实现。它推翻了 `Docs/21` 第二节「恢复 W/S/A/D 四向移动」的结论：
> 四向自由移动不是目标，横版地面左右移动才是目标。

---

## 一、口径定义

| 输入 | 改动前 | 改动后 |
|---|---|---|
| A / D | 左右移动 | 左右移动（不变） |
| W | 向上移动（曾被当成跳跃） | **跳跃**，与 `Space` 等效 |
| S | 向下移动 | **无功能**（按键仍绑定，但不产生任何动作） |
| Space | 跳跃 | 跳跃（不变） |
| 竖向位置 | 可在背景矩形上下自由移动 | **锁定在地面线**，跳跃只抬升 `JumpOffset` 视觉子物体 |

角色根节点的 Y 恒等于「地面线」，因此角色永远踩在地面上，不会飘到半空。
跳跃仍然是 2 格高度的抛物线，只是作用在视觉子物体 `JumpOffset` 上，不再是根节点的 Y 位移。

## 三、关键实现

### 1. 地面锁定的求解入口

`CombatBody.Update()` 现在在地面锁定时**每帧都解算一次**（即使没有移动输入）：

```csharp
if (lockToGround || delta.SqrMagnitude > 0f)
{
    position = SolveMotion(position, delta);
    transform.position = new Vector3(position.X, position.Y, transform.position.z);
}
```

这样 `Teleport` / 拉回 / 落位把角色放到别的高度后，会被立刻压回地面线，
不会出现「站着的位置比地面高一截、要按一下方向键才掉回去」。

`SolveMotion()` 的分流顺序：**地面锁定 → 矩形四向 → 圆形**。三者共用同一套墙体阻挡。

### 2. 地面线从哪里来

`MatchSpawner.ConfigureBody()` 用当前地图的几何快照写入：

```csharp
character.Body.ConfigureArenaRect(stage.PlayableRectMin, stage.PlayableRectMax, stage.CellSize,
    stage.GroundSurfaceY + groundClearance);
```

- 左右边界 = 背景世界矩形的左右边（按 `bodyRadius` 内缩）；
- 地面线 = `GroundSurfaceY`（背景图里那层地面的上沿）+ `GroundClearance`（默认 0.02，避免视觉陷进地面）；
- `CombatBody.Awake()` 会先把**出生高度**当地面线，避免生成第一帧被拉到 `y = 0`；
  真正的落位由 `MatchSpawner` 在地图展示后覆盖。

### 3. 为什么 W 没有直接写进「跳跃」的键位槽

`InputBindingTable.CollectIssues()` 把「同一个键绑给两个动作」判为 **Error**，
`GameInput.LoadBindings()` 遇到 Error 会丢弃存档并回退默认键位。W 同时是 `MoveUp` 的主键，
若再把 W 塞进 `Jump` 的备用槽，运行时会被判定为冲突并整表回退。

因此键位表保持 `MoveUp = W`（不动），由输入适配层 `PlayerMotor` 把 **W 的按下沿**解释为跳跃：

```csharp
bool jumpPressed = input.JumpPressed
                   || (moveUpAlsoJumps && input.WasPressed(InputActionId.MoveUp));
```

副作用：按住 W 不会连跳（读的是 `GetKeyDown` 边沿），跳在空中时 `RequestJump()` 会被 `airborne` 挡掉。
`S` 仍然绑在 `MoveDown` 上（不解除绑定，避免触发「某动作没有绑定任何按键」的 Error），
但由于移动轴只取水平分量、且 `CombatBody` 锁地面，**S 不产生任何游戏内动作**。

### 4. 对其它系统的连带影响（有意为之）

| 系统 | 影响 |
|---|---|
| 闪避 / 冲刺方向 | 取 `PlayerMotor` 的 `move`，其 Y 已被清零 → 只能左右闪 |
| 击退 / 击飞 / 强制拉回 | 竖向分量在 `MoveGround` 里被丢弃，只有横向位移；击飞的**高度**仍走 `JumpOffset` 视觉抛物线 |
| AI 角色 | 同样挂 `CombatBody`，默认也锁地面，与玩家一致 |
| 技能位移（`MoveInstant` / `PullTo`） | 走同一个 `SolveMotion` → 竖向被压平，不会把角色拉离地面 |

如需恢复四向自由移动（例如做空中战斗或俯视关卡），把 `CombatBody.lockToGround` 关掉即可，
`MoveRect` 的原有行为与回归断言都还在。

## 四、Inspector 新增字段（都有默认值，不拖也能跑）

`CombatBody`：

| 字段 | 默认 | 作用 |
|---|---|---|
| `Lock To Ground` | 开 | 角色只能沿地面左右移动 |
| `Ground Line Y` | 0（运行时取出生高度） | 角色脚底所在的地面线世界 Y |

`PlayerMotor`：

| 字段 | 默认 | 作用 |
|---|---|---|
| `Move Up Also Jumps` | 开 | W 与 Space 等效跳跃；关掉则只认 Jump 键 |

## 六、Unity 里需要验收的位置

1. **左右移动**：A / D 沿地面左右走，角色不会再离开地面线上下移动。
2. **跳跃**：`Space` 与 `W` 都能起跳，高度一致；按住 W 不会连续起跳；跳在空中再按会被忽略。
3. **S 无功能**：按住 S 角色不动、不播移动动画、不改变位置。
4. **换图**：切到另一张地图（`Z1`…`Z6`）后角色仍严格站在该图地面线上（`MatchSpawner` 会随 `MapShown` 重摆）。
5. **技能位移**：任何带位移的技能（突进、拉回）都只有横向效果，不会把角色抬离地面。

**离线校验覆盖不到的部分**：MonoBehaviour 生命周期、`JumpOffset` 子物体是否真的存在并随跳跃抬升、
Inspector 序列化值（`lockToGround` / `moveUpAlsoJumps` 是否被场景里旧组件实例覆盖为 false）。
若在 Unity 里发现行为没变，先检查场景中角色上 `CombatBody` 组件的这两个勾选项。
